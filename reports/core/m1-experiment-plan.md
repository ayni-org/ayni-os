## 实施约束与验证

1. **模块归属。** Host 负责故障后的持久镜像与异步借用；Provider/执行端负责实际效果和停止证据；runtime 是装配与实验驱动的唯一组合根。Core 只修改由实验证实存在缺陷的机制，不增加业务场景分支。沿用公开查询，确需白盒切断探针时保持测试边界并说明原因。
2. **断电生命周期。** 先结束旧 Host/Provider 对 Kernel 缓冲区的访问，再丢弃旧易失内存；独立效果记录跨重启保留。旧 completion 不得向释放的内存投递。正常关闭与模拟断电分别验证。
3. **证据。** 每个用例关联原步骤与契约，保留实际配置、版本、切断点、提交/调用身份、事件序列、独立效果计数和第一个失败断言。失败退出、未实现和超出有界步数均不能计为通过；产物不包含密钥、私有正文或媒体。
4. **复用。** 先复用既有 Host 故障、记录 codec、注册与查询机制；不另造通用配置语言、持久重试系统或另一套授权。正常 profile 继续保留，其历史范围不被扩大。
5. **验证资源。** 构建前检查内存、swap、CPU 与活动任务，明确设置构建/测试并行度及所用容器限额；本地跑相关检查，普通代码 PR 的完整既有套件由 ASan/UBSan CI 承担。阶段完成后报告实际运行结果，不预填测试数量。
6. **审查与合并。** 先创建 draft PR，再另开只读独立审查；修复发现并复查影响后 ready。PR 分别记录删除注释、Kernel 新字段、重复公式、裸数字四项自查/独立审查结果；最终 head 的所有适用 CI 通过后自动合并。
