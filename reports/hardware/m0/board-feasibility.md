## 固件基线（编译结果，非实机）

`targets/esp32_assistant` 的 Hello 固件在本地与 CI 均编译通过（ESP-IDF v6.0.3，工具链 `esp-15.2.0_20251204`，`sdkconfig.defaults` 指定 8 MB Octal PSRAM，Flash 暂按所有模组都有的 2 MB 配置，见下文自检第 3 步）。本地 `idf.py size` 的结果（2026-10-19）：

| 内存区 | 已用（字节） | 总量（字节） | 说明 |
|---|---|---|---|
| Flash 代码 `.text` | 69,454 | — | |
| Flash 数据 `.rodata` 等 | 39,196 | — | |
| DIRAM（内部 RAM） | 51,513 | 341,760 | 其中 `.text` 35,631、`.data` 13,346、`.bss` 2,536 |
| IRAM 段 | 16,384 | 16,384 | 固定大小的向量与 IRAM 代码段；其余放入内部 RAM 的代码计入上面 DIRAM 的 `.text` |
| 应用镜像 | 174,047 | 应用分区 1,048,576 | 分区剩余 83%；使用默认单应用分区表，分区布局在测量真实固件后确定（计划 §4.2） |

这些数字只说明空 Kernel 与 Hello 流程的静态占用，不代表 M1 以后的 Kernel、Wi-Fi、摄像头与音频同时运行时的内存是否足够；PSRAM 是否被识别、运行时堆余量要看实机日志。计划 §1.3 的“摄像头 DMA/PSRAM 并发”在 M3 测量。

当时的 Hello 固件启动后打印：芯片型号与版本、ESP-IDF 版本、复位原因、实测 Flash 与 PSRAM 容量、内部 RAM / DMA / PSRAM 堆基线、任务栈水位，然后在内部 RAM 中创建并销毁一个空 Kernel。它不驱动任何电机或 GPIO。

当前入口已随[#123](https://github.com/RobotSe7en/ayni/pull/123)改为平台、ABI和默认arena需求查询，不再尝试把后续版本的默认Kernel放入内部RAM。以上M0静态测量保留为历史结果；当前完整消费者使用PSRAM区域，见[独立程序说明](../../../tests/portability/README.md)，尚无实机运行结果。

## 板型核对（照片，2026-10-20）

用户提供了开发板正反面照片。以下结果只来自照片与同类板型的公开资料，**没有上电**；带“待实测”的项要按下文自检确认。

| 项 | 照片所见 | 结论与影响 |
|---|---|---|
| 板型 | 背面丝印 `ESP32-S3 2025-V1.4`；双 Type-C、RST/BOOT 键、WS2812 RGB 灯、SOT-223 稳压器 | 与 VCC-GND 的 YD-ESP32-S3（原理图 V1.4）布局一致，引脚与 ESP32-S3-DevKitC-1 兼容；原理图按该板参考，实物差异待实测 |
| 模组 | 丝印 `ESP32-S3-N16R8 WiFi+BT MODEL`、FCC/CE/SRRC；不是乐鑫 `ESP32-S3-WROOM-1` 的丝印 | 第三方模组。型号不带 `V`，GPIO47/48 应为 3.3 V，停止链引脚不变；Flash 16 MB、PSRAM 8 MB 只是标称，**待实测** |
| 天线 | 模组有板载天线，旁边另有 IPEX 座 | 用哪一路由模组上的选择电阻决定，自检时看 Wi-Fi 信号强度确认，**待实测** |
| 引出 | 左排 3V3、3V3、RST、4、5、6、7、15、16、17、18、8、3、46、9、10、11、12、13、14、5Vin、GND；右排 GND、TX、RX、1、2、42、41、40、39、38、37、36、35、0、45、48、47、21、20、19、GND、GND | 引脚表用到的 GPIO 全部引出；35、36、37 也引出，但被八线 PSRAM 占用，照旧不用 |
| 摄像头 | 板上**没有**摄像头插座 | 与原假设不同：须另配 DVP 摄像头模组与转接板，用连线接到引脚表的摄像头引脚（全在左排）；连线要短，XCLK 可能要降频，M3 采购前定（bom-candidates.md） |
| RGB 灯 | WS2812 经标有 `RGB` 的焊盘接 GPIO48；同类板出厂时该焊盘断开 | 焊盘保持断开，GPIO48 留给停止链读回，不用焊接；状态灯改用外接 LED（gpio-candidates.md）。焊盘状态**待实测** |
| USB | `COM` 口经 CH343P 转 UART0（GPIO43/44，带自动复位）；`USB` 口是芯片原生 USB（GPIO19/20） | 与引脚表保留的两组引脚一致 |
| 电源跳线 | `IN-OUT`、`USB-OTG` 两个焊盘；同类板出厂时都断开 | 都保持断开。`IN-OUT` 断开时 USB 的 5 V 不送到 5Vin 脚，外接 5 V 与 USB 之间有二极管隔开，所以按电源方案 A 把降压模块接 5Vin、同时插 USB 看日志是安全的；只插 USB 时 5Vin 脚没有 5 V，功放须由外接电源供电。`USB-OTG` 闭合会连通两个 Type-C 的 VBUS |

来源：[YD-ESP32-S3 原理图 V1.4](https://mischianti.org/wp-content/uploads/2023/08/YD-ESP32-S3-SCH-V1.4.pdf)；[vcc-gnd/YD-ESP32-S3](https://github.com/vcc-gnd/YD-ESP32-S3)（CH343P、RGB 灯在 GPIO48）；[deepcoder/YD-ESP32-23](https://github.com/deepcoder/YD-ESP32-23)（三个焊盘出厂断开及 `IN-OUT`、`USB-OTG` 的作用）；以上 2026-10-20 访问。

## 到板后的自检

按顺序执行，每一步的结果写回本报告与 gpio-candidates.md：

1. **拍照与丝印**（2026-10-20 已完成，见“板型核对”）：板子正反面照片；记录模组丝印（如 `ESP32-S3-WROOM-1` 与 `N16R8`）、板子型号与版本、是否附带摄像头。若模组是 1.8 V 版本（型号带 `V`，如 R16V），GPIO47/48 只有 1.8 V，停止链须改用其他引脚（stop-chain.md）。
2. **找原理图**（2026-10-20 按同类板型 YD-ESP32-S3 V1.4 参考：没有摄像头插座，RGB LED 经焊盘接 GPIO48，GPIO38、47、48 都引出）：用万用表确认 `RGB`、`IN-OUT`、`USB-OTG` 三个焊盘断开。
3. **烧录 Hello 固件**：`idf.py -p <SERIAL_PORT> flash monitor`（`docs/development.md`），保存完整串口日志，核对日志中的实测 Flash（`flash detected`）为 16 MB、PSRAM 为 8 MB 且已初始化。确认后把 `sdkconfig.defaults` 的 Flash 容量改为实测值，重新执行 `idf.py size` 并更新上面的表格。
4. **只读查看 eFuse**：用 ESP-IDF 自带的 espefuse 工具执行只读的 summary 命令（命令名以 v6.0.3 文档为准），确认 `EFUSE_STRAP_JTAG_SEL` 未烧写、VDD_SPI 相关 eFuse 与模组电压一致。**不得执行任何 burn 类命令。**
5. **测量供电**：USB 供电时 3V3 引脚电压；Hello 运行期间的 USB 电流（如有 USB 电流表）。
6. **更新分配**：按 1～2 的结果修改 gpio-candidates.md 的“分配”一节；“约束”一节不随板型变化。

完成 1～6 后，`MA-001` 中与开发板有关的两项即可关闭；BOM 询价完成并合计后，预算一项才能关闭。
