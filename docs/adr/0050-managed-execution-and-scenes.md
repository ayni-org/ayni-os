# ADR-0050：受管理执行、Scene 与停止闭环

> **现行目标补充（2026-10-30）**：安全关键分支目标已由 [ADR-0088](0088-safety-branch-coverage-target.md) 统一为 ≥80%，原90%目标弃用。以下保留本 ADR 当时的决定、测量及验证事实。

- **状态**：已接受；Scene 启用持久保存由用户 2026-10-25 确认
- **日期**：2026-10-25
- **关联**：MA-018B、MA-008A 的最小 Observation；ADR-0045、0049；C-AUTH-011、016；C-PERMIT、C-STOP；C-RES-008

## 背景

#68 只交付独立执行端门，Core 尚不签发许可，Scene、观察前提和停止回执仍缺消费者。本部分将这些机制与 Mock 执行器组成一条公开调用链，作为一个完整功能 PR 交付；内部记录、属主实现、API 与测试使用聚焦提交，不再分别交付前置 PR。

## 决策

1. Core 的 `resources/permit` 管本 boot 的许可租期及执行资源隔离；`work/execution` 定义保存于 CallState 的原执行约束、会话与停止事实；`authority/scene` 保存有限场景声明和启用状态；`knowledge/observation` 保存当前 boot 内的最新可信观察与版本。Kernel 编排既有准入、持久屏障和 B4 提交，不承担这些领域状态。
2. **Scene 持久语义（产品语义，用户选定推荐项）：** 保存所有者启用状态；重启后新调用重新检查授权、配置版本和有效观察。旧动作和控制会话不自动续跑。声明变化不能借用原启用记录扩大权限；Scene 只是 Grant/Scope 之外的约束，不能授予权限。
3. 首版执行仅使用 Mock、本地可信端口和完整有界数值包络。参数从调用保存的同一规范参数中提取，不建立另一份未经授权的执行参数来源。Provider 的受理、执行结束、停止确认和目标验证分别表达。
4. 签发只能发生在原 LogicalCall 的 DISPATCHING 屏障持久且最终复核通过之后。续租复查 Grant 撤销栅栏、Scene、工作生命周期、依赖、资源和已持久依据；受限或关闭状态不续租。执行端仍独立实施 ADR-0049 的 nonce、代际及样本新鲜度规则。
5. 观察前提使用正式的有界类型、来源/代际/sequence、采集时刻、有效期、质量及测量/推断分类。本部分只提供 Mock 执行所需的最小观察消费；连续订阅、媒体引用及通用上下文继续由 MA-008B 完成。观察不跨重启恢复为有效事实。
6. 资源释放必须与精确执行身份相匹配；终态/取消回执不能替代停止测量。停止未确认时保持隔离，旧回执不能释放新占用。调用结果和 Task 进度继续共同提交，必要执行引用阻止提前回收。
7. Scene 管理使用现有所有者管理会话、命令身份和 revision。启用需要持久依据才可消费；已接受关闭立即阻止新的消费及续租，不等后台持久清理。回执仍区分内存接受和持久完成，不伪造跨重启保证。
8. 许可 ID 使用 B3 已持久的原执行 attempt.request_id；operation_id 保留原动作身份。资源优先级和 Agent 轮转可改变接受顺序，因此 operation_id 不用作 gate 单调序列。每个 Executor 的所有 Binding 共享规范顺序中的首个独占 ACTUATOR；执行身份与资源准入仍走同一调用链。
9. Provider 终态在等待停止时保留在可靠完成槽，按槽屏蔽待应用终态，其他调用仍前进。停止事实持久后释放隔离；不可追加状态的显式关闭仅在已测停止、借用排空后释放易失占用，不产生持久成功。端口失败保留可查询诊断，不当作停止确认。
10. 独立停止按易失许可槽推进，不依赖正在重载的工作表；原请求超时同样禁止续租。例行轮询与业务处理轮转，单项 step 预算仍可应用结果；急需禁止输出的停止优先。对账与原完成共用 CallTable 结果验证：先校验原始形态和正文，再因过期依赖拒绝成功、保留副作用事实。
11. 替换 Executor 时只替换公开 typed 本地端口及 runtime 装配；Core 保存精确原声明/代际、动作和资源所有权。连续控制样本留在执行端，不逐条过 Kernel 或写 journal。当前只模拟本地传感和输出，未来硬件/远端适配必须另有认证、生命周期及实测证据。

## 后果

本部分完成后才能报告 MA-018B 的 Native Mock 正常闭环。硬件控制周期、停止上限、网络认证、丢失续租/传播失败/重启竞态仍未验证；不得以 Mock 的成功作为实机许可。

## 备选方案

- 在 Provider 内自行决定是否授权或调用私有 Core 表：会分裂权限与资源事实，拒绝。
- 为许可新建公开执行旁路：会绕过既有 LogicalCall/ActionRecord 屏障，拒绝。
- 将停止受理当停止确认：没有本地测量证据，拒绝。
- 按每个内部表拆 PR：不足以让使用者验证受管理动作闭环，本部分不再采用。

## 验证

公开 C ABI 的 Native Mock 正常签发、续租、Scene 启停、到期、观察约束、撤销、停止未确认隔离及确认释放、正常关闭均已通过相关测试；单项 step 公平推进和容量边界通过，独立审查问题已修复并复核。实际命令、内存测量、CI 及限制集中于 [#69](https://github.com/RobotSe7en/ayni/pull/69)。新增故障/恢复专项仍暂停，不将静态审查作为该专项通过。

完整能力的覆盖率量测达到 Core 行覆盖目标，但所列执行安全范围的分支覆盖未达到通用 90% 目标。范围包括授权、资源、执行/观察目录、调用与执行工作事实、Kernel、知识、gate 和 Mock 的完整相关目录及头文件；不删防御分支或缩小分母。当前交付仍限正常功能，覆盖率差距与暂停的失效/恢复证据明确保留，不能作为安全或 Core Alpha 验收。计数、聚合方法、复现步骤及本地证据限制见 #69；不为追数启动新的专项。
