# ADR-0069：Native 容量测量与编码开销口径

- **状态**：已接受
- **日期**：2026-10-27
- **关联**：P6；F18；ADR-0014、0026、0027、0058；计划 §4.2；`contracts/domain/limits.md`

## 背景

F18 记录持久化编码随已用表行数增长，要求在 P6 先量开销，再决定是否增加脏行索引。公开最大容量配置还同时放大 arena、快照空间预留和单批编码界限；只查询 arena 或只量空 Kernel 不能代表填充后的工作。Native 没有另行约定最大容量的硬实时验收预算，ESP32 时限仍须 M2 实测。

## 决策

1. **测量工具属于测试边界。** `tests/measurements` 可读取内部 `KernelTestProbe`，但状态变化全部通过公开 C API 和合法策略输出。单独调用实际 `encode_transition` 测编码，读出的模型保持不变，不修补 stamp 或记录。Core、ABI 与持久格式不变；部署组合根和产品默认配置不变。
2. **配置与填充分开。** 共用 C99 兼容的最大测量配置；所有容量、字节和结构限制取公开最大值，存储缓冲/日志大小自动，写间隔为显式 1 μs。公开 API 填满 Goal、Task、Grant、Memory；每个 Task 填满步骤和检查点。调用、资源占用、目录及来源依赖等未填满，输出明确 Calls=0，不把本负载声称为所有表/所有分支的最坏情况。模拟 Host 逻辑存储额度取 1 GiB，以覆盖最大快照预留；不预分配同等内存。
3. **两个合法 transition。** 最后一条记忆创建和停止实例的批量变化在管理调用返回后立即重复编码；在任何后续 step 改变 stamp 之前完成，检查编码大小稳定、批次可读且身份一致。计时包含 BatchWriter 初始化与 finish；不包含分配样本/编码缓冲和后续排序。另记完整管理提交耗时，不把它混入 step。
4. **真实时间与正常关闭。** Core Host 单调时钟和外部计时均使用 `steady_clock`，存储完成在 step 之外投递。分别记录填充/排空、满表本地输入工作与静止 step；满表后取消一个 Task，再由已有本地事件 Goal 在同一满表尺寸下派生/决定替换 Task，单独确认实际执行。显式 `max_items=1` / `max_time_us=1000`，检查 item 上限。最大值和 nearest-rank p99 仅为这次样本的观测，不是硬实时上界；耗时样本不作为 CI 性能断言。正常排空/销毁，不能证明关闭时保留完整借用状态并报告失败。
5. **容量证据。** arena 工具报告默认、最小 work、双 Agent 调用/执行和最大配置；性能输出报告实际 arena、journal 批次上界、快照记录/负载上界，并经公开 memory-requirements 二分查出最小可接受显式缓冲，不复制 Core 的选择公式。来源修订、dirty 标记、编译器和配置随产物记录。
6. **当前取舍。** 本轮交付 Native 基线，保留当前编码扫描。没有已约定的 Native 硬预算可据以宣布性能通过或失败；不因观测值自动增加脏行维护机制。具体调度预算、调用表满载和 ESP32 数据明确后，再针对实际瓶颈决定索引、编码或调度优化。E1-N2 的响应性选择仍按 ADR-0068，不改变完整实验与硬件验收。

## 后果

可以重跑明确的数据集，区分稀疏配置、填满选定表、管理提交和 step 成本。主机调度、CPU 限额、优化级别会影响真实耗时，不能把一次最大值当作证明。最大 arena 和保守快照预留并非适用于 ESP32 的部署建议。

## 备选方案

- 先增加脏行表：新增索引一致性和持久状态维护，尚无目标预算或测量证明其收益，本轮不做。
- 在生产 Core 加计时字段/探针：引入额外状态与成本；使用现有测试探针和只读编码入口。
- 所有容量设置最大即称所有表满载：混淆配置与实际占用，拒绝。

## 验证

Native Release 最大配置工作负载、最小缓冲公开查询和正常关闭已执行；CI 只验证小规模数据与输出，不设耗时阈值。独立审查、准确命令、最终 CI 与数据在对应 PR 记录。未新增故障/恢复专项；硬件、所有表满载与真实停止时限未验证。
