# ADR-0028：权限与审批（一）：可信所有者绑定与会话入口

- **状态**：已接受；`MA-006` 六部分的设计基线，A 已实现并验证，PR #25 待合并
- **日期**：2026-10-22
- **关联**：计划 §2.2、§2.4、§2.5、§3.2、§4.3、§5.3、§9.1、§14.1；`MA-006` A；ADR-0003、ADR-0008、ADR-0017、ADR-0025～0027；C-AUTH-010；E2、E4

## 背景

`MA-010` 已有逐 transition 日志、命令窗口、双槽快照和隔离重载。主体注册与会话入口仍与应用意图入口同在公开头文件，Session 虽然保存渠道和绑定版本，Core 尚未持久保存所认证所有者的绑定。旧 Goal/Task 又没有可恢复的授权上限；不能把缺少授权元数据解释为不需要权限。

`MA-006` 涉及可信入口、范围代数、Grant、撤销、审批和工作模型，不能作为一个大型 PR 提交。现有资源许可和 Provider 尚未实现，因此本包也不能以真实派发或停止的验收作为自身前置条件。

## 决策

### 1. 六个顺序 PR 与验收边界

每个部分单独审查、验证、提交和合并，不提前开放未闭合的变更入口。以下 ADR 与 ABI 编号是实施顺序预留；只有 A 属于本 ADR 的实现范围，B～F 仍待实现。

| 部分 | ADR / ABI | 内容与独立验收边界 |
|---|---|---|
| A：可信绑定与会话入口 | 0028 / 0.16 | Host 受管入口、持久 OwnerBinding、绑定失配受限；恢复工作缺授权元数据时停下 |
| B：Capability 与范围代数 | 0029 / 0.17 | 有界能力注册、字段类型/单位/取值域、规范化、覆盖和收窄判定；注册不代表调用已实现 |
| C：Grant 与受限委派 | 0030 / 0.18 | 创建、查询、期限、父链、安全回收、规范请求去重；对象与命令映射同批，接入日志/快照/恢复 |
| D：即时撤销与回执 | 0031 / 0.19 | 拒绝栅栏、待决撤销、分阶段回执、背压优先级与自动重载保护 |
| E：待审批 Goal 与原子批准 | 0032 / 0.20 | GoalType 需求导出、权限上限、`PROPOSED`、批准/拒绝、激活计时与同批持久化 |
| F：工作模型与兼容闭环 | 0033 / 0.21 | Task/子目标检查、决策复核、显式恢复、撤销清理和旧数据确认；本包机制验收 |

`MA-006` 验证授权机制及模拟消费者；屏障后复核、停止续租随 `MA-018`，真实调用的在途取消与外发随 `MA-008`，完整故障矩阵随 `MA-022`。物理停止仍需独立执行端与硬件证据。F 合并后才可标记本包机制完成；后续联调证据另行跟踪。

### 2. 已确认的产品语义

下表记录用户已批准的实施计划（2026-10-22），不将后续部分写成已实现。

| 事项 | 已确认语义 |
|---|---|
| 合法目标缺少授权 | 保存为 `PROPOSED`，不生成可执行 Task；未知能力、非法需求或不支持的路径仍明确拒绝 |
| 目标审批范围 | 仅覆盖该 Goal 的完整参数、触发源与既定重复规则；跨目标复用另建 Grant；不覆盖子目标 |
| 待审批计时 | 延迟/周期从批准激活时开始，等待期间不积累 occurrence；已有明确失效期限仍按原规则处理 |
| 撤销后的工作 | 保留进度与检查点并暂停；新 Grant 不自动恢复，须显式恢复并重新选择授权 |
| 授权期限 | 明确的长期授权，或只在当前 `boot_epoch` 内有效的限时授权；不能证明有效即拒绝 |
| 参数约束 | 有限声明式规则，由 Core 判定覆盖与收窄，不运行表达式或策略脚本 |
| 旧 Goal/Task | 保留并以独立授权原因停下，管理端确认前不补权限、不自动恢复 |
| 撤销写失败 | 保留即时拒绝覆盖，继续已有 writer 隔离与自动重载；未持久回执不承诺跨断电保存 |
| 撤销回执 | 使用统一意图回执的 `PENDING`、`APPLIED`、`DURABLE`，与物理停止确认分开 |
| 所有权变更 | 本包仅实现绑定隔离；完整转移、解绑及旧主体命令窗口清理随 `MA-028` |
| 次数/费用额度 | 随 `MA-018` 接入；本包明确拒绝尚不支持的额度请求 |
| Scene | 本包不开放依赖 Scene 的授权，返回 `UNSUPPORTED` |
| Grant 历史 | 表满时回收最早且可安全回收的终态记录；没有安全候选则拒绝新增 |

### 3. A：Host 可信入口与持久绑定

- `ayni_register_principal` 与 `ayni_open_session` 的声明从应用头文件移至 `include/ayni/host_authority.h`；保留函数名和既有 Kernel 所有者线程/禁止回调重入规则。Host 认证后才可调用；应用意图仍只带 Session 引用。Core 不处理密码、TLS 或凭据，公开 C 头文件也不能隔离恶意进程内原生代码。
- Session 描述符增加 `binding_revision` 与保留字段。建立会话时必须核对 Host 本次配置的 principal/revision 与已持久绑定；不接受调用者仅自报渠道便提升权限。重启和自动重载关闭全部 Session。
- `PrincipalRegistry` 持有 Host 的本次预期绑定以及从存储恢复的唯一 `OwnerBinding`，两者不能互相覆盖。持久绑定含 `principal_id`、`binding_revision` 和原始 transition stamp；会话和凭据不持久化。
- 新增 REQUIRED `OWNER_BINDING` 记录，type 12、version 1，16 B 小端 body：`u64 principal_id`、`u32 binding_revision`、`u32 reserved=0`。身份与版本必须非零；重复绑定记录、非法长度或保留位属于损坏。快照附原始 stamp，并沿现有分页布局、容量公式和一致性校验恢复。
- 完整恢复先核对存储绑定与本次 Host 配置。主体、revision 不同或缺少所需 Host 所有者时进入 `RESTRICTED`，只读诊断；不得写入新 boot/binding 或把旧工作当空存储重新创建。原日志与命令窗口保留供诊断，不实现所有权转移。
- 旧存储无 `OWNER_BINDING` 时，先核对全部保留的 `USER` Goal origin 的 principal/revision，以及全部保留 `CommandMapping` 的 principal。任一现存证据与本次 Host 绑定冲突，即以 `OWNER_BINDING_MISMATCH` 在新恢复写入前受限；不能以最后一条来源猜当前 owner，也不能忽略历史冲突而收养旧工作。命令映射没有 revision，不从中推断版本。现存证据全部一致或完全没有所有者证据时，才由可信 Host 提供首次绑定；已有 `OWNER_BINDING` 则以绑定为权威，不以历史来源重写它。这是现存证据一致性迁移，不实现完整转移。绑定与进入 `RUNNING` 时实例创建/恢复整理的首个领域 transition 同批，不塞入 `BOOT_EPOCH` 控制批次；即使无 Agent，只要需要绑定也生成该 transition。绑定的提交尚未达到 `durable_seq` 前不开放敏感会话。已存绑定不重复写入领域批次，快照则保留其原 stamp。

### 4. A：旧恢复工作的拒绝覆盖

恢复后，尚未终结且没有授权元数据的 Goal/Task 使用独立的 `LEGACY_UNCONFIRMED` 授权暂停原因停止推进。保留原生命周期、进度、检查点和其他失败/不兼容原因；`GOAL_RESUME` 不能解除授权原因，目录重新注册也不能解除。

这是本次恢复的拒绝覆盖，不改写旧持久对象或在快照中伪造批准事实。旧日志首次建立 OwnerBinding 不代表既有工作已获授权；A 中新建工作仍只具有现阶段已实现的行为，不据此声称已有 Grant 或完整授权准入。完整的需求重建、批准和显式恢复随 E/F：只有原 GoalType 版本仍能解析保存参数并导出完整需求，才可供管理端确认，否则继续停下。

### 5. B～F：状态归属与接口设计基线

- `catalog` 拥有 Capability 版本化描述、固定扁平字段 ID/类型/单位/取值域及 GoalType 权限需求声明；`authority` 拥有绑定/信任级别、Grant/父链、范围包含判定与即时拒绝覆盖。
- `work` 拥有 Goal/Task 权限上限、授权引用、进度和独立暂停原因；`kernel` 只编排跨模块同批提交、审批、命令回执和待持久撤销；`durability` 不解释授权语义。不向内核对象散加授权布尔量、重复 epoch 或另一套事务系统。
- 范围首版支持有符号整数等值/闭区间、枚举/标识符等值/有限集合、执行目标及外发目的地的精确标识符集合；字段取合取，集合排序去重。未知字段、空集合、类型/单位不符拒绝；省略约束只表示已注册取值域的全范围，实际请求缺必要字段仍拒绝。
- 一项需求须由一条完整 Grant 覆盖，不拼接多条扩权；优先该 Goal 专属 Grant，再选实例通用 Grant，同级按 Grant ID 决定。Grant 内容不原地扩权，续期/扩权新建 ID；撤销不可反向恢复原 Grant。委派检查完整父链，禁止循环、超深、范围扩大、期限延长或再委派权限扩大。
- GoalType 以有界纯回调从已验证参数导出需求，Kernel 校验并保存上限和所选引用；Task 继承上限，派生、恢复、继续决策分别复核。子目标另检自身授权及父目标上限。管理端批准绑定 Goal ID、owner、GoalType 版本、完整参数、触发源、重复规则和有效期，默认不可委派。
- `GRANT_CREATE`（可选父引用表示委派）、`GRANT_REVOKE` 和 `GOAL_APPROVE` 沿用统一意图入口；拒绝提案复用 `GOAL_CANCEL`。Grant/回执查询说明持久状态。授权管理要求非零 `command_id`，保存完整有界规范请求作确切幂等比较，FNV 仅作索引，不以哈希相同代替内容相同。
- 未授权但合法的目标保存为 `PROPOSED`，无隐含审批超时且占 Goal 容量；审批以 `expected_revision` 校验。Goal 专属 Grant、授权引用、激活和命令映射同批提交，新权限在持久确认前不开放执行。普通创建/审批背压返回 `BUSY`，不另建通用排队系统。

有界容量均来自调用方提供的内存；初始设计如下，后续部分须同步批次/快照/内存布局公式并实测，不据默认值宣称符合 ESP32 RAM 预算：

| 配置 | 默认值 | 范围 |
|---|---:|---:|
| Capability 数 | 16 | 1–256 |
| Grant 数 | 32 | 1–1024 |
| 每 Goal 权限需求数 | 4 | 1–16 |
| 每项范围规范编码上限 | 256 B | 64–4096 B |
| 委派深度 | 4 | 1–16 |

每能力最多 8 个授权字段，每集合最多 8 个成员；超出配置的字节容量返回明确容量错误。

### 6. D～F：撤销、重载、回执与安全回收

认证和命令身份校验通过后，撤销先建立 authority 的易失拒绝栅栏，再等日志空间；快照分页期间不修改正在导出的持久模型。Kernel 命令模块每个 Grant 至多保留一条待决撤销，同命令返回同回执、异内容冲突、同目标另一待决命令返回 `BUSY`。所有命令入口检查待决身份，普通窗口 floor 不能遗忘已接受撤销。

| 阶段 | 语义 |
|---|---|
| `PENDING` | 仅用于撤销：已建立拒绝栅栏并保留请求，尚无有效 `commit_seq` |
| `APPLIED` | transition 已应用并排入日志，回执含本次 boot 的提交序号 |
| `DURABLE` | 对应 transition 已确认持久 |

空间可用后优先将撤销版本、命令映射及清理游标同批提交。写入失败保留栅栏；重载关闭 Session，恢复持久事实但保留本 Kernel 已接受的拒绝覆盖/待决命令。原命令已持久则完成回执；否则丢弃旧 queued stamp，在新 boot 重新提交，不能用新 boot 的 `durable_seq` 判定旧序号。已接受撤销不依赖旧 Session 继续存在。绑定失配仍保留拒绝并报告受限；目标 Grant 因创建未持久而消失时，持久记录明确的无操作完成结果。

`PENDING` 只保证本 Kernel 及其自动重载持续拒绝；整个进程断电前未到 `DURABLE` 不承诺跨重启撤销。任何阶段均非物理停止确认。清理可分步但拒绝立即生效，游标持久保存；显式恢复只解除授权原因，不能解除策略失败或类型不兼容。

仅回收永久失效、无保留子 Grant/活工作/Gate 依赖的叶节点。按终态提交顺序再按 ID 选择；日志写明被替代 ID，重放不得重选。限时 Grant 从接受时计时，到期失效；自动重载的新 `boot_epoch` 也不能使它重新有效。

### 7. 存储兼容与交付

沿用 `storage_schema=1`，以新增 REQUIRED 领域记录演进；变更既有记录时单独递增记录版本并保留旧版读取。旧 reader 遇授权新记录必须受限，不能回退旧快照继续执行。A 必须覆盖 OwnerBinding 在 journal、replay、双槽分页快照和最大容量公式中的路径；后续 Grant/审批/撤销的断电与兼容证据分别在对应 PR 补齐。

ABI 升为 0.16，0.15 调用方须重新编译。受影响的 C99 契约、C++ 封装、Native/ESP-IDF 组合根和测试须同步包含 Host 受管头文件，不能为兼容保留应用侧的身份自报入口。默认/最小配置内存数字待实际量测后记录，未测前不填写预计值。

## 后果

- 新 Host 仍只需提供认证事实与绑定配置，不把密码/TLS 实现耦合到 Core；Core 负责持久事实及绑定一致性。更换存储 Provider 不改变授权语义，须继续满足共享存储契约。
- 从旧版恢复的活工作会停下，即使原 GoalType、策略仍在；这是避免无授权自动推进的兼容变更。A 尚无批准接口，恢复须等 E/F 完成，不以自动补 Grant 绕过。
- 本包不做 Scene 授权、费用/次数额度、所有权转移或命令窗口删除；分别明确拒绝或交由 `MA-018`/`MA-028`。真实 Provider、执行许可、屏障和停止证据不能由机制单元测试替代。
- B～F 尚未落地，不把本 ADR 的已接受状态解释为功能、跨平台或完整 E1–E4 已完成。

## 备选方案

- 继续把会话建立入口交给应用并信任渠道自报：不能保证受管入口的信任级别，拒绝；Host 头文件是受管 API 边界，不能据此声称原生代码隔离。
- Host 每次配置覆盖存储 owner/revision：会把旧授权事实交给新所有者并允许旧命令重新执行，拒绝；保留原事实并受限，转移另做。
- 旧工作缺授权记录即视为无需求，或自动生成无限 Grant：无法证明原授权范围，拒绝；保留、禁行并显式确认。
- A 先把旧工作取消或重写为普通用户暂停：丢失事实或使普通恢复绕过授权，拒绝；采用独立拒绝覆盖。
- 把所有权限状态放进 `ayni_kernel`，或新增独立授权日志：破坏不变量归属和跨对象原子性，沿用现有模块及提交协调器。
- 在 `MA-006` 提前实现真实 Provider/资源许可以满足旧完成定义：依赖倒置且扩大 PR，改为明确机制验收与后续联调归属。
