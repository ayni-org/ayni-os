# ADR-0117：独立 Ming3 TTS 网关与语音端点配置

- **状态**：已接入，正常OTA与启动自确认通过；板端实际播放待验证。
- **日期**：2026-11-27。
- **关联**：ADR-0097、ADR-0098、ADR-0108；计划 §14.1；[实验说明](../../experiments/esp32_wifi_chat/WIFI.md)。

## 背景

用户要求 TTS 接入已部署的 `http://192.168.31.221:8080` Ming3 网关。现有实验将 ASR、TTS 和语音健康检查共用 `speech_url`，TTS 固定请求 Qwen3；直接替换该地址会将转写发送到不提供 ASR 的服务。

## 决策

1. `speech_url` 继续表示原 ASR 根地址，追加独立 `tts_url`，默认使用用户提供的 Ming3 网关。触屏网络页与 Web 可编辑两个地址，仍在保存、正常关闭及重启后生效。模型密钥继续仅发送到模型 HTTPS 接口。
2. TTS 使用 `ming3-tts`、`灵小柔`、`Chinese`、`pcm` 和 24000 Hz，请求仍为 `/v1/audio/speech/stream`。保留 AYTS/1、原 64 KiB 有界播放缓冲、期限、取消、成功终帧及真实播放完成要求。使用服务默认分块，不追加可选 grow 参数；不新增 WAV 回退、重播或另一条扬声器调用链。
3. 语音健康检查顺序检查 ASR `/readyz` 和 TTS `/health`，两者均成功才报告就绪。共用原作业期限与取消代次，释放首份响应后再读取第二份。
4. 实验设置记录升级到 v3，在原 v2 字段之后追加 TTS 地址；已知、校验通过的 v2 只读载入，原 ASR、网络、密钥和模型选项保留，新字段取默认地址。读取不改写 NVS，用户保存时才发布完整 v3 快照。v1 和其他未知版本仍拒绝并保留。此决定只补充 ADR-0108 的实验设置规则，不增加 Core 存储迁移器。
5. 本轮只修改独立实验与对应文档，Core、公开 ABI0.62/schema12 和外部服务代码保持原值。最初仅软件验证；2026-11-27用户随后明确要求正常OTA，沿用软件停止、排空和真实关闭屏障，保留卷与配置。播放听感和长语音验收仍另行安排。

## 后果

替换 TTS 服务不再改变 ASR 目的地。每份设置快照增加一个 192 字节地址字段；旧固件不能读取保存后的 v3 设置，回退需另行配置，不能通过自动擦除掩盖格式不匹配。

## 备选方案

只替换共用地址会破坏 ASR。固定第二地址而不加入配置则每次搬迁服务都需重编译固件；独立可配置地址沿用现有设置机制即可，无需新 Provider 或 Core 改动。

## 验证

本机到新网关的固定短句请求成功，响应为 AYTS/1、24000 Hz、单声道、16-bit PCM，成功终帧计数匹配。相关正常软件检查、固件编译及随后授权的正常OTA与启动自确认通过，原设置保留，板端ASR/TTS健康检查成功，见实验说明。未主动播放设备音频，实际朗读、ASR往返与长语音仍待对应验证。本轮尚无 PR/CI 证据。
