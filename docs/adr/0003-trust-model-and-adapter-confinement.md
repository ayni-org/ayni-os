# ADR-0003：信任模型与适配器约束

- **状态**：已接受（设计基线，待实现与验证）
- **日期**：2026-10-18
- **关联**：计划 §2.5、§3.7、§10.6、§10.8 B5

## 背景

架构讨论中曾把 Agent 平面称为“不可信提议者”，同时允许 Strategy 在 step 内执行原生回调。若“不可信”指模型输出，这一设计合理；若包括 Agent 代码，纯函数接口无法阻止越权访存、直接 I/O 或无限循环。独立适配器进程只提供地址空间与崩溃隔离，不自动限制设备、文件、凭据、网络与 IPC。ROS 2 的 DDS-Security 提供参与者认证与 Topic 级访问控制，但默认关闭，也不表达 Ayni 的 Grant、预算与恢复语义。

## 决策

按计划 §2.5 与 §3.7：

1. 信任分两条轴：模型、VLA、外部消息、发现到的描述与 MHS 参考文件是不可信数据；v0.x 进程内原生代码都是可信内置代码，保留既有可信编译时注册边界。
2. 纯函数策略接口用于确定性与可替换性，不是安全边界。
3. 适配器以独立系统账户运行，不能访问执行器设备节点与凭据库，只经带自身主体身份的本地 IPC 连接 Kernel；ROS 侧启用 SROS2 严格模式，适配器只能向执行端许可门发布。
4. 执行端拒绝缺少有效许可的指令，这是无法旁路受管入口的最后防线；进程隔离是纵深防御。
5. 第三方原生代码与 MHS 代码文件不进入固件，只有可转换为有界 Procedure 数据的子集可经校验接入。

## 后果

- 安全声明与实际隔离能力一致；适配器被攻破时仍受执行端许可约束。
- Full Profile 部署需要配置系统账户、文件与设备权限，以及 SROS2 的密钥与权限文件；许可门增加一跳转发。

## 备选方案

- **以纯函数接口宣称隔离**：不能阻止原生代码越权，否决。
- **只依赖进程隔离**：不限制设备、网络与凭据时，适配器可直接旁路，否决。
- **首版引入 WASM 等受限运行时**：体积、内存与调试成本尚未评估，留待 M6 按需求立项。

## 验证

§10.6 权限与隐私行：适配器直接写设备节点、绕过许可门发布控制命令、伪造 IPC 主体都必须被拒绝；R1 B5 验证 SROS2 严格模式与许可门。
