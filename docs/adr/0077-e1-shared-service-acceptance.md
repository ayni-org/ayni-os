# ADR-0077：完整 E1 共享服务与失效恢复验收

- **状态**：已接受；实现与交付结果见本阶段 PR
- **日期**：2026-10-28
- **关联**：MA-021、计划 §10.2；ADR-0042、0045、0060、0063、0065/0066、0075/0076

## 背景

P6 的正常 profile 只证明正常隔离、并发和有限重开；其本地响应 30 step 不满足完整 E1 的 10 step 门槛。完整实验还需要资源整组竞争、停止隔离、授权/来源失效、完成槽、提醒呈现与真实中途恢复证据。

## 决策

1. **确定性基线。** 用户 2026-10-28 明确保留本地规则不超过 10 次实际 `ayni_step` 的硬门槛；资源等待则按用户随后决定保留 Core 的 30 秒，替代原计划 500 ms，不增加配置或 ABI。每 Task 模型硬上限 2、模型槽 1、正常延迟 100 ms、超时延迟 1,500 ms/deadline 1,000 ms 均保持。Host 按公开 `more_ready`、wake、存储请求和 Core/Provider 的最早截止调度，不把无工作轮询计成必须的 step，也不跳过实际 Core step。
2. **组合与责任。** `runtime/sim_node` 装配双 Agent、实际 ToolLoop、规则测试策略、现有 Mock 模型/摄像头、公开资源/Grant/Memory/日历及实际 assistant 工作流。新的 `applications/experiment_fixtures` 只决定有限的资源/观察/共享上下文步骤；Core 仍拥有任务、权限、来源、调用与恢复事实。延迟 ModelProbe 和派发屏障检查从正常 profile 抽出共用，保留原正常行为。
3. **非运动与独立停止。** 非运动竞争使用普通互斥 `test.actuator` 测试资源；带 ACTUATOR 标记的 `mock.actuator` 继续强制经过 Core 许可与同一独立 Mock 执行端。停止用例分别观察取消送达、Provider 终态和独立停止测量/持久发布，未知停止期间不准入下一动作。Mock 可在首个操作前选择人工测量确认，不改变已开始执行的停止语义。此模拟不证明真实设备停止时间。
4. **来源与信任。** 私有/公共档案分别验证，语音不能新增 Grant 或执行敏感删除。跨 Agent 只以 CONTEXT 共享进入前台摘要，不开放跨 Agent ORGANIZE。删除/用户修改/撤销共享后，让实际旧模型成功结果到达；旧 Task 不能导出或写回过期内容，既有派生摘要失效，用户新版本与 CAS 保留。删除清理在持久接受后中断并重启继续；撤销共享只撤掉 B 的使用资格，保留 A 的原用户事实。
5. **可靠完成与呈现。** 普通队列满时向真实 Kernel 投递存储确认和 Provider 终态；完成槽耗尽另由 `tests/experiments/completion_slots.cpp` 直接运行现有 CompletionPool 属主，验证 BUSY、端口不调用、一次应用和槽归还。测试关闭时探针明确 UNSUPPORTED。真实提醒策略区分入列、外部呈现、成功持久化与 Task 完成；失败/未知保留待处理，重复不重复应用，丢失后按原 operation 权威查询。暂停组关闭自主观察/运动但保留提醒；安静时段通过现有 QuietHours 与资源窗口延后。
6. **恢复机制修复。** 实验确认：来源失效并清理时重启，旧调用已可能派发，`advance_call` 却先走本地未派发取消，ActionRecord 拒绝后进入 INTERNAL。将恢复检查集中到 `restore_wait`：先把可能派发的旧操作归为 UNKNOWN，再对确定未派发的工作检查来源、暂停和资源队列。沿用原调用身份，不直接重放，不扩大授权；Core 无新增字段，C ABI 0.45/schema 2 不变。
7. **阶段完整性。** 原 E1 步骤 1～11 的活跃变体与新增共享撤销组成 32 个独立 schema 1 用例；ADR-0042 废止的累计额度 ID 保留为历史，运行限制用例另编号。生成器与 CLI 产物测试核对清单、两轮确定性、10 step 门槛及正文不进入轨迹。

## 后果与备选方案

按事件就绪和截止调度避免无效轮询，同时保留持久提交所需 step；不降低响应门槛。资源等待改为现有 30 秒是用户决定，未引入可调 ABI 字段。普通测试资源不能用来声称已验证物理许可/停止，独立执行端也不能用来声称真实硬件验收。测试探针复用机制属主，未另造完成分配或恢复状态机。更换摄像头、模型或 Host 仍只改变边界装配；应用依赖公开契约，Core 无场景分支。

## 验证

Native/Sim 的完整 E1 场景与相关正常/E2/调用/执行/记忆回归通过；具体命令、步数、内存配置、独立审查、最终 CI 和限制集中在本阶段 PR。每项实际通过仍以对应 PR/CI 为交付证据。ESP32、真实设备/媒体、耐久、独立安全覆盖与 Core Alpha 未验证；E3/E4 继续按已授权顺序交付。
