# ADR-0065：通用持久暂停组

- **状态**：已接受；正常实现、验证与独立审查见 [#87](https://github.com/RobotSe7en/ayni/pull/87)
- **日期**：2026-10-27
- **关联**：P5 / MA-019；ADR-0042 决定 5、0063、0064；C-LIFE-031

## 背景

暂停助理需要同时限制多个 Agent 的自主目标，并让暂停期间新建的自主目标受同一限制。批量改写 Goal 的用户暂停会丢失原有独立暂停原因；按名称或模型输出猜测归属也不能形成稳定契约。暂停机制先作为完整通用 API 交付，统一助理再在 Core 外选择成员。

## 决策

1. **产品选择（用户选定推荐项，2026-10-27）。** Goal 最多属于一个直接组，并受祖先所属组的限制；可信应用在创建时固定归属。提醒与显式用户工作不加入助理自主组。恢复不补做暂停期间自主检查/观察的周期和事件积压；已有 Task、检查点及单次意图保留。
2. **归属。** `work/goal` 拥有固定八组的独立 gate；0 表示无组，1～8 是应用选择的通用编号。尚未控制的组默认开放、revision 0、无对象 ID。首次所有者控制分配稳定 Kernel ID，之后每个精确命令推进一次 CAS。组不开启权限，也不改变 Goal 的用户生命周期。
3. **传播。** 复用现有 Goal 祖先与 Task 结算规则；关闭组在同一 transition 暂停受影响 Task，阻止新派生，并沿原调用链立即关闭采集 gate、停止许可续租及收敛在途请求。管理返回前对在途普通 delivery 及执行许可锁存停止，连续暂停/恢复不能复活旧调用或旧许可；实际端口操作仍由有界 step 推进。接受暂停不代表物理停止确认。解除组只解除本组原因，不清除 Goal/实例用户暂停、授权、未知结果或策略 hold。
4. **恢复前沿。** 重新开放时跳过未派生的 interval/local-input 积压；每日/每周日历同步推进自身 occurrence 游标，时间不可信时明确拒绝该恢复。单次/延时目标保留原意图。输入使用现有逻辑 ingress incarnation/through 前沿，排除恢复前已入队的事件；它是 epoch/序号，不是时间戳。
5. **持久。** 组事实使用 REQUIRED type28/v1，日志在所有 Goal/Task/日历变化后、精确命令前；快照使用同一 codec。恢复证明状态与确切命令配对，正常重开先读完组事实再结算 Task。Goal type3/v13（日志）与 v14（快照）追加不可变组和 provenance 标记；旧无组布局保持可读。
6. **命令。** `PAUSE_GROUP_SET` 走受绑定所有者 MANAGEMENT 限制和完整字节幂等窗口，type9/v14 保存其 canonical 请求。输入只包含 group、desired pause 和原 revision，不接受应用自报权限。审批/重新授权的完整 Goal echo 包含组，旧无组 echo 与普通创建 digest 保持原字节。
7. **兼容。** ABI 0.44，所有 0.x 消费者重新编译；schema 2 不变。旧 reader 对含组工作遇 REQUIRED 新版本拒绝，不做旧目录迁移。八组固定内存与新增记录预算纳入 arena 量测，结果集中在 PR；Native 数字不作为 ESP32 证据。

## 后果

暂停组可跨 Agent 使用，单个 Goal/Agent 的既有暂停含义保持。周期游标清理和 Task 结算按已有硬容量有界；日历日志预算扩大到最多 Goal 容量，以容纳一次组恢复的完整变化。暂停组是受管理入口机制，不能约束可信原生代码绕过 Core 的直接 I/O。

## 备选方案

- 批量暂停当前 Goal：漏掉暂停后新建工作，也无法可靠保留独立用户暂停。
- 用共同父 Goal 表示组：现有 Goal 树要求同一 owner，无法覆盖两个 Agent。
- 一个 Goal 多组归属：本轮无需求，增加表达、编解码和配置成本；用户选单组。

## 验证

正常公开 ABI 用例覆盖混合显式/自主工作、暂停后新建、祖先与用户暂停独立、周期积压跳过、旧输入前沿、精确重试、正常关闭重开及订阅停止/新代际重开。实际命令、内存、独立审查与 CI 结果集中在 [#87](https://github.com/RobotSe7en/ayni/pull/87)。新增故障/恢复和变异专项继续暂停；不据正常结果宣称完整恢复或物理停止时限已验收。
