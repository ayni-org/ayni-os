# ADR-0001：设备治理模型与执行许可

- **状态**：已接受（设计基线，待实现与验证）
- **日期**：2026-10-18
- **关联**：计划 §2.2、§2.6、§2.10、§2.9、§7.3；`MA-017`、`MA-018`、`MA-026`、`MA-038`；E2 F14

## 背景

跨设备与具身控制需要回答三件事：谁可以批准执行器动作，执行期间由谁检查，以及授权撤销、Kernel 重启、校准失效、急停复位或网络分区时，旧授权何时失效。v1.3 已在可选 `EMBODIMENT_V1` 中定义控制代际与命令最大年龄，但 v0.1 的必需轮式动作依赖这些规则，形成必需路径引用可选章节的倒置。另一个缺口是：“许可未过期 + 安全平面健康”无法给出撤销消息传播失败时的停止上限。

此外，“Component 就是 Resource”的等同过强：一台摄像头可能占用多个资源，多个轮子可能共享一个底盘控制域，模型槽也不是物理组件。

## 决策

1. 设备模型区分 Component（设备结构）、Resource（容量、互斥与冲突域，可为非物理资源）、控制域（带 `authority_epoch` 的执行器 Resource）与 Binding（能力到 Component/Provider 及所需 Resource 的关系）。
2. 每个控制域任一时刻只有一个 authority-owner Kernel 作为决策点，负责静态准入、账本与持久记录；执行端作为执行点，逐控制周期校验许可、限值与持续联锁并负责停止，只能收紧授权。无 Kernel 的设备端点同样由唯一 authority-owner 治理。
3. 具身执行分过程（Procedure）与控制会话（ControlSession）两种形态，在过程或会话粒度使用同一派发屏障与 ActionRecord。
4. 执行许可是短租约：绑定 `kernel_boot_epoch`、`authority_epoch`、`executor_boot_epoch`、`safety_epoch` 与校准版本；续租回显执行端 nonce；租期按执行端本地单调时钟计算。撤销不依赖消息送达，停止续租即可在剩余租期内失效。
5. 各失效事件的机制与最坏停止上限按计划 §2.10 的失效矩阵执行，所有上限均须实测。
6. 执行许可与 `MotionOutcome` 基础阶段属于基础契约；`EMBODIMENT_V1` 只增加机器人专用类型。

## 后果

- 撤销传播失败、Kernel 崩溃、存储受限栅栏和网络分区都有可计算的停止上限；单机与跨设备使用同一规则，Kernel 不进入实时环路。
- 会话需要周期续租；租期过短会误停，过长会延迟停止，须按能力风险与实测停止时间设定。执行端需持久化 `authority_epoch`。
- 无法给出停止上限的能力不开放会话形态。

## 备选方案

- **只依赖显式撤销消息**：传播失败时没有停止上限，否决。
- **Kernel 逐条审批指令**：Kernel 进入实时环路，控制频率下不可行，否决。
- **长期许可 + 独立心跳**：心跳正常但授权已撤销时仍存在执行窗口；把续租作为许可本身的一部分即可消除，否决。
- **用跨设备同步时钟判断新鲜度**：缺少可信同步时钟时不可靠，改用执行端 nonce 与本地租期。

## 验证

E2 F14 以模拟执行端覆盖撤销与指令并发、撤销传播失败、续租丢失、延迟续租重放、Kernel 重启、校准失效与急停复位后重放旧许可；`MA-018` 验证失效矩阵；`MA-038` 验证分区下许可到期；`MA-026` 在真实执行端复核并实测停止上限。
