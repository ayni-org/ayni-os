# ADR-0102：复用调用契约与简化正常存储路径

- **状态**：已接受（用户2026-11-14要求实现、提交推送）；软件验证与独立审查结果见实验记录，实机提速待验证。
- **日期**：2026-11-14。
- **关联**：ADR-0084、0091、0096；C-CALL-001、C-AUTH-017、C-HOST-010/013。

## 背景

ESP诊断记录显示，短动作前后的Ayni本地交接耗时明显。代码在同一次准入、派发或执行许可检查中重复解码完整机器契约；正常日志追加遍历所有旧记录头；ESP每个文件请求完成和空闲轮询都遍历LittleFS统计空间。用户要求改为契约验证后复用、正常日志直接追加、空间维护账目，并要求保持实现直接。

## 决策

1. **契约视图留在调用链内。** 在现有owner词法workspace中解码一次，将同一原始域／机器契约的`DecodedBusiness`传给输入规范化、已保存输入读取、授权和执行准入。外部／恢复边界仍走完整解码验证，实际业务输入仍逐次检查。视图不跨owner调用保存；没有常驻契约缓存、额外Kernel状态或arena扩容。撤权、期限、停止、Scene及观察依赖仍实时复核。
2. **只跳过确定的新序号查重。** FileLog在open及UNKNOWN重扫中记录完整有效帧的最大commit_seq，成功追加后推进。新序号严格大于该上界时无需遍历旧帧；旧序号仍按原writer/transition身份及完整字节核对。UNKNOWN先按原规则重扫、重写确认，已知损坏和不完整尾部处理保持。trim后允许保留偏大的上界，只会多查，不会漏查。格式与重放规则不变。
3. **ESP空间采用保守账目。** 独占LittleFS卷首次真实测量后，在每次program/erase之前，按本轮触及的不同物理块扣减完整块大小；修改原已分配块也扣减，删除不提前返还空间。64个有界块号溢出、累计64 KiB扣减或发生低水位变化时重测。测量失败及关闭重开使账目失效，原空闲重试仍可恢复。读操作或无变化的空闲查询直接使用账目。Native／其他Files实现不变。
4. **保留完成和派发屏障。** Host仍先维护空间缓存及在途预留，再投递完成；准备、派发、结果和停止事实的原持久顺序不合并。Core ABI0.54、schema9、业务能力与UI行为不变。账目属于ESP文件适配器；序号上界属于共享FileLog，不是另一份Core领域事实。

## 取舍与兼容

词法复用减少同一次调用的重复工作，不追求跨调用复用；避免引入常驻缓存的内存、失效和借用管理。空间账目可能低估可用空间，并在阈值或低水位重新核对；不得高估或提前返还删除空间。正常追加快路径不承担周期性介质巡检，open/read与已知损坏拒绝规则保持。本轮不引入新的故障、掉电或恢复专项，也不以软件检查替代真实介质保证。
