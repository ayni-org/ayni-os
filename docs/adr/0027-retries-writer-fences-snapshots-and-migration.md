# ADR-0027：持久化与恢复（三）：重试、写入栅栏、快照与迁移

- **状态**：已接受；`MA-010` E+F 已实现，实际结果见本文「验证」
- **日期**：2026-10-21
- **关联**：计划 §2.8、§4.2、§4.3、§4.4、§9.1、§14.1；`MA-010` E+F；ADR-0002、ADR-0016、ADR-0025、ADR-0026；C-COMMIT-008～011、C-STORE-005～007、010～011、C-VER-020～023；E2 F12、E4 步骤 6

## 背景

#20 已实现逐 transition 日志、整批恢复、Native 文件 Host 和命令幂等，但追加失败直接受限，没有快照、轮转或格式迁移。两个 Host 还会重复追加同一批次；因此不能仅在 Kernel 重试，否则 `UNKNOWN` 已落盘时会留下重复日志。按提交序号翻页也不能越过栅栏后混入的旧 epoch 物理批次。

交接还留下容量错误分类：首个完整批次比本次缓冲大时，Host 返回一般读取失败，Kernel 不能区分容量缩小与介质故障。

## 决策

1. **仍是一个 PR。** E+F 沿 ADR-0025 的拆分收尾 `MA-010`。不提前实现动作、Grant、预算、记忆或对外输出；各所属包沿现有故障注入补齐各自验收，不据此声称完整 E2/E4 已通过。
2. **历史保留 A（产品语义，用户选定，2026-10-21）。** 快照保留当前可查询对象、步骤、私有检查点、命令映射和下限；激活持久后允许删除覆盖日志，不额外保留历史档案。终态对象仍按原表满让位规则保留。不会为了轮转丢弃活对象或现存命令窗口。
3. **重试保持身份。** 每次调用使用新的 request 身份，同一批次的 epoch、transition、commit 和字节不变。最多三次尝试，失败后退避 10 ms、50 ms；完成槽不足不计尝试。Host 对同序号、同字节的尾批次再次确认持久，不重复追加；不确定同步须重新校验并完整重写需要重试的字节，不能仅靠第二次同步假定原数据可靠。
4. **异常与维护暂停新工作（产品语义，用户选定推荐项，2026-10-21）。** 正常首发在途不冻结准入；首次失败或未知后暂停新 transition，意图为 `BUSY/STORAGE_BACKLOG`，查询继续。幂等映射检查先于存储背压，已接受命令仍返回首次结果。快照维护同样暂停新意图、触发与策略推进，不停止单调时钟、不重置运行中计时。
5. **栅栏与重载。** 耗尽重试进入用户已定的 `FENCED=7`。成功隔离旧写入方且借用完成槽归还后，才丢弃易失状态、重新读真实持久前缀并持久化独立 `WRITER_FENCE` 和新 `BOOT_EPOCH`。隔离失败或恢复再次失败进入只读 `RESTRICTED`，不无限自举。冷启动先只读校验，之后握手取得实际新 writer epoch；Native 排空单 worker，Sim 另验证持久 epoch。返回 `EPOCH_INSTALLED` 的 Host 持久保留已安装 epoch，即使在日志栅栏前断电，下次仍分配更高 epoch。Native 以 `DRAINED` 排空确认隔离；同一 Host 内递增，冷启动选择高于已记录 epoch，不保留尚未记录的临时代际。
6. **物理读取与容量错误。** 正式 ABI 增加 `storage_read_log`，完成带 `next_cursor`；0 是起点，轮转后旧 cursor 失效。Core 校验旧 epoch 和连续前缀，Host 只负责分帧。新增读专用 `READ_BUFFER_TOO_SMALL`：首批放不下时报告精确所需大小、不写缓冲、不前移；先放入若干批次时先返回它们。只有合法该结果映射 `STATE_EXCEEDS_CAPACITY`；`OK` 却越界及普通 I/O 故障仍为 `STORAGE_READ_FAILED`。
7. **单模型快照。** 排空日志后复用存储缓冲，按完整记录分页，不增加第二份 WorkModel 或全量快照内存。领域属主分别导出、导入静态状态；原始创建身份、提交序号、步骤顺序、命令顺序保留，所以调度与回收次序不改变。目录缺失造成的本次恢复覆盖状态与持久原态分开；快照不永久保存这种临时停下。恢复失败仍丢弃全部重放内容。
8. **双槽激活。** 使用已定双槽和递增 generation。写非当前槽、回读校验、独立持久槽尾标记后，再写 REQUIRED `SNAPSHOT_COMMIT`。槽标记证明内容完整，日志激活记录决定切换；未激活候选忽略。恢复先找最新有效激活再读它的槽，避免把已覆写的旧槽引用当损坏；当前激活不支持或损坏时只读诊断，不选择过时槽。
9. **有界轮转与写频（产品语义，用户选定等待背压及 10 ms 初值，2026-10-21）。** 所有可能写介质的请求共享最小 10 ms 发起间隔，含重试、epoch 安装、启动、快照、标记、激活及回收；读不受此限制。等待反映在 step 期限，不空转。日志自动上限为 `max(1 MiB, 8 × storage_buffer_bytes)`，75% 或将侵入维护预留时暂停准入并维护。快照最大大小由工作容量计算；可用空间不足明确失败，不能先删除当前有效来源。该限频是逻辑请求上限，不是 Flash 页写次数或磨损实测。
10. **Native 回收。** 保留原 `AYNL`/`AYNF` 物理文件格式；以激活批次完整身份定位物理保留点，而不是按序号过滤旧帧。新文件同步、rename、目录同步后确认回收；重复请求幂等。稳定目录锁与原日志 fd 锁共同持有，替换文件在发布前也加锁，防止轮转绕过单写入方。重开后首次变更须完整重写继承的前缀并同步文件及目录绑定；只读打开与诊断不触发重写。轮转目录同步未知时，同一进程的后续变更也须先重新确认。
11. **迁移与回滚。** 读 schema 0/1、正常写 1。旧格式完整流式恢复后，先在隔离的 Host 上写 schema 1 快照；切换前不向旧源追加新控制记录。激活仍使用 schema 0 外壳和旧 reader 不认识的 REQUIRED 记录，构成旧固件的拒绝运行证据，之后重新恢复并写新栅栏、启动记录。激活后才回收旧日志；旧固件不能通过旧路径回到过时状态。旧源可大于新稳态阈值，迁移前须有候选和切换空间。真空存储直接建立 schema 1 日志，不制造空快照。
12. **未注册所有者的命令窗口（产品语义，用户选定推荐项，2026-10-21）。** 不再跳过其命令恢复。命令表仍一行，第二个 principal 无空行时拒绝新非零 command，不能先改变领域状态再发现容量不足。日志需要多行且本次放不下时以容量受限；所有权转移和明确清理随 `MA-006`。
13. **默认缓冲三倍（产品语义，用户选定推荐项，2026-10-21）。** 默认从 `2 × max(W+4,256)` 改为三倍；只有一个批次在途时，至少有一段可容纳下一最大批次。显式小缓冲仍允许并保留 `BUSY`。不移动 Host 仍持有的批次。单此项默认内存增加 3,700 字节，整库数字须实测。
14. **未完成请求不合成超时（产品范围，用户选定推荐项，2026-10-21）。** 接受请求仍须真正完成一次；隔离写权限不等于归还指针。可查询和发起关闭，所有槽归还后才能 STOPPED、销毁或复用缓冲。本包不增加卡死 I/O 的取消协议、专用槽或有限恢复时限。
15. **ABI 0.15。** 追加配置、物理游标完成字段及 Host 端口；新原因与生命周期标明版本，固定原字段布局。0.14 调用方重编译。协议版本、领域版本和 `storage_schema` 分开。内存变化、工具链、实际验证与限制在本 ADR 和 PR 正文记录。

## 后果

- 存储故障可在同一身份下恢复，受限后可能丢弃尚未持久的内存状态；调用者仍须用同一 boot 的 `durable_seq` 判断接受结果。
- 重试和自动维护造成可见 BUSY；快照按状态大小和限频需要多次 step，不承诺固定暂停时长。运行中维护不重置提醒计时；真正重载沿 ADR-0026 从恢复结束重新计时。
- 轮转后不再保留已让位对象的完整日志历史。当前查询对象及命令窗口保持原契约。
- 槽大小与临时轮转文件峰值受界；旧格式来源在迁移期间额外占用空间。空间不足时保留来源并受限，不伪造迁移成功。
- ESP-IDF Host 尚无存储端口；实际 Flash 擦除与执行器会话调度仍随 `MA-026`，真实 OTA 与硬件回滚仍随 M4。
- 新增存储 Host 时，预计只需实现公开的八个存储端口并通过共享 Host 契约套件；WorkModel、领域表、快照与恢复编排继续复用。此为边界设计，目前只验证 Native 与 Sim，不能据此声称 ESP-IDF 已支持。
- 实现以 Kernel 编排恢复与发布、durability 编解码和前缀机制、领域表静态导入校验、Host 介质操作分工；共享写入期限与重试机制只维护一份。设计自查未引入第二份 WorkModel、通用迁移框架或平台依赖。

## 备选方案

- 以新 transition 身份重试、或跳过失败批次：会重复应用或制造提交缺口，否决。
- Host 根据 commit_seq 过滤栅栏后的旧批次：把恢复语义复制到各 Host，且混入高序号旧帧时会跳过合法记录，改用物理 cursor。
- 复制整份 WorkModel 以允许维护时继续写：增加有界存储和一致性机制，用户选择暂停新工作。
- 槽标记单独决定切换：还需要另一套迁移防回退证据，改用已有计划中的 `SNAPSHOT_COMMIT`。
- 丢弃未注册所有者的命令窗口：未来重新注册可能重复执行，用户选择保留。
- 为省 RAM 维持两个默认批次：保留分段背压；用户选择多占约 3.7 KB。

## 验证

### 环境与内存

实际在 x86_64 Linux 容器中使用 GCC 13.3.0、Clang/clang-format 18.1.3、CMake 3.31.6、Ninja 1.11.1、Python 3.12.3 与固定的 GoogleTest 1.17.0。Clang 首次配置因镜像只有 `clang-18` 命令而失败；补齐指向现有编译器的 `clang` / `clang++` 别名后重新配置、构建与测试通过，未跳过检查。GoogleTest 使用已固定版本的离线源码。

C99 小程序实际调用 `ayni_kernel_memory_requirements`：默认配置只覆盖前 12 字节，工作容量最小组按 workflow §7 设置。默认 **62,608 B**（0.14 为 57,944，增加 4,664）；最小工作容量 **28,816 B**（原 27,344，增加 1,472）；均对齐 8 B。默认缓冲改三倍单独增加 3,700 B，其余变化来自新编排状态与领域恢复字段。

初期并行构建造成主机失去响应、宿主临时记录丢失，不能把中断任务计为验证完成。之后停止全部构建，恢复遗留植入缺陷并逐文件核对正常 Core，所有最终验证重跑为单任务、`CMAKE_BUILD_PARALLEL_LEVEL=1`、较低 CPU/I/O 优先级；唯一运行容器限 1 CPU、2 GiB 内存、无额外 swap。植入缺陷峰值 531,365,888 B（约 507 MiB）；五配置验证峰值 835,964,928 B（约 797 MiB）；内存上限/OOM 事件均为 0，宿主 swap 始终为 0。脚本、原文、日志与结果在仓库外持久目录保存。

### 植入缺陷

40 个唯一匹配、可编译的 Core 缺陷逐项植入，每项只构建单元测试目标并运行未过滤的完整单元套件；最终恢复原文后再次构建成功。**40/40 被命名断言发现，无存活、编译失败或超时**。其中 32 项完整执行 571 个测试；另外 8 项先触发已有断言失败，再因测试夹具继续访问未建立的对象而 SIGSEGV，按 workflow 的非零退出规则计入发现，不称为完整执行。所有修改文件逐字节/SHA 校验恢复一致。

### 自查与独立审查

设计自查修复了旧 activation 过早绑定已复用槽、非法 `TOO_SMALL` 误归容量以及完整重放校验晚于写入等问题。另一个代理在仓库外 worktree 对完整 diff、相关调用方和失败路径作只读审查，逐项回看全部修复；审查者不把静态检查写成已运行测试。八项记录全部闭合：旧槽引用、非法容量结果、慢 step 的真实发起时间、UNKNOWN 跨重开确认、无关槽读取失败、覆盖序号溢出、激活必须 REQUIRED 且独立成批、Native 文件与目录绑定共同确认。没有尚未解决的阻断代码发现；上述最终五配置实际验证在修复后执行。

本 PR 未测量定量行/分支覆盖率，不声称达到 Core ≥75% 或安全分支 ≥90% 的目标；完整 E1–E4、其余领域断电验收、真实 Flash/OTA/回滚与耐久结果仍由各所属包补齐。本包的证据限于上述单元/契约、文件 I/O 故障和确定性模拟。CI 与合并状态见对应 PR 和 `reports/core/m1-progress.md`。
