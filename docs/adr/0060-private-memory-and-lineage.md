# ADR-0060：私有记忆、来源依赖与删除屏障

- **状态**：已接受
- **日期**：2026-10-27
- **关联**：P3 / MA-011A；ADR-0042、0056、0057、0058、0059；计划 §2、§9.1、§14.1；C-PROD-040～042

## 背景

P2 的外层对话文件删除没有清除 Kernel 保存的 Goal 参数、检查点、调用正文及命令历史。P3 同时交付有界记忆与这些内容的来源追踪和清理；只删除记忆表或摘要不能阻止旧回答、在途响应再次带回被删内容。

## 决策

1. **用户已选定的产品语义。** 明确管理保存是已确认的独立用户陈述；模型推断及整理结果初始未确认，只能由所有者确认。确认不改变来源，也不删除依赖。公共档案初始为空，只收明确保存的称呼、语言和交互偏好；每个 Agent 单独授权访问。整个 Kernel 默认 64 条、正文最多 512 UTF-8 字节、最多 8 项完整来源依赖；启动可配置，满表拒绝新记录。写入走 Kernel 意图，读取走公开查询及策略受限视图，CLI 复用契约；显式模型工具适配按实际需要再接入。（产品语义，用户选定推荐项，2026-10-27。）
2. **归属与边界。** `knowledge/memory` 拥有事实、正文、标签、版本、来源、确认与依赖图。Kernel 组合 Session、Agent、Grant、Task、调用及提交协调；Host/runtime 承担文件 I/O 和应用对话流程。普通管理查询也要求当前持久所有者的 MANAGEMENT Session，不能以任意 actor 参数冒充 Agent。策略只能使用当前决定所绑定的 Task/Agent 视图。
3. **容量与检索。** 记录容量 0 可禁用，启用范围 1～256；正文范围 1～4096 字节；每个完整来源集合范围 1～8。每条至多 4 个标签和 8 个关键词，各 64 UTF-8 字节，精确字节匹配；正文检索为有限子串匹配。无向量数据库、自动淘汰或无限历史。上下文屏障占一项依赖，但不占用户记忆记录容量。容量不足前检查，拒绝不产生半条记录或部分输出。
4. **实际来源与权限。** Kernel 累计实际读取以及 Goal 参数、检查点、调用结果和历史对话继承的完整来源；相同来源的不同 revision 不能覆盖合并。读取、共享与外发权限分开，捕获实际 Grant ID/revision；后续失效时不能重新挑选另一许可使旧结果继续有效。模型调用还绑定实际目的地。在查询、派发、结果接受、决定发布、Goal 参数/检查点导出和外层文件发布时复核。正文管理导出拒绝策略回调重入，避免绕过受限视图及实际来源捕获；元数据查询保持原规则。超出依赖容量使整个决定失败，策略忽略读取错误不能提交部分结果。
5. **删除与擦除。** 接受 tombstone 立即使原记录及传递派生内容不可用；后续有界步骤擦除各属主保存的正文与搜索内容。工作身份、实际动作结果及未知结果语义保留，隐私不可用状态独立于成功/失败。晚到的成功、失败、取消或查询响应均不能重新填回正文。清理状态及游标持久化；完成需覆盖内存、journal、两个快照槽和外层文件确认。原有两个快照槽交替写入机制需要完成两轮覆盖，不能把一次压缩等同全部擦除。范围是程序管理的逻辑内容，不声明存储介质取证不可恢复或远端 Provider 的物理删除。
6. **对话屏障。** 每个 Agent 对话有独立的有界 context anchor，作为粗粒度隐私版本屏障，不替代逐项记忆依赖。删除单轮持久记录目标轮 ID、旧/新 revision、清理阶段和文件确认；同一 anchor 清理期间拒绝冲突修改。保留未删的显式用户输入，清除依赖旧上下文的回答和摘要；不把旧生成内容重新贴上新 revision，也不为重建历史重新执行工具。外层新文件只能在 Kernel 删除屏障持久后发布；旧异步保存完成须重查版本。重启按持久删除目标继续清理，不能把旧文件再次收养成新来源。
7. **兼容与精确命令。** ABI 升为 0.40；storage schema 保持 2，新增语义以 REQUIRED 类型/版本表达，旧 reader 明确受限并保留目录。新内存事实用 type 23/v1、记忆管理命令用 type 9/v10，共用一份值编解码。受删除影响的 exact canonical 不能用摘要替代精确字节；清理后保留 `privacy_expired` 命令身份，重试返回 EXPIRED，无关命令继续原规则。旧无关联对话不能当作独立内容；旧非对话工作保持原行为。本轮按实施计划既定兼容规则，不制作旧对话迁移工具：缺少完整来源证据的旧 chat 目录在任何写入或调用前明确拒绝并保留原目录；普通旧 Core 工作不受影响。缺少 exact GoalType 版本但同 ID 当前可信版本声明为 Context 时，旧无来源 Goal/Task 的正文导出同样拒绝；完全未知普通类型保留所有者诊断。显式脱敏记录、新对话文件版本及这一回退边界随完整实现一并验收。
8. **模块变化场景。** 替换模型 Provider 不改变记忆事实或删除图规则，只改变外部调用与目的地声明；增加 Host 不改变 Core 的版本屏障，但须实现异步持久化和相同删除完成确认。CLI 只映射管理意图和展示状态，不拥有另一套授权或记忆真相。

9. **跨 Context 收敛与存储校验。** 清理提升一个 Context revision 后回到记忆阶段重新扫描；每次回退清掉一个 anchor 的依赖集合，有限容量下收敛，再清工作与调用。重放按相同候选验证进度，进入 compact 必须有持久的文件 ACK；purge/complete 快照的 generation 必须达到目标。合法历史超过本次依赖/记录容量报告容量受限，不能误报损坏。
10. **原始输入的独立寿命。** 已接受输入与 pending Goal 一并先写外层有界 draft。发布失效时恢复为原编号 user-only 轮次，不能并入新轮次逃避原轮次删除。正常 3 轮之外保留 1 个专用槽，满 4 槽需用户先删一轮；未编号草稿可合并续写但合计不超过 384 UTF-8 字节。生成回答与摘要全部失效；不重放旧工具。内部文件 ACK/自动清理遇正常 BUSY 保留状态后续重试，非暂态错误如实报告。
11. **记录与迁移边界。** 完整格式集中在 `contracts/storage/records.md`：type 23/24/25/26，Goal v7/v8、Task/Checkpoint v2、Command v10～v13、Call v5；外层 AYNF/AYNC/AYNT v2。无来源旧 chat 目录在 Host 锁内、Kernel 启动前拒绝，不自动清空或迁移。清理等待外部文件和借用释放，因此不承诺固定墙钟完成时限；每个 owner step 和表扫描有界。

## 后果

固定上限使 arena 和遍历可量测；全文、标签、来源和 exact 请求会增加内存及存储预算。精确撤销/版本失效会拒绝旧派生内容，不能静默扩大权限。保守对话屏障可能同时清除未删轮次的旧生成回答，显式用户输入仍保留。模型结果的确认与可用性是两个维度。

## 备选方案

- 将记忆放到 CLI 文件：无法统一策略、共享权限及在途调用屏障。
- 只删原记录或摘要：保留了派生回答、检查点及命令里的正文副本。
- 用单个 anchor 代替所有记忆依赖：丢失逐项来源与实际授权，不能证明跨轮失效。
- 清除整个所有者命令窗口：会影响无关命令；按受影响映射过期更精确。

## 验证

正常用例覆盖记忆保存/查询、独立授权与外发、来源失效、跨 Context 清理、逻辑正文擦除和正常重开；独立审查发现的分类、来源固定点、发布输入保留和背压问题已修复。实际命令、最终 CI、内存量测及复查证据集中在 [#81](https://github.com/RobotSe7en/ayni/pull/81)。新增故障/恢复专项暂停，完整 E1–E4、硬件及安全关键分支覆盖率目标不据此标为完成。
