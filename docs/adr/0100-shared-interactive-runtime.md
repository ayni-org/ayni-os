# ADR-0100：共享交互会话、正文缓存与提交辅助

- **状态**：已接受（用户2026-11-12）；共享实现已提交推送，用户随后安排单子智能体独立审查并授权最小修复、提交推送。
- **日期**：2026-11-12。
- **关联**：ADR-0094、0096、0097、0098；C-SDK-009/011/012、C-HVAL-005/006。

## 背景

ESP实验已复用Core、ToolLoop、Host及模型协议，但另有History回合/文件状态机、缓存重建包装、文件队列配额及命令身份/回执实现。共同Session早于实验存在，却只支持保留草稿；受限设备还缺少缓存清退接口。用户要求依次补齐共性、迁移消费者、全部完成后统一提交推送，本轮不做独立审查。用户明确旧历史文件不需要。

## 决策

1. **会话归属。** 扩展`runtime/conversation::Session`，共享输入、Goal创建、终态观察、发布、文件CAS、ACK及清空。默认继续保留未完成草稿；显式`discard`模式在原Goal/Task终态持久后仅丢弃草稿，接受下一输入。新增非阻塞取消、显式放弃保留的终态草稿、一次性终态结果及关闭前quiesce。文件/版本错误保持拒绝，不转换为新空会话。暂停仍附着原Task，处理权限或限额后继续，绝不重交旧动作。
2. **发布与取消。** 未创建Goal的取消不调用模型；已创建的取消经原管理入口，等待真实Core终态及持久序号。已进入上下文发布的回答继续完成文件和精确ACK，取消只由应用抑制显示，不回滚已确认历史。Core仍拥有授权、来源、上下文及调用事实，没有第二份领域账本。
3. **正常关闭/重开。** 交互部署先取消自己选择的旧Goal并等待Task终态，再开放会话和策略；运行中关闭先quiesce等待文件/ACK及正文请求排空，再进入Core shutdown。Core shutdown本身不承诺取消所有持久Goal。选择discard的Session只在相应旧工作已持久结束、Core锚点匹配时清理保存的草稿。未完成的跨存储发布/ACK仍拒绝并保留，不增加通用恢复算法。
4. **正文端口。** Session借用窄`BodyCollection`端口，脱离对具体FileBodies对象的依赖；正文及收集的属主仍是存储实现。替换持久记录后再释放旧引用，包含冷加载时没有scope缓存元数据的引用。
5. **缓存。** FileBodies提供正数字节预算（默认0维持原无限制缓存）、resident payload查询和主动清退。只清退无文件借用的durable缓存，不删除磁盘正文、不更换公开descriptor。单正文超过预算或在途正文无法腾出空间时返回容量错误。完整ready检查包含排队未受理的删除；同一owner继续推进文件请求。预算不等于模型token窗口，也不包含容器元数据或调用方缓冲。
6. **准入与命令。** `hosts/storage::ValueAdmission<N>`拥有固定槽及完成转交，部署选择额度为共享Host队列留余量；不复制文件机制。Native/ESP共同portable Profile也将所有正文及会话值接入4槽准入，Host至少5槽（运行期Core存储单在途，启动期尚无外层请求）。正常程序曾捕获FENCED/STORAGE_REJECTED，暴露了原直接入队的争用，本轮由此补齐共同消费者。不可复制的C++ `CommandClient`拥有一个principal的启动代次/序号及待持久回执；调用方保证其他生产者的身份区间不冲突，不自动重试已接受命令。Native portable与ESP使用同一提交实现；Native CLI复用CommandSequence身份规则，保留原有多命令回执窗口，不强行串行化。
7. **ESP消费者与兼容。** 删除实验History、BodyCache、ValueQueue；正常聊天使用`wifi.chat`和Core上下文锚点。旧`usb.chat`类型仅用于保留记录和取消旧工作，合成容量诊断另用无上下文类型，不发布为真实历史。按用户决定不迁移旧独立历史，初始化新锚点对应文件；不擦Core卷、不删除调用证据、不增加启动自动擦卷。新锚点之后的正常历史仍精确重开。ESP缓存payload预算为2 MiB、外层文件额度8/Host16，具体内存峰值待板端证据。
8. **版本与交付。** C ABI0.54、Core schema9、AYFV1及ConversationRecord5不变。C++源码Config改用BodyCollection，全仓消费者更新并重编译；外部源码消费者把FileBodies指针改为`collection()`。回退原二进制/原目录的既有规则保持；旧实验二进制不会读取新锚点文件，不能把旧历史当新会话的回退副本。本轮只编译和软件正常验证，不烧录、OTA、模型付费调用或运动，不启动故障/掉电/耐久/变异专项。

## 后果

2026-11-12独立审查修正：清退只移除payload，保留scope/digest/长度直至释放，以免collect漏删中间正文。新增ready状态保留已完成但未被read/write取走的结果，观察结果后才允许自动清退；显式trim可放弃未消费但已无文件借用的结果，避免取消后等待清退。不能腾出预算时明确返回CAPACITY_EXCEEDED，主动trim受在途文件借用阻挡时返回BUSY，避免多正文解码每次从头重试时反复互相清退。该修正不改变C ABI、正文文件或记录格式，也不为ToolLoop增加跨调用正文副本。

换Host或增加普通设备能力不再需要重写会话文件/回合状态机。实验仍拥有设备实现、交互呈现、启动时选择取消哪些工作及部署预算。代价是共享运行时增加明确的交互生命周期接口，C++源码消费者需要重编译；Core未改变，不把UI或平台线程放入内核。

## 备选方案

保留第二套History会继续分化上下文保证；直接替换现有Session会改变失败/取消语义；整体套用portable Profile会带入双Agent、夹具模型和模拟执行器。均不采用。这里只扩展已有属主和两项有实际重复的辅助机制，不引入平台工厂、插件系统或另一套调度器。

## 验证

共享会话、正文文件/缓存、既有上下文及Native助理正常检查通过；最小Host队列与隔离Native完整程序/正常重开通过，外层准入修正后Core不再因该正文队列争用进入FENCED。独立实验和只读SDK共同消费者的ESP-IDF编译通过；检查、工具版本和Native资源查询集中在原统一提交说明。共同验证程序同时修正了一处uint32_t诊断格式的32位编译问题。后续独立审查确认两项缓存问题，最小修复及正常回归见后续提交说明；不把Native小预算复现视为ESP默认2 MiB配置实测。旧历史导入、跨存储中断恢复及板端运行不在本轮验证范围，既有存储重放未决项保持未决。
