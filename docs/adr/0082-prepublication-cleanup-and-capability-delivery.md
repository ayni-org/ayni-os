# ADR-0082：预发布清理 存储格式统一与能力自描述交付

- **状态**：已接受；用户 2026-10-29 批准实施。
- **日期**：2026-10-29。
- **关联**：计划 §2、§4、§9；ADR-0053、0080、0081；AP-00/AP-01。

## 背景

用户选择先做 AP-00/AP-01，并明确未发布不做兼容，本轮同时完成清理、代码迁移和必要局部重构。进一步选择一并统一 Core 历史存储格式、对未知记录/版本/标志严格拒绝，并恢复该格式变化必需的故障与恢复验证。

## 决策

1. 按三个完整交付推进：已替代入口清理；schema 3 与必要恢复验证；能力自描述。每包 draft、独立审查、修复、适用 CI 全绿后 merge commit。详细状态见[实施清单](../architecture/ap00-ap01-implementation.md)。
2. 首包删除 provider include bridge 及已被正式入口替代的 kernel/policy/control 草案。未知值拒绝测试自带非法值，不依赖旧声明；保留有独立待实现用途的 Host trace 草案。正式运行结构和领域行为不变，ABI 递增为 0.46，所有消费者重编译，不保留兼容路径。
3. 日志/快照只读写 schema 3，每个记录族/存储上下文一种当前正文。历史版本所表达的有效业务语义改用显式标记；不删除授权、来源、清理和恢复证明。未知记录/版本/标志拒绝恢复，已知非法正文按损坏处理，旧目录原样保留，不迁移、不自动清空。
4. 第三包说明归扩展，runtime 配对，模型 Provider 在 submit 内合并 Core 权威视图并复制。必需说明缺失或失配外发前拒绝；删除旧 binding ID 说明和重复工具文法，无 legacy 回退。保留实际输入 parser 到 AP-02 替代。
5. 恢复仅本次格式变化必需的故障/恢复验证，复用现有运行器。M2、真实设备、付费模型、变异及其他新专项不在本轮内。

## 后果

不同 ABI 的调用方重编译；schema 3 交付后旧数据需保留原目录并用新目录启动，回退只能使用原二进制与其原数据。新存储证据不能自动沿用 schema 2 的历史验收结果。旧 ADR 保留历史含义，ADR-0080 的 optional 扩展待决项在严格格式实际交付与验证后关闭。

## 备选方案

- 保留旧路径、双说明和多格式 reader：用户明确不选择。
- 仅改 schema 号而保留所有旧正文选择分支：未完成清理，不采纳。
- 将业务变体一并删除：会破坏现行授权/恢复语义，不采纳。

## 验证

首包公共头、正式入口消费者、未知意图拒绝和版本测试通过；独立审查无剩余阻断项，证据见 [#105](https://github.com/RobotSe7en/ayni/pull/105)。格式统一与必要恢复验证见 [#106](https://github.com/RobotSe7en/ayni/pull/106)。第三包能力闭环见 [#107](https://github.com/RobotSe7en/ayni/pull/107) 与 [用法契约](../../contracts/host/tool_usage.md)，不把规划当执行证据。

AP-01 以 ABI0.47 发布模型中立 C99 描述与只读端口。Provider 通过纯公开 `ayni_validate_utf8` 复用 foundation 的现有规则，避免在边界复制 Unicode 算法；Core 不感知说明结构、不保存长文。增加的固定说明内存只在 Native 模型 Provider 请求槽，不能推定 ESP32 预算。
