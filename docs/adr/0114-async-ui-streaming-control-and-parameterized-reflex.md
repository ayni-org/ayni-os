# ADR-0114：异步界面、流式控制与传感参数反射

- **状态**：已实施；正常主机验证、独立复查及最终固件编译通过，板端时延待测。
- **日期**：2026-11-25
- **关联**：[低时延路线](../architecture/low-latency-realtime-agentos-plan.md)、ADR-0110～0113；目标 ABI 0.61 / schema 11。

## 背景

用户要求按照所提供的《极低时延实时反馈、异步界面解耦与旧代码清理实施方案（修订版）》开始实施。当前基线 ABI 0.60 的 UI 输入/输出共用包池，终态通知拥堵会使 Chat 提前返回而跳过 Core step，LCD 同步 DMA 阻塞交互线程。

## 决策

本次请求采用计划中的七项选择；它们属于本次实施范围，不以计划中的“已拍板”文字补造先前授权历史：

1. Core 签发 SESSION 包络，执行端复用 replace_target / push_segment 热更新，PermitGate 每拍验证实际输出。
2. 高频连续整形归独立 ControlLoop；Core Reflex 使用受检整数仿射投影处理瞬态调用。
3. 直接升级 ABI 0.61，schema 保持 11；删除废弃 ABI 占位、background 策略及 motor.plan，保留持久记录输入格式校验。
4. UI/控制解耦：独立输入/输出池、异步 LCD、目标 latest-wins、停止粘滞至输出停稳证明、独立接受/覆盖/应用/拒绝/停机反馈。UI 拥堵不能跳过 ayni_step。
5. BargeInPolicy 默认 hold；窄包络不允许低速时软停。显式取消与急停始终执行停止。
6. 不新增自然语言快捷词解析；结构化控件和经 Core 授权的模型目标分别接入邮箱。
7. 完成便携实现、主机验证及最终 ESP-IDF 6.0.3 编译；不自动 OTA、擦卷、真实运动或调用付费模型。用户补充要求固件编译集中在全部改动完成之后。

按 UI/邮箱、清理与 ABI、流式控制、参数反射与测量、契约和验证组织提交。

### 第一批机制

- InputPacket 的 6 × 4 KiB 与 OutputPacket 的 8 × 8 KiB 有效载荷合计 88 KiB，相对原 128 KiB 共享载荷减少 40 KiB；元数据、进度槽、独立 32 KiB 模型槽及显示帧另计，不能当作部署总 RAM 节省量。
- 三缓冲的原子状态只保护槽位所有权，普通字段的读写始终分槽。多写者争用显式返回 busy；收据由目标写者串行发布，执行反馈由唯一控制线程发布，UI 分别读取，不依赖普通字段 seqlock。
- 控制序号使用 32 位原子编码；保留专用耗尽硬停序号。硬急停不可降级；确认早先序号不清除后来请求，停止之前的目标即使确认后也仍被屏障拒绝。
- ESP-IDF 的 PSRAM 原子 workaround 会对外部内存回退到锁，故组合根把 ControlMailbox 独立放入内部 RAM，32 位操作使用 IDF 原生 S32C1I 分支。显示任务 TCB 和 4096 B 栈同样放内部 RAM；双帧和已确认像素影子放 PSRAM。
- lcd-display 优先级 2；只在短帧复制时持元数据互斥量，SPI/DMA 和回执等待均不占用 chat-io。普通帧可合并；工具帧不可覆盖，真实 DMA 完成后可靠投递 render_info、display_ack，队列拥堵保留进度重试。待提交工具帧冻结画布，取消后释放。
- 最终通知在 Core/reflex/audit 推进后尝试排队，关闭前保留 Session/Host/Kernel。UI 完全失去消费能力时，关闭排空最多等待 2 秒；超时明确记录未交付终态后释放，不能报告为通知成功。
- 五态反馈放在电机页的独立“反馈”详情中，原启停/自检状态保留。

### 通用独立授权操作会话

用户在本轮明确选择通用方案。`runtime/operation_session` 通过现有公开 Goal/Task/Call API 组合生命周期，不给 Core 增加电机或聊天分支：

- 开启请求先通过来源 Call 的授权；新建无父节点的 `CANCEL_ON_REBOOT` Goal，按其精确需求另取得完整 Grant。来源 Goal 专属 Grant 不转移、不继承，也不自动批准。
- 注册的策略只调用配置的精确 Binding。创建、授权、句柄交付、激活、关闭、终态分别建模；独立 Goal 已获授权且开启回执成功投递后才打开执行门。句柄只是身份，不是能力令牌。
- 独立操作不随来源回合结束；自身到期、撤权、租约、取消与停止仍生效。原绝对到期时间覆盖授权与交接等待，执行线程首次启动及热改都只使用剩余时间，不能重新起算。
- `motor.stream` 是开启工具，内部物理 ACTION 为 `motor.stream.execute`；`motor.steer` 每次仍经 Core Grant/Scope 检查，再校验当前会话身份、owner 和原包络。手柄未交付的取消执行回滚；关闭期间继续排空已接受 Provider 回执，已受理目标与输出停止分别报告。
- 同一机制已用于两个无关的软件 Binding 正常测试；没有设备时不需要驱动或硬件停止链。单个实例容纳一个有界操作，多路部署可组合多个实例；不引入全局会话注册表。

### 控制与参数反射

`ControlLoop` 是显式输入/下一状态的纯整数转换，允许状态原地更新，不申请堆内存或执行 I/O。最多四路已配置传感源均为必需，缺失、过期、退化、未来时间、硬停阈值及周期超时均要求软停；hold 与传感比例取较小者。单拍 slew 从零起步且只限制增速，减速立即生效。当前 ESP bench 未接实体测距源，传感避障只取得便携实现证据。

`tick_effective` 保持 desired 和排队段不变，实际输出逐项校验同号、幅度不增加和完整许可范围；窄许可不能借“降速”绕开下界。硬件首次输出、热改及换段都使用已通过 Gate 的 effective。软停后握手及已排队启动序号均不可复活。

Reflex 在启动规范化输入后解析精确 I64 字节位置，拒绝重复位置、非整数/缺失路径、零分母和越 Schema 输出范围。触发只复制至预留槽并修补至多四个位置，之后完整运行 Agent/Grant/Scope/Scene/ExecutionBinding 校验。无符号 32 位分肢乘法、64 位长除法与饱和加法给出确定整数结果，不依赖原生 128 位类型；schema 11 无新增记录。

### 调度与时延边界

主机使用 `steady_clock` 实测 512 B、8 KiB、32 KiB 保留历史（后两者提高测试保留预算以防 seed 被裁掉）的真实 ToolLoop 决策及 16 item 的 Core 步进。Debug 长历史决策 P99 约 0.54 ms，按约八倍余量向上取整为 owner `step_us=5000`，`step_units=16` 与测量一致。它是协作式预算，不能抢占单次策略调用；主机倍数不构成 Xtensa CPU 时限证明。相比旧 250 ms，允许 Core 更频繁返回 owner；慢调用不再以拉长整拍预算解决。板端仍须测量并校准，不声明硬实时保证。

ObservationSlot 从 clean 到 dirty 直接 wake；ESP task notification 保留忙时唤醒，下一次等待立即取走。UI 终态排队在 Core/reflex/audit 推进后，输出背压不改变这个顺序。

## 后果

所有 0.x 调用方按最终 0.61 重编译；Core 存储格式不变。ControlLoop 是有界整形与超时保护，不是安全认证功能，不替代独立硬件停止链。输出低电平证明不等于车轮或目标停稳。

## 备选方案

保留共享池、同步 LCD 或清零即消费的停止标志都会使界面压力影响控制时序或丢失停止确认，故不采用。每拍替换 desired 会清空轨迹，故使用独立 effective 校验接口。

## 验证

正常便携 Core/control/策略/ABI 与 Wi-Fi 集成检查通过 ASan/UBSan；Wi-Fi 主机检查通过。目标邮箱和 ObservationSlot 的既有并发用例通过 TSan。Release/ASan 的真实主机闭环、目标接收、参数反射及短/中/长历史微基准通过已实现的主机门槛；无设备的软件 Binding 证明同一独立生命周期可复用，生产电机注册及正常关闭交接通过。按工作流完成独立只读审查与设计自查，修正停止屏障、关闭借用、失败分类、TTL、ASR 顺序及历史停止展示问题。

最终 Xtensa/ESP-IDF 固件在全部实现和主机检查结束后编译通过，未出现编译警告或错误；上游 Kconfig 弃用提示保留。C ABI、契约、依赖与机械可读性检查通过。Reflex 参数元数据在本机每 slot 增加 360 B，关闭该可选目录时不增加其 arena 区；最大内存测量现包含 Reflex/event/audit 容量。
