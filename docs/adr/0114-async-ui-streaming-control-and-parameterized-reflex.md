# ADR-0114：异步界面、流式控制与传感参数反射

- **状态**：实施中；分批提交，完整验证尚未完成。
- **日期**：2026-11-25
- **关联**：[低时延路线](../architecture/low-latency-realtime-agentos-plan.md)、ADR-0110～0113；目标 ABI 0.61 / schema 11。

## 背景

用户要求按照所提供的《极低时延实时反馈、异步界面解耦与旧代码清理实施方案（修订版）》开始实施。当前基线 ABI 0.60 的 UI 输入/输出共用包池，终态通知拥堵会使 Chat 提前返回而跳过 Core step，LCD 同步 DMA 阻塞交互线程。

## 决策

本次请求采用计划中的七项选择；它们属于本次实施范围，不以计划中的“已拍板”文字补造先前授权历史：

1. Core 签发 SESSION 包络，执行端复用 replace_target / push_segment 热更新，PermitGate 每拍验证实际输出。
2. 高频连续整形归独立 ControlLoop；Core Reflex 使用受检整数仿射投影处理瞬态调用。
3. 直接升级 ABI 0.61，schema 保持 11；删除废弃 ABI 占位、background 策略及 motor.plan，保留持久记录输入格式校验。
4. UI/控制解耦：独立输入/输出池、异步 LCD、目标 latest-wins、停止粘滞至输出停稳证明、独立接受/覆盖/应用/拒绝/停机反馈。UI 拥堵不能跳过 ayni_step。
5. BargeInPolicy 默认 hold；窄包络不允许低速时软停。显式取消与急停始终执行停止。
6. 不新增自然语言快捷词解析；结构化控件和经 Core 授权的模型目标分别接入邮箱。
7. 完成便携实现、主机验证及最终 ESP-IDF 6.0.3 编译；不自动 OTA、擦卷、真实运动或调用付费模型。用户补充要求固件编译集中在全部改动完成之后。

按 UI/邮箱、清理与 ABI、流式控制、参数反射与测量、契约和验证组织提交。

### 第一批机制

- InputPacket 的 6 × 4 KiB 与 OutputPacket 的 8 × 8 KiB 有效载荷合计 88 KiB，相对原 128 KiB 共享载荷减少 40 KiB；元数据、进度槽、独立 32 KiB 模型槽及显示帧另计，不能当作部署总 RAM 节省量。
- 三缓冲的原子状态只保护槽位所有权，普通字段的读写始终分槽。多写者争用显式返回 busy；收据由目标写者串行发布，执行反馈由唯一控制线程发布，UI 分别读取，不依赖普通字段 seqlock。
- 控制序号使用 32 位原子编码；保留专用耗尽硬停序号。硬急停不可降级；确认早先序号不清除后来请求，停止之前的目标即使确认后也仍被屏障拒绝。
- ESP-IDF 的 PSRAM 原子 workaround 会对外部内存回退到锁，故组合根把 ControlMailbox 独立放入内部 RAM，32 位操作使用 IDF 原生 S32C1I 分支。显示任务 TCB 和 4096 B 栈同样放内部 RAM；双帧和已确认像素影子放 PSRAM。
- lcd-display 优先级 2；只在短帧复制时持元数据互斥量，SPI/DMA 和回执等待均不占用 chat-io。普通帧可合并；工具帧不可覆盖，真实 DMA 完成后可靠投递 render_info、display_ack，队列拥堵保留进度重试。待提交工具帧冻结画布，取消后释放。
- 最终通知在 Core/reflex/audit 推进后尝试排队，关闭前保留 Session/Host/Kernel。UI 完全失去消费能力时，关闭排空最多等待 2 秒；超时明确记录未交付终态后释放，不能报告为通知成功。
- 五态反馈放在电机页的独立“反馈”详情中，原启停/自检状态保留。

## 后果

所有 0.x 调用方按最终 0.61 重编译；Core 存储格式不变。ControlLoop 是有界整形与超时保护，不是安全认证功能，不替代独立硬件停止链。输出低电平证明不等于车轮或目标停稳。

## 备选方案

保留共享池、同步 LCD 或清零即消费的停止标志都会使界面压力影响控制时序或丢失停止确认，故不采用。每拍替换 desired 会清空轨迹，故使用独立 effective 校验接口。

## 验证

第一批正常主机集成检查通过；独立审查发现的内部 RAM、取消帧、反馈显示、发布争用、音频边界及序号耗尽问题已修正。完整 ASan/UBSan/TSan、闭环/反射微基准、最终固件编译与板端时延仍分别待验证；编译不代表板端通过。最终命令与结果随交付记录集中保存。
