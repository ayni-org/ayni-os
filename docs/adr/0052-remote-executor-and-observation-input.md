# ADR-0052：远程执行端与观测输入的线程模型

- **状态**：提议（推荐方案见“决策”；用户确认前不实施任何依赖它的 ABI 或代码）
- **日期**：2026-10-25
- **关联**：ADR-0015、ADR-0044、ADR-0049、ADR-0050、ADR-0051；架构静态审查（基线 `e089a22`）F15；MA-008B 订阅
- **决定时点与依据**：在第一个远程执行端（ESP32 链路或 ROS Bridge）或 MA-008B 订阅的数据源开始实现之前，由用户在两种模型中选定；依据是能否保持已验证的停止链与 ABI，以及能否用带延迟的远程 Mock 证明 `ayni_step` 不阻塞。

## 背景

Core 的外部 I/O 现在有两种线程模型并存：

- Provider 走异步邮箱（ADR-0044）：`submit` 只受理，结果由任意线程投递，拥有者线程消费。
- 执行端端口（`include/ayni/execution.h`）在拥有者线程同步、有界、非阻塞地运行：派发前 `challenge`，续租时 `challenge` 与 `renew`，急停时 `stop`，轮询时 `status`，均在 `ayni_step` 内由 `ExecutionControl` 调用。M1 只有本地 Mock。
- `ayni_publish_observation` 只能在拥有者线程调用；事件则经线程安全的 ingress 队列（ADR-0015）。

真实或远程执行端的 nonce 往返要经过链路，同步端口要么阻塞 step，要么给不出新鲜 nonce；MA-008B 订阅的数据源大多在其他线程。这两点要在更多代码依赖同步语义之前定下来。

## 决策（推荐，待确认）

1. **远程执行端一律由本地代理闸门前置，执行端 ABI 不变。** 代理与 Kernel 同机，用 ADR-0049 的许可门在本地持有 nonce、许可、租约与停止状态，所以四个端口仍能在拥有者线程同步、非阻塞地回答。代理把许可、续租与停止异步转发给远端；远端执行器自身也运行许可门，链路中断时按自己的租约停止输出。
2. **代理的回答不能强于远端事实。** 只有收到远端的停止测量后，代理才报告已停止；代理只能对从未转发出去的许可报告 `NOT_FOUND`；代理授予的租约不长于远端能独立保证的租约。`stop` 立即在代理侧禁止续租与转发，再要求远端停止，返回值仍不是停止证据。
3. **观测输入复用 ingress 模型。** 拥有者线程之外的观测源经与事件相同的线程安全队列进入拥有者线程，再按现有规则写入 `ObservationTable`。`ayni_publish_observation` 保留为拥有者线程接口，供本来在拥有者线程采样的 Host 使用。队列满时拒绝新样本并计数，不阻塞生产者；丢失的样本只会让 Scene 依赖变旧而停止执行，不会放行执行。
4. 本决定不改 ABI 与 Core 代码。代理闸门是 runtime/Host 侧组件，在第一个远程执行端工作包中实现；观测队列在 MA-008B 中实现。

## 后果

- 许可签发、停止链与同步端口保持现状，已验证的安全语义无需重新论证；链路的不确定性限制在代理与远端两个本地许可门之间。Core 不区分本地执行端与代理。
- 每个远程执行端多一个代理组件和一份链路协议；代理要把远端租约保守地映射到本地时钟。
- 观测与事件共用一种跨线程入口，订阅数据源无需占用拥有者线程。

## 备选方案

- **现在定义异步执行端 ABI**（`challenge`、`renew`、`stop`、`status` 各有请求与完成变体，像 Provider 一样走邮箱）：需要升 ABI 版本；急停优先于日志准入、授权失效即停等停止链规则要在异步完成下重新论证；目前没有远程执行端可以验证，故不推荐。
- **暂不决定，只记约束**：同步语义会继续被新代码依赖，之后迁移的成本更高。
- **允许任意线程调用 `ayni_publish_observation`**：`ObservationTable` 要加锁，并与拥有者线程上的 Scene 判断竞争，违背单一拥有者模型。

## 验证

本 ADR 不交付代码。实施时须证明：带可控延迟和断链的远程 Mock 下，`ayni_step` 不因执行端端口阻塞；断链后远端在租约内停止输出；代理在收到远端停止测量之前不报告已停止；观测队列满时不阻塞生产者，也不放行已过期的依赖。
