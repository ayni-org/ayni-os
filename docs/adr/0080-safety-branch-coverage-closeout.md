# ADR-0080：安全范围分支覆盖收尾

- **状态**：已接受（用户 2026-10-28 授权本项及其后 Core Alpha 报告）
- **日期**：2026-10-28
- **关联**：计划 §9 M1、§10.6；ADR-0071、0075～0079

## 背景

完整 E1～E4 已交付。#101 合并后的阶段测量中，Core 行覆盖达到 75%，保守安全范围分支仍低于 90%。用户最新明确要求补做安全分支覆盖率，再完成 Core Alpha 报告；M2 继续暂缓。此次恢复相关测试，不恢复生产代码植入缺陷或变异活动。

## 决策

1. **口径不变。** 沿用 `tools/collect_coverage.py` 的 Core、permit_gate、Mock Provider 与 Mock 执行端范围及所有相应 TU 头文件；GCC 13 Debug、无 sanitizer、atomic counters，按行并集与函数/有序分支布局槽并集统计，仅过滤 compiler throw arcs。不缩分母、不删除防御分支追数。
2. **按不变量补证据。** 从 #101 既有原始数据定位缺口；分别补持久事实/重放、调用与结果、授权/目录以及执行/订阅端口的边界场景。优先走公开契约；模块单测的内部调用标记 White-box，使用合法前置状态，验证拒绝、分类错误与失败后状态保持，不能用非法内存或绕过前置条件制造覆盖。
3. **收集与冻结。** 迭代数据只用于定位；最终干净修订重新构建、发现测试后清除 counters，运行完整既有及新增测试和模拟器，再一次收集完整数据。计数、命令、实际配置与原始数据来源集中交付 PR；原始数据未上传时明确标为仅本地。
4. **交付。** 覆盖率作为一个完整 PR，draft 提交后只读独立审查、修复并复核影响；最终适用 CI 全绿后 merge commit。Core Alpha 报告另一个 PR，补齐最终配置验证与证据索引，随后停止。M2、完整 MA-038、真实设备与付费模型均不自动开展。
5. **问题处理。** 有实证的机制缺陷在本项范围内修复；涉及产品语义、兼容、验收阈值或统计范围的新决定先带证据询问用户。不把未达或未执行写成通过。
6. **订阅新代恢复修复。** 补测发现确认停止后 live `restart_subscription` 生成的合法新代，会被 Call replay 的旧终态查询检查拒绝。沿用 ADR-0063 的新代准入，由原 `reopens_subscription` 证明已知停止及新的合法 generation；此分支要求无 query，其他历史仍走原 `query_advances`。UNKNOWN 不获新代重试权限，不改 ABI、记录版本或生产策略。
7. **回调 ABI 尺寸分类修复。** 独立审查发现 `request_call`、`call_result`、`call_tool` 将较大的 `struct_size` 与短结构一起判为 INVALID_ARGUMENT，违反 C-VER-004 / ADR-0053；相邻的 Provider tool 描述回调也有同类缺陷。四个入口改用既有 `catalog::check_struct_size`，较大尺寸返回 UNSUPPORTED_VERSION，短尺寸或空指针仍拒绝，失败不写输出。不新增状态、ABI 布局或存储版本。

## 后果

补测保持领域模块的不变量属主与生产依赖方向。目标仍为 Core 行 ≥75%、保守安全分支 ≥90%；软件覆盖不证明 ESP32、物理停止时间或耐久。ABI/schema 仅在实际语义变化并获相应决策后调整。

## 备选方案

- 缩范围、删防御检查或把缺失数据排除：会改变验收含义，拒绝。
- 用随机输入返回不崩溃代替明确断言：不能证明拒绝与状态保持，优先有限场景和独立预期。
- 顺延恢复变异或推进 M2：不在本次授权内。

## 验证

基线来源为 #101 的合并后阶段测量；本次实际结果、独立审查、最终 CI 与限制集中交付 PR，不预填达标结论。
