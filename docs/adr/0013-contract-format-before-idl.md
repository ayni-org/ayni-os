# ADR-0013：IDL 选定之前的契约表达方式

- **状态**：已接受（M0 已实现；IDL 选定后由 ADR-0009 的结论接续）
- **日期**：2026-10-19
- **关联**：计划 §3.1、§3.2、§9（`MA-017` 完成定义）；ADR-0009、ADR-0011、ADR-0012；`MA-005`、`MA-017`

## 背景

计划要求 M0 把第 2.5/2.7/2.8/2.10/3.4/3.6 节与五项产品语义写成“可判定”的契约，并由 `contracts/domain/` 生成或核对 C 类型、JSON Schema、持久化映射与 conformance fixtures（§3.1）。但 IDL 与本地 API 编码（ADR-0009）要到 M1 早期按 ESP32 的固件体积、峰值 RAM 与消息延迟实测决定。M0 需要一种现在就能写、能检查、以后能平滑迁到 IDL 的表达方式。用户在 M0 规划中选择了“Markdown 契约 + 可编译 C 头文件草案”。

## 决策

1. **条款写成 Markdown 表格**，每条一行四列：ID、规则、反例、验证（`contracts/README.md`）。ID 形如 `C-<领域>-<三位序号>`，一经发布不复用；每个领域前缀只属于一份文档，跨领域只引用 ID、不复制正文。
2. **反例列是必填项。** 它直接对应一个反向测试，让“可判定”有可检查的标准：写不出反例的规则说明它还不能被测试区分。
3. **验证列指向实验步骤、工作包或测试名。** 已实现的条款写“M0 已实现”并给出 GoogleTest 名（`Suite.test`）或 CTest 名（ctest `name`），由工具核对这些测试真实存在。
4. **接口形状用 C 头文件草案表达**，放在 `include/ayni/draft/`：只有声明、没有符号，调用会在链接时失败而不是得到伪造结果；草案与已发布 ABI 分开命名，避免同时包含时冲突；每个草案头文件单独、以及全部头文件合在一起，都以 C99 `-pedantic-errors` 与 C++17 编译（`tests/contract/`）。实现某个接口时，整组声明移入正式头文件并按 C-VER-002 追加（C-VER-007）。
5. **`tools/check_contracts.py` 做机械检查**，在 CTest（`check_contracts_repository`）与 CI 中运行：四列齐全且非空、ID 唯一、前缀与文档一致、全仓库引用的 ID 都有定义、引用的测试存在、计划中 E1–E4 的每个步骤都至少被一条条款的验证列点名，并生成 `contracts/traceability.md`（过期即失败）。
6. **字段宽度与编码不在 M0 固定。** 条款规定语义与最小字段；具体编码在 M1 由 fixtures 收敛，IDL 选定后由 ADR-0009 决定是否生成 C 类型与 JSON Schema。持久格式例外：`storage/records.md` 给出字节布局草案，因为故障注入测试需要具体格式，定稿前 `storage_schema` 为 0。

## 后果

- 条款可以被普通 Markdown 工具阅读和评审，不需要先学 IDL；代价是语义靠人写、靠评审，工具只能检查结构与引用，检查不了规则是否正确。
- 草案头文件让接口问题（所有权、线程、完成方式、版本字段）在 M0 就暴露并能编译检查，但它们没有实现，不代表任何能力已存在。
- 选定 IDL 后要做一次迁移：能由 IDL 表达的类型改为生成，条款表格保留为语义说明与反例来源。迁移成本主要在 `include/ayni/draft/` 与 fixtures，条款 ID 不变。
- E1–E4 覆盖检查依赖计划中实验表格的格式（`| 1. ` 与 `| F0：` 行首）；计划改格式时须同时修改检查脚本。

## 备选方案

- **M0 就选定 IDL（如 Protobuf/nanopb）**：ADR-0009 的实测条件在 M0 不具备，提前选型可能在 M1 推翻，否决。
- **只写 Markdown、不写头文件**：所有权、线程与 ABI 版本字段等问题要到 M1 写代码才暴露，否决。
- **只写头文件、用注释表达规则**：反例与验证点无处安放，难以追踪覆盖，否决。
- **用 YAML/JSON 存放条款再生成文档**：多一层格式与工具，中文长句在 YAML 中可读性差；当前规模用 Markdown 表格加检查脚本即可，否决。

## 验证

- M0：`check_contracts_repository` 与 `check_contracts_rules`（18 个场景）通过；头文件检查在 GCC 与 Clang 下通过。
- M0 结束：`reports/core/m0-review.md` 复核条款与计划一致，并列出未被条款覆盖的计划规则（目标为无）。
- M1：第一批 fixtures 引用条款 ID；ADR-0009 决定 IDL 后修订本 ADR 的状态。
