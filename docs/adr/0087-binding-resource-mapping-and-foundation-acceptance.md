# ADR-0087：Binding 资源映射与基础验收边界

- **状态**：资源映射及本包直接升级已接受（产品/兼容语义，用户 2026-10-30 选定）；基础验收实施中。
- **日期**：2026-10-30。
- **关联**：ADR-0083～0086；AP-04/AP-06；[实施设计](../architecture/ap06-ap04-foundation-design.md)。

## 背景

同能力版本的 Provider offer 必须与 Capability 完整契约相同。资源 ID 在契约内，故两个 Binding 虽可精确选择端点，却不能分别声明独立的 Core 资源。基础验收需要同语义两个软件实例的独立/共享资源证据。SDK 已有生命周期和值辅助，软件工作流仍只有 Sim 示例证据。

## 决策

1. 用户选择有界 Binding 资源映射；保留 Capability 的逻辑需求、单位及其他执行语义，按绑定替换实际资源 ID。映射不增删、合并或改变单位；省略项为恒等映射，启动前冻结。Provider offer 仍精确匹配逻辑契约。
2. catalog 统一解析有效契约与实际资源索引，调用接受、资源准入和派发复用结果。Call 保存有效实际组及原业务证明；原证明/实际组的本征校验保留非资源语义及需求单位的一一对应，派发另核对当前完整有效契约，禁止旧 Call 暗换资源或端点。
3. 用户明确“直接升级，还在开发，不用兼容”：本包 ABI 0.52 / schema 8，全仓重编译，拒旧保留目录，无旧 reader/迁移器；回退使用原二进制与原目录。既有 Call 字节布局可表达有效组，语义变化仍升级 schema，策略与 SQLite 版本独立且不变。
4. 软件样例应用归 applications，runtime 负责 Native/Sim/Provider 装配。共用 Task checkpoint、真实结果校验及关闭规则，不增加业务专用 Core、模型 codec 分支或新 SDK 框架。
5. 正常软件与公开边界验证、既有专项回归、设计自查及独立审查属于本包。变异、新故障/恢复、硬件、付费模型和平台实验未由本决定启动。基础覆盖按用户后续统一为80%的目标处理（ADR-0088），必要未验证证据分别处理；不是沿用 ADR-0080 的局部例外。

## 后果

同一能力可绑定不同实际资源，原权限与 Provider 契约保持稳定；接入实例只改 Provider/Binding 与部署资源配置。当前仍不支持按 Provider 改 form/effects/超时等约束；出现真实需求后另行演进，不能借资源映射绕过检查。映射增加有界配置及解析成本，ABI/容量变化随本包实测。

## 备选方案

- 完整拆分 Capability/ProviderOffer/Binding 的所有执行约束：本次仅需资源隔离，用户未选，避免扩大迁移面。
- 只保留共享资源或给每实例捏造不同能力版本：前者缺少基础场景，后者把部署差异误作业务语义变化，均不采纳。

## 验证

实施与验收中。正常场景、实际检查、适用审查和最终结论随交付 PR 更新；尚未执行的恢复及平台验证不记为完成。
