# ADR-0106：操作内正文复用与会话发布确认

- **状态**：已实施；相关本地正常验证及独立复查通过，ESP编译结果见实验记录，本轮不OTA。
- **日期**：2026-11-16。
- **关联**：ADR-0100、0104、0105；C-POLICY-013、C-HVAL-009、C-SDK-009/011。

## 背景

用户要求继续精简共享输入到结束流程的重复遍历、复制、校验和确认，同时保留权限、隐私及必要持久保证，只做本地验证。前一版已移除结果测长/输出的双遍Schema投影，但依赖发现、准备与使用仍反复复制/验摘要；每个检查点回扫历史来请求保存；Session等待确认及PUBLISH时反复复制、解码完成检查点。

## 决策

1. 共享策略的同步正文边界集中在body_reader.cpp。一次owner操作中的相同完整引用，可复用已验证的不可变小正文；该读区最多保留16 KiB字符串capacity和64条目，另有有界map/handle元数据。大正文及预算满时继续按需读取，prepare每次消费后释放大正文，最终大字段直接移动至输出，不为整张原始图另保留一份缓存。字节摘要与文本UTF-8各按自身边界检查，读区不跨Core推进/隐私变化。缓存耗尽只改变读取次数，不改变接受的正文或静默截断。
2. 会话永久正文在创建时请求后台confirm，共享结果别名请求自己的所有权保存；原write的持久行为保持。检查点不再为请求保存而遍历全部旧历史。模型请求临时正文继续走原put_body，不提前confirm，原终态持久后的到期释放保持。
3. Session以隐私/会话版本及四个完整根引用识别确认图，只收集、去重一次依赖；同ID的不同完整引用显式拒绝。一个引用数组分为已确认前缀与待确认后缀，每次只推进后缀，避免再复制一份待确认数组。后台错误仍从原状态端口报告。
4. background完成Task后只复制/组装一次候选，以显式prepare_publication/publishing阶段持有它，等待整图确认和Core PUBLISH持久时不重读检查点。正常重开没有该内存候选时仍从已完成持久检查点重建，不重跑Task。
5. 外层文件完整保存后，旧图回收借用已确认的新引用集，旧引用去重后只释放一次，用排序ID集合取代两层成员遍历。全部正文/所有权→外层文件→实际清理→精确Core ACK持久顺序保持，取消/关闭继续排空在途发布；权限/来源、动作派发/停止和UNKNOWN不重试由原属主维护。
6. 不改C ABI0.55、区域/持久格式或存储版本，不增加公开借用指针接口、另一套运行器或长期历史缓存。C++源码消费者正常重编译。

## 后果与备选方案

以最多16 KiB小正文容量及64条目的临时元数据，减少重复分配、复制和摘要计算；真实平台峰值仍需单独实测。无界保留整张原始正文图会绕过原FileBodies预算，已改为有界复用和大正文流式路径。跳过外部读摘要/UTF-8或缓存实际授权会削弱边界，均不采用。把旧图删除移到ACK之后需要另有持久清理证据和兼容决定，本次保留真实排空屏障。

## 验证

相关正常软件回归核对冷读/重用的字节一致、独立引用读取次数、超预算大正文和条目边界、UTF-8拒绝；Sim Core与真实POSIX文件验证只确认一次、依赖/文件/精确ACK就绪前不公开答案、发布中取消及删除后新输入，默认durable路径同样覆盖。既有共享Session/LittleFS正常回合及关闭保持。实际结果见[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-16-操作内读取与结束确认简化)。本轮不进行OTA、云端模型、真实设备或新增故障/恢复专项，不以桌面测量声明板端100 ms目标或长期稳定性。
