# ADR-0048：可复用确定性 Mock Provider

- **状态**：已接受
- **日期**：2026-10-25
- **关联**：MA-008A、MA-020、MA-021、MA-023、MA-033；ADR-0045；C-PROV-002、006、008、012

## 背景

公开调用主干已经由 #64 交付，但 Mock 仍嵌在各测试夹具中。Native 示例和后续实验需要可替换、可重复使用的 Provider，不能把测试私有对象或 Core 内部表作为运行时接口。

## 决策

1. `providers/mock` 提供一个有界 C++17 组件，仅依赖正式 C ABI。A/B 使用不同 Provider/endpoint ID，分别在一次/两次显式 `advance` 后推进。文本服务回显复制的输入；动作服务先报告进度，下一次推进再记录模拟呈现并回显。动作不代表执行器或真实播放，不声明物理副作用、查询或服务器去重能力。
2. `submit` 只验证并复制到启动时分配的有界槽；容量不足返回 `REJECTED_NOT_RETAINED`。配置允许 1～64 个槽，每槽文本 1～4096 B。运行中的提交、取消、推进均不分配内存。A/B 的事件顺序由组合根或夹具显式推进；不引入工作线程、真实时钟或随机源，不承诺墙钟延迟。
3. 正常取消在未执行时终结为 `CANCELLED/effect NONE`；已执行结果不能被取消受理改写。终态发表失败时保留槽及原结果，后续推进只重投，不再次执行。成功发表后清空局部正文并归还借用；Core 的 Task 正文保留规则不变。
4. 组件与 Kernel 由同一所有者线程驱动。组合根先停止准入、推进取消和终态，再销毁 Kernel，最后显式 `close`。`close` 在有借用时返回 `BUSY`，析构不冒充成功排空；调用方违反顺序而析构时，有借用的上下文保持分配以避免悬空引用，不能据此声称正常关闭成功。
5. 依赖检查正式登记 Provider 实例边界：可使用本实例头、公共 API 和外部库；不得包含 Core 私有头或其他 Provider。runtime 可装配 Provider，targets 继续只依赖 runtime。新增头参与独立 C++17 编译；C ABI、storage schema 与 Core 容量不变。

## 后果

后续 Native 装配、双 Provider 实验和顺序工作流可以复用相同实现。替换为真实模型 Provider 只需在 runtime 选择其他组件及 Binding；Core 的授权、资源、派发和完成机制不变。许可动作、订阅、工具协议、真实网络和完整 E1–E4 仍分别交付。

## 备选方案

- 继续在每个应用内复制测试 Mock：会让关闭、容量和取消语义各自演化，故不采用。
- Mock 自建线程和定时器：增加无法由确定性夹具控制的事件顺序；真实网络线程由直连 Provider 实现。
- 将 echo 或模拟呈现放入 Core：会把应用行为与调用机制耦合，故不采用。

## 验证

通过公开注册/调用/完成接口验证 A/B 的文本与动作、输入复制、进度、取消、满容量拒绝及正常关闭；依赖规则验证自身头、runtime 装配与跨边界拒绝。实际验证及 CI 结果集中记录在本功能 PR。未开展新的故障、恢复或硬件验证。
