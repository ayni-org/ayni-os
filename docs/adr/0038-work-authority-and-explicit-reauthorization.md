# ADR-0038：工作授权、显式重新授权与正常重启

- **状态**：实施中；F 按 F1～F5 交付，F4 按决策 18 拆为两份代码 PR，F1～F3 已交付内部事实、持久化、消费/查询、清理与触发边界；继续 F4，正常重启仍由 F5 验收。
- **日期**：2026-10-24
- **关联**：计划 §9.1、§14.1；MA-006 F；ADR-0028、0037；C-AUTH-004/005/023/030；C-STORE-020

## 背景

E 已交付 Goal 需求、待批与原子批准；Task 尚无独立授权事实，恢复阶段仍统一拦住已激活工作。E 的历史批准校验也以引用不会替换为前提。F 需要共同补齐运行时传播、清理、显式重新授权、历史证明及正常重启，不能只解除恢复 hold。

用户批准本轮实施计划，并明确开发期不用兼容。用户同时选择分层本地验证、一次性/延迟目标恢复后执行一次，以及周期未派生积压全部跳过。

## 决策

1. **按依赖分五份代码 PR。** F1 内部授权事实、Task 表及 codec；F2 arena、持久化、消费检查和查询；F3 有界工作清理、专属 Grant 终态和触发边界；F4 公开重新授权及历史证明；F5 正常重启与集成验收。生产增删超过约 1,500 行时按内部事实/持久证明先于运行时/公开入口继续拆，安全前置不能后补。五份共用本 ADR，覆盖率在全部合并后统一量测，再作文档收尾。
2. **事实归 work，机制归原属主。** 公共 AuthorityReference 是准入时选定身份，零对表示未选择；Task 必须完整，但允许明确零需求。Task 保存原 Goal 的绑定及按原需求顺序排列的 Grant 引用，不复制原域/Scope，不缓存 Grant 当前状态。Grant、范围、父链、期限及 Gate 仍由 authority 拥有。Kernel 只编排跨表准入和提交，durability 不解释授权。
3. **绑定与暂停分开。** GoalBinding 保存建立绑定的提交序号、确切父绑定和输入恢复水位。普通用户暂停不改变授权绑定；子 Goal 必须检查原父绑定代次，父重新授权不能自动恢复子 Goal。输入实例身份是 ingress 首个持久 boot epoch，不是 Kernel ID；同实例的序号可比较，不跨实例比较。重启不保存队列内容。
4. **Task 表按稳定 slot。** TaskTable 的行 index 会移动，新表只按 Task.slot 及 exact task_id 定位。缺表项与 count=0 不同。恢复必须保持 Task/Goal 身份、需求数，严格推进 stamp，绑定序号不倒退；同绑定只能保留引用或暂停，不能换引用或从暂停恢复。新绑定的合法性由整体重放证明，而非表自行猜测。容量和输出拒绝不得发布部分事实。
5. **F1 codec 边界。** 新 type18/v1 正文为 task_id、goal_id、goal_binding_seq、transition_id、commit_seq 五个 u64，phase/count 两个 u32，随后 count 个 Grant ID u64/revision u32；固定 48 B，每项 12 B。journal/snapshot 共用一个 reader/writer；struct/bytes 共用一个语义验证器。F1 只验证内部表示及 codec，不启用新记录、Kernel arena、公开 ABI 或正常恢复。
6. **开发期存储断开（产品语义，用户明确选择，2026-10-24）。** F2 切换批次和快照 schema=2，仅支持新格式。旧格式在新写入前受限并保留，由开发者使用新状态目录；不自动清空、迁移或回退旧快照，不实现旧 Goal/Task 确认。本项替代 ADR-0028 中本轮 F 的旧数据确认要求；不削减新格式本身的断电恢复和 writer 隔离证明。
7. **运行时消费。** 派生、策略调用前及接受结果前共用原选定引用与祖先检查，回调后重新采样时钟。失效输出及检查点全部丢弃；新 Grant 不自动选择。用户暂停、授权暂停、类型不兼容和策略失败分别保留，有效生命周期由查询组合。
8. **有界清理。** work 拥有稳定 ID 的固定 through/单调 after 和扫描中新增请求的下一轮边界。每次最多一 Goal 授权事实及直属 Task，进度与工作状态同批，消耗 step 预算。authority 保留自己的 Grant 后代游标。快照/背压/写失败不解除即时拒绝。活 Task 保护 Grant；释放、复用和终态使用实际 durable frontier/fence，不另建引用计数。
9. **专属 Grant 结束。** Goal 终态立即不可消费，其专属 Grant 的结束原因由后台工作清理持久证明，然后按原终态排序安全回收；不伪造管理命令或物理停止回执。
10. **显式重新授权。** 新 GOAL_REAUTHORIZE 沿统一入口，绑定 MANAGEMENT、非零 command、Goal revision、授权事实提交序号和完整原创建回显。选择现有有效持久 Grant，专属优先、通用其次、同级按 ID；缺覆盖明确拒绝，先单独创建 Grant。完整预检 Goal 和直属活 Task 后，同批提交新引用、绑定、授权暂停解除、触发水位和命令结果；新恢复事实持久前不执行。子 Goal 单独恢复，其他暂停/失败不清除。
11. **触发语义（产品语义，用户选定推荐项，2026-10-24）。** 未失效的一次性/延迟目标恢复后执行一次，同 boot 不重新延时。周期所有未派生的到期次数（包括暂停前积压）记为跳过，恢复后接回原节拍。输入恢复水位之前全部未消费输入对该 Goal 跳过，不影响其他 Goal。保留已有 Task、步骤和检查点；普通断电提醒及跨 boot 计时契约保持。
12. **历史及恢复证明。** 批准和重新授权命令保留当时完整引用证据；不能以当前引用反推旧批准。新 REQUIRED 记录纳入发现、整批配对、双槽快照和最大容量公式。F5 完整重放并核对绑定/目录/主体/父代次后，永久授权有效工作正常继续；授权暂停、旧 boot 限时权限及不兼容工作继续禁行，不重新导出需求解释旧事实。
13. **本轮验证提速（流程，用户选定推荐项，2026-10-24）。** 每 PR 本地完整 Debug、ASan/UBSan、模拟器和工具检查；同一最终提交的 ready PR CI 完成全部适用矩阵；F 收尾本地五配置。独立审查和 15～25 项独立出题变异保留。验证与只读审查重叠，变异用隔离固定目录增量构建；同一变异源码不并发修改。首轮全部完成后补测试，首轮与补测后结果分开。
14. **质量与证据。** 每 PR 作者/独立审查分别给删除注释、Kernel 新字段、重复公式、裸数字的证据。Core 行覆盖目标≥75%，安全相关分支≥90%；范围固定为 E 原范围加 F 新增授权/清理/重放模块。可触达缺口补测试，不以删除分支、缩范围或 E 已存偏差豁免。PR 写命令/变异表/CI，ADR 仅写结论并链接；状态文档保持简短。

15. **F2 持久接入。** Goal type17/v2 固定头扩为72 B，保存绑定/父绑定/输入边界；Task type18/v1 REQUIRED 随派生同批保存，snapshot 紧接每Task状态。struct/bytes 共用原codec，恢复精确匹配Goal绑定及有序引用，所有存量Task（包括终态）保留事实；新准入须证明完整Grant链在绑定时有效，批准同批专属Grant由原批准证明处理。父链拓扑归GoalTable::visit_lineage，消费/批准/历史校验及工作传播复用。schema2移除不可达旧格式迁移编排，仍保留writer隔离与双槽切换。ABI0.24增加Task摘要/逐项引用查询及Goal绑定摘要，输出均复制到caller；查询即时反映Gate，F2不解除恢复hold。

16. **F3 保持一份 PR。** 实现内部先验证扫描事实、稳定 ID 查询、输入顺序与触发跳过，再接入持久运行时、独立 Task 授权暂停及专属 Grant 终态；这些是同一 F3 的开发阶段。最终以完整生产 diff 核对约 1,500 行门槛，实际超限才按决策 1 的边界继续拆分。ABI 0.25 明确输入顺序耗尽及本份实际公开变化；公开重新授权仍由 F4 完整事务交付。

17. **F3 清理及整批证明。** type19/v1 是 journal 清理事务的末尾见证，snapshot 固定保存一项（含 idle），仍用共享 codec。Goal 4/v4、17/v3 与直属活 Task 的 6/v2、18/v1 逐项配对；授权暂停只改授权事实及提交 stamp，不改用户/策略状态、revision、触发或步骤/检查点，终态 Task 保留历史。扫描合并保留 Goal 和孤儿专属 Grant 的稳定 ID；结束本步 Goal 的全部 ACTIVE 根，写 14/v3 GOAL_ENDED，按既有终态持久顺序回收。游标、完整 cohort 与状态必须同批，footer 后不得夹带记录。15/v2 撤销、14/v4 到期和有活专属根的 4/v3 Goal 终态同批请求扫描；无专属根的普通 Goal 结束不生成无用全表扫描。恢复保留已有扫描，真实权限变化再请求新一轮；目录兼容/主体可用性仍为独立 hold，不经扫描持久化。直属活 Task 与其自身 Goal 的授权 phase 必须在整批恢复与快照中一致；终态历史、子 Goal 和其他 hold 独立保留。缺少独立 deny 的旧暂停 journal 在新写前拒绝，不补事实。F3 不提前开放正常恢复或显式重新授权。

18. **F4 按完整 diff 拆为两份。** 完整生产改动实际超过决策 1 的约 1,500 行门槛，依次交付内部结果事实/持久证明、完整公开重新授权事务。前置提取共享原创建 echo，CommandTable 同槽保留输入与授权结果，批准 journal/snapshot 改用 REQUIRED 9/v5；历史结果独立于当前 Goal 引用，仍受创建 stamp、覆盖边界及 ACTIVE revision1 约束。Goal 快照 3/v4 保存不可变完整创建 pair；旧快照/批准格式明确拒绝，不猜测历史事实。生产 arena 和批次预算共用配置上界，Grant 请求不叠加批准结果空间。前置不新增 ABI 或公开恢复入口；后续将入口与全部拒绝/重放证明同份交付，不再按局部函数分阶段。

## 后果

- work 的 goal/task 向 work/authority 共享事实模块单向依赖；它隔离共同身份/绑定不变量，不新增 authority→work 依赖。共享引用的历史字段注释移至唯一属主，Goal 保留有说明的别名。
- F1 的 Task 表尚未装入 Kernel arena；现有 GoalGrantReference 布局不变，公开 ABI 和持久字节保持。每 Task 只为 configured requirement count 分配引用，不付最大 Scope 副本成本。
- F2 是明确的开发期格式切换；回退使用原二进制与原状态目录，旧 reader 遇新 schema 受限，不能删新字段降级。F 自身的重启恢复、原子性和安全拒绝仍为必需验收。真实许可、Provider 在途取消和完整 E1–E4 仍分别随原包完成。

## 备选方案

- Task 动态借用 Goal 当前引用：Goal 重新授权会隐式改变旧 Task 准入证据，拒绝；保存独立准入引用。
- 每 Task 复制完整需求和 Scope：重复 Goal 的不可变上限并放大 arena，拒绝；Task 保存 Goal 身份/绑定和有界引用。
- 每次父恢复遍历全部后代并改写：扩大原子批次且可能漏掉尚未清理的后代，采用绑定代次和有界持久清理。
- 为开发存储增加旧 Task 自动迁移/确认：用户明确不需要兼容，采用新格式边界，减少跨版本证明范围。
