# ADR-0070：typed 多节点正常子集与固定服务 Task

- **状态**：已接受；服务 Task 选择暂按推荐项实现，改选再改
- **日期**：2026-10-27
- **关联**：P6；MA-038 正常子集；ADR-0009、0068；计划 §3.4；C-FIX-007～010

## 背景

两个独立 Kernel 已有 SimNode，但尚无正常跨节点执行与查询证据。完整 MA-038 的认证、线解码、持久去重/低水位、重放、分区与恢复矩阵仍不在本轮。远端入口也不能把一个节点的 Task/Grant ID 直接当成另一节点的对象或授权。

## 决策

1. **固定服务 Task（暂定实施选择）。** 已向用户提出“固定服务 Task”与“先新增远程准入 Core API”两个范围。尚未收到答复；按 workflow §2.3“提问后按推荐项继续做”的约定，**按推荐项实现，改选再改**，不记为用户已选定。发起 Task 留在 A；B 用预配置的固定服务实例、本机管理 Session 和本机 Grant 创建独立 Goal/Task。没有 Task 所有权转移，也不新增 Core 准入入口。
2. **职责与范围。** `applications/normal_fixtures` 的 `fixture.remote` 导出明确模拟目的地 Scope，并在实际请求中使用同一值。`runtime/sim_node` 组装两个 SimNode、现有 Counter 和私有 FakeTransport；其适配器只实现空正文计数能力和一个预配置通道。Provider submit 仅复制并排队，owner 在两个 Kernel 回调之外推进 typed 消息和本地管理意图，不在 Core step 内跨节点等待。ABI 0.45/schema 2 不变。
3. **节点与权限。** A/B 各有独立 Host、时钟和存储；B 起始时钟有独立偏移，推进节拍不同。夹具实际只推进 A，断言 B 的时间/持久前缀不变。Route 的源 Kernel/instance 与接收服务实例来自组合根，不接受消息自报替换；接收前核对源 Call 的 owner、operation 与持久屏障。两端各通过本机 Goal 需求/Grant 选择和调用消费链，正常路径明确核对所选本机 Grant。预配置通道不是生产认证证据。
4. **有界 typed 请求。** 四项保留槽，已接受身份在本次运行内不复用；重复 submit 或满槽明确拒绝，不建立另一套持久重试系统。A 的 operation 原属 Core Call，B 的服务 Goal 创建使用单独预留的本地管理 command 区间。映射本身仅在 RAM 中保留；接收端 Goal 的持久化不等于实现 C-WIRE-006 的完整持久映射。无线编码/IDL/消息解码器，ADR-0009 的待决条件不变。
5. **正常查询与结果。** 一项 typed 查询独立排队并有确定延迟，通道隐含绑定原调用 peer。回复只提供本例的 operation、原 Task、服务 Goal/Task、Task 状态、效果与接收持久前缀汇总；完整 Call 诊断另外写公开查询轨迹。只有 B 的 Task、Goal 和成功效果 Call 都持久后才回报 A 成功。查无记录不表示 NOT_ACCEPTED；无墓碑、低水位或断连结论。其它终态不推断效果，明确报告未知并保留尚未归还的借用。
6. **身份与可观测性。** 所有跨节点身份带节点限定，允许数值相同；两端独立分配的 Task/instance ID 确实可能碰撞。两次 operation 分别记录执行中/完成查询；原 Task ID/owner 不变，接收端服务 Task 各自独立。实际 Counter 次数证明执行，不以接受或日志替代。产物记录逻辑时钟、Call 状态、查询、编译配置和源码修订，不含正文/凭据/媒体；固定调度两次重放产物一致，不是网络抓包或全部 journal 的镜像。
7. **正常在途关闭。** 第二次调用在服务 Task 运行中发起正常关闭。先取消不持有效果/Kernel borrow 的只读查询，在两端仍 RUNNING 时有界完成已接受服务和最后的结果核对，然后进入 DRAINING、排空并销毁。先 DRAINING 会使服务策略无法发布完成。不能证明关闭时保留包含 Link、Counter、Policy、Host 和 arena 的全组合；异常兜底 guard 也遵守此边界。首因、close、artifact 分类独立，保留 C API 原状态，分配失败单独分类。

## 后果

可以在 Native 重放固定 owner 的正常调用和查询，并复核独立存储/时钟、两端本地工作响应、本机权限消费及在途正常关闭。没有通用远程生产 API；服务 Session 是可信组合根的受限接线输入，不是对外提供任意管理入口。替换真实传输、接收准入或服务策略必须另做协议/认证、授权、持久映射和生命周期设计。

## 备选方案

- 现在新增远程准入 Core API：扩大 ABI 与持久机制范围；已向用户提出，本轮先用已有公开机制。
- 直接把源 Task 或 Grant 写入接收 Kernel：跨越属主与授权边界，拒绝。
- 把 RAM 映射称为完整协议去重，或把预配置 peer 称为生产认证：缺少所需证据，拒绝。

## 验证

MA038-N1 的实际调用/查询、在途正常关闭、双次产物重放和新目录边界已验证；原九个正常场景回归通过。具体命令、独立审查与最终 CI 在对应 PR 汇总。没有新增故障/恢复/变异专项；完整 MA-038、真实链路/认证与硬件仍未验证。
