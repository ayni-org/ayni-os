# ADR-0090：通用有界工作区与低栈接口

- **状态**：已接受设计；实施与验证中。
- **日期**：2026-10-31。
- **关联**：ADR-0014、ADR-0084、ADR-0089；[独立接入计划](../architecture/independent-consumption-plan.md)。

## 背景

既有有界 Schema、原业务证明与对话控制器把数十 KiB 的候选树放在调用栈。Native 可运行不代表适合 ESP 内部任务栈。降低功能上限或给 Core 加平台分支都会使同一库的契约分叉。

## 决策

用户选择先完成通用内存整改，必要接口直接升级全部消费者。ABI 升至0.53，不保留旧的大栈调用入口；Core schema8、业务证明编码与策略格式4不变。

Kernel 从调用方 arena 划出一个有界暂存区，单一 owner 及其同步调用链借用。Catalog/WorkModel 只持有引用；Producer ingress 继续使用低栈只读投影验证，不访问 owner 工作区。临时对象按词法作用域释放，擦除活动字节，无 Core 堆分配、TLS、全局暂存或平台判断。

独立纯函数通过 `ayni_workspace_v1` 显式借用对齐区域：值/Schema/参数操作与完整业务证明分别查询容量。回调仍持有原证明时，嵌套解析使用另一条区域；区域不足、布局不支持及非法对齐保留原错误分类。区域、输入、输出不得重叠，输入在返回前不可变，回调视图只在同步调用内有效。

ToolLoop、Conversation 与结果 JSON 投影分别公开自身的内存查询。策略在配置时借用区域，不在 decide 分配；Conversation 每次操作显式借用。调用方可用 C 自有内存或可选 C++ `Workspace` 所有者，在启动前分配，也可借用平台选择的内存。FreeRTOS/Linux 等平台只决定这些区域的位置和任务栈；不改变 Core 调度、ToolLoop 或授权机制。

## 后果

以可查询的 arena/组件字节取代大栈候选，支持预分配与平台 PSRAM 选择；不承诺所有配置都适合所有硬件。Query 提供有界上限，部分路径不使用整个区域。临时对象及嵌套 public codec 各有明确存活范围，擦除增加有界 CPU 工作，实际资源和时延分别量测。

公开纯函数及 C++ 策略/对话消费者需要重新编译和升级调用。旧二进制、源码与原存储目录可整体回退，不加入迁移器；本包没有持久语义迁移。新独立应用仍须在指定 profile 上测量实际栈余量，Native 栈帧不能替代 ESP 实测。

## 备选方案

不采用增加 ESP 任务栈、全局/TLS 暂存、隐藏堆分配或维持一套旧大栈入口。单独缩小 ESP 的 Schema/对话语义上限也不解决通用库的原样消费问题。对 Producer 只读形状验证采用同一个节点读取契约，避免为了检查而构造完整副本。

## 验证

实施中。容量和布局拒绝、输出保持、独立区域并发、正常编码/对话/调用回归、无堆符号检查及栈帧量测分别记录；尚未形成 ESP 实机栈、时延或存储验收证据。最终结果由本包 PR 提供。
