# ADR-0109：不可变正文复用与按会话确认清理

- **状态**：已接受并实施；本地验证和独立复查见[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-16-正文归属与按会话收尾精简)。暂不OTA。
- **日期**：2026-11-16
- **关联**：ADR-0104～0108；C-POLICY-012/013、C-SDK-009/011；计划§14.1。

## 背景

用户要求将输入到结束流程复查中提出的七项精简全部实施。仍有默认持久输入在等待中重复编码/暂存、检查点重复散列未变正文、历史索引另存输入与最终回答、模型封套复制完整消息、压缩完成重复投影、ESP为进度再次解码并长期保留模型提议，以及最终清理等待无关正文的问题。

## 决策

1. Session在支持stage/confirm的正文端口上只暂存输入一次；默认durable仍先confirm依赖图、保存根记录，再创建Goal。background仍可提前启动，但发布屏障不变。Core外部参数、权限及来源校验保持。
2. 策略私有Turn输入准入后不可变；SummaryProgress同时拥有候选文字及其引用，替换/清空文字时使引用失效。检查点直接复用未变引用，不再反复散列。冷读及公开存储边界仍验证完整引用、UTF-8和所有权；不缓存权限结论。已保存摘要直接成为记录摘要引用，不另存同一正文。
3. 新历史帧以偏移关联原始输入/最终答案引用，索引复用这些raw引用；工具结果仍使用其专用结果视图种类。保存或替换历史时清理关联，压缩后保留当前输入关联；不增加持久字段。请求封套和消息写入同一个Writer；压缩完成交给正常ready路径投影和预算决定，删除未使用的提前完整投影。
4. ESP网络worker在首次解析模型结果时只生成固定2048字节上限的安全工具进度，权威结果优先入队，进度尽力发送。只包含固定函数名、合法根binding_id及固定operation，不复制业务正文。Api::Job结束/复用清空进度；主owner只接收当前有效Call的进度。删除ModelTools的整份结果副本、二次解码及32节点旧门，保留通用每工具256节点和列表64项上限。
5. BodyCollection增加`collected(scope)`和不扫描全队列空闲的`progress`。异步适配器须提供前者；返回BUSY表示该scope已有释放尚未持久完成，错误按原分类传播。回调在owner线程调用、不可重入，端口活至Host join。FileBodies按有界owner槽保存释放凭据：共享正文等待包含该别名移除的manifest版本完成，最后owner等待正文块和manifest实际删除；冷manifest和临时引用释放同样不能绕过凭据。后续无关版本不延长已完成证明。
6. Session发布/隐私ACK只等待当前scope的真实清理证明；关闭仍用ready/idle排空全部借用和工作。sticky后台失败继续阻止成功。scope检查扫描有限descriptor，不把“已请求删除”当完成，也不改变物理执行、派发持久屏障或UNKNOWN不重试。
7. C ABI0.56、Core schema10、ATC3、ConversationRecord6、turn8、ANRV2和SQLite5保持，turn8中摘要引用的原字段顺序不变。C++端口调用方同仓库直接升级；无旧适配层、迁移、擦除或OTA。

## 后果与备选方案

按不可变属主保留引用，要求修改候选文字的入口统一失效，避免为省散列而引入陈旧引用。继续比较整份正文可以减少该约束，但会重复遍历，故选择集中修改入口并补正常计数验证。Frame关联只覆盖新写文字，不建立另一个长期全文缓存。

全局idle实现简单，却把别的scope工作混入当前ACK；单看删除已提交又不足以证明持久。选择在现有FileBodies内记录有界版本凭据，不另建清理worker或发布状态机。多个普通工具和单个存储worker的优先级串行机制不变。替换Host仍只改值端口，替换模型仍只改Provider/协议投影，Session不认识平台网络/数据库。

## 验证

定向正常Native、ASan/UBSan、Wi-Fi回归及ESP-IDF编译通过；计数和审查证据集中在上述记录。本轮未运行新故障/恢复/变异专项、CI、真实模型、设备或OTA；桌面计数不等于板端耗时、内存峰值或P95验收。
