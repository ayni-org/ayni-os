# ADR-0084：通用业务值、完整授权投影与开发期升级

- **状态**：已接受（用户 2026-10-29 确认类型、精度、授权范围和兼容规则）；AP-02 本包实现 ABI 0.48 / schema 4，验证与交付见下文。
- **日期**：2026-10-29。
- **关联**：ADR-0029、0045、0054、0082、0083；AP-02；[基础计划](../architecture/foundation-and-experiment-plan.md)、[AP-02 盘点与设计](../architecture/ap02-typed-capability-design.md)。

## 背景

现调用以有限授权字段加 text 表达业务输入，结果为文本或固定的工具提议列表。通用对象、列表与两种小数尚无共同表示。只为模型 codec 增加 JSON 支持，会留下原生输入、授权、Provider、持久和恢复之间的语义差异。

用户在确认“参数/结果属于已注册能力的调用接口”后，选择首版同时支持列表、嵌套对象和小数，并确认同时支持近似浮点与精确十进制；还选择开发期直接升级。对于列表授权和数值权限，用户进一步选择沿用完整授权逐项检查，以及权限数值只用整数/精确十进制。

## 决策

1. 首版采用有界、模型中立的业务 Schema 与值，包含对象/列表、整数、布尔、枚举/标识符、UTF-8 文本、有限浮点与精确十进制。不是完整 JSON Schema 或无界数据模型；所有层次和字节有上限。
2. 浮点表达近似值，decimal 表达声明精度的精确值；能力各自声明范围与精度，不隐式在两类间转换或对精确值舍入。实现设计采用 finite binary64 和固定 scale/I64 coefficient 的 decimal，边界及编码按公开契约冻结。
3. 规范化业务值是单一请求事实。默认值在授权前确定，从此值生成授权投影，Provider 执行与持久恢复消费同一规范值，不接受另一份调用者自报的 authority 影子输入。
4. 列表权限逐项由同一条完整授权覆盖：固定一个 requirement 及其 Grant 引用，全部元素检查通过才准入；越界或空授权列表整次拒绝。禁止逐项选不同 Grant 拼接、跨 Binding 暗投递或隐式跨列表配对。关联、跨列表及总量规则留待独立明确扩展。
5. 权限相关数值采用整数或精确 decimal 的显式单位/scale 投影；浮点不直接用于权限比较，不做取整/容差绕过。不能表达的投影在注册时拒绝，不隐藏在业务 text 中继续执行。
6. 授权来源及调用记录保留解释原权限、输入/结果所需的机器 Schema、投影、精度和 exact 契约证明；Grant/Goal 即使尚无 Call 也不能被当前目录重释，Task 沿原来源关联。保留原身份、Binding、派发屏障、UNKNOWN、查询与隐私擦除不变量；已擦除 Call 不补默认、不重建正文或再派发。
7. 本包开发期直接升级所有仓库内消费者。布局变化分别升级 ABI/存储版本，旧目录在新写入前明确拒绝并保留，不读旧格式、不做迁移器或清空。回退使用原二进制与原目录；历史 AP-00/AP-01 的例外不被推定为未来包的永久授权。
8. 本轮完成文档交付、基础/消费者盘点与可实施设计；不据此宣称生产实现、平台实验、付费模型或新专项已启动/通过。后续实现依本设计和工作流完成适用验证。

## 后果

同一能力的模型和原生调用能沿统一类型、授权与恢复路径演进。代价是公共 ABI、Call 记录/预算、模型副本、策略及全部消费者必须一并迁移；不能靠增加一个 JSON 字段完成。首版授权仍有明确边界，不支持总量或关系策略的能力不能冒充已获覆盖。

## 备选方案

- 先只做扁平字段：范围较小，用户已选择首版支持嵌套/列表和两种小数。
- 为每个 Provider 自行解析 JSON：复制规则并可能让授权值与执行值不同，不采纳。
- 列表各元素任选 Grant、空列表默认无权限需求：破坏完整覆盖或引入隐式副作用语义，不采纳。
- 一律使用 double：精确数值可能丢失，用户选择同时支持近似和精确类型。
- 继续读旧格式或提供迁移器：用户本包选择直接升级并保留原目录，不采纳。
