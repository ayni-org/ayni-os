# ADR-0086 Task 所有长操作与订阅的模型控制

- **状态**：已接受产品选择；AP-05 实施设计，尚未实现。
- **日期**：2026-10-30。
- **关联**：AP-05、D09/D07；计划 §2.2～2.4、§3.2/3.6、§9、§14；ADR-0045、0063、0084、0085；[实施设计与消费者盘点](../architecture/ap05-managed-operations-design.md)。

## 背景

AP-02/AP-03 已随 #112～#114 交付 typed 规范输入/结果、按需授权、固定四工具、标准消息和 Native 上下文/结果存储。Core 已有 action、Task 订阅、有限租约和事件驱动等待，但普通 action 一直占前台，GoalType 工具列表拒绝 subscription，ToolLoop 只等待业务终态。模型还不能取得受管引用后继续读取、等待或停止。

用户授权推进下一步并要求主动提出决策。2026-10-30 已分别确认本 ADR 的四项产品选择；技术方案复用原 Call、Task、授权、资源和来源属主。

## 决策

1. **控制入口（产品语义，用户选定推荐项）。** 保留现有四个固定模型工具；在 `ayni_call_capability` 内增加受管启动、读取/查询本地状态、等待、取消和关闭操作。引用只对原 Task 有效，不授予权限，也不交给下一轮 Task。原普通调用默认仍等待终态；具体封套和接口见实施设计。
2. **最终答复（产品语义，用户选定推荐项）。** 最终文字答复结束原 Task 并触发所属操作的取消/关闭收尾。需要继续工作的模型应显式等待；本包不增加阶段答复及后续输入回到存活 Task 的语义。Task 结束不证明 Provider 已停止，真实终态、effect、借用与资源隔离仍保留。
3. **兼容（产品语义，用户选定推荐项）。** AP-05 单独选择开发期直接升级所有仓库内消费者。公共布局/记录变化分别升级 ABI/schema；新写入前拒旧保留原目录，无旧 reader/迁移器；回退使用原二进制和原目录。AP-02/AP-03 的决定没有被当成本包的默认授权。
4. **并发范围（产品语义，用户选定推荐项）。** 首版每 Task 同时一个 action，可与模型分析及已有订阅并存；第二个 action 等原调用结束。Core 统一准入把排队、取消中及未解决 UNKNOWN 也计为占用，普通 invoke/Shell 不能绕过；已知终态后仍需完成借用归还和资源隔离处理。不引入多 action 并行或 join。
5. **状态属主（实施细则）。** 不新增平行操作表、权限目录或结果账本。Call 拥有受管模式、原执行身份、共同前后台归属与完成事实，Task 只持前台引用或 tagged wait，subscription 继续拥有特定的 desired/generation/lease。后台完成不得结束另一条前台模型调用；pending/UNKNOWN 继续阻止安全回收。
6. **等待（实施细则）。** 模型 wait 带回上次实际读取的前沿；owner 原子比较并登记，已变化则立即回复。复用 WAITING 和原生订阅唤醒属主；有限等待到期只结束这次等待，不自动取消原操作。同状态续租不唤醒，样本/进度保留最新，终态与取消可靠交付。
7. **授权与结果（沿用原契约）。** start 走规范业务参数、完整 Grant、资源和持久屏障；read 不是 owner 管理对账，cancel/close 只停止原操作。UNKNOWN 不重试、不换实现；subscription 的租约/代际、来源失效及物理能力的原执行保证不削弱。样本进入工具消息和模型上下文时补齐来源依赖，不把历史正文作为当前授权或新鲜度证明。
8. **验证范围。** 首版用可取消的软件 action 与现有 BOOL/I64 软件事件流贯通公开路径。保持已有正常/专项回归；变异与新增故障/恢复专项继续按 workflow 暂停，未验证事实单列。平台、硬件、付费模型和完整 MA-038 不属于本包。

## 后果

模型可以在同一 Task 内管理长操作及订阅，固定工具集合保持稳定。代价是公开策略接口、Call/Task 的前后台及等待关系、持久记录、工具消息配对和上下文来源都要一起迁移，不能只删除订阅 allowlist 的限制。直接升级降低迁移范围，但旧目录需要使用原版本打开。

最终答复收尾保持当前对话轮次边界；持续监控必须显式等待。后台操作仍占用声明的资源和完成容量，受原 Task 运行限制，不能用后台模式绕过 UNKNOWN、资源冲突或授权暂停。

## 备选方案

- 新增专用 start/read/wait/cancel/close 模型工具：语义直观，但改变固定四工具集合；用户选择扩展既有入口。
- 普通 Provider 回调 Core 实现控制：产生重入、线程和权限旁路，不采用。
- 所有长操作仍占 Task 前台到终态：无法在同 Task 中读取进度或提出取消，不满足 AP-05。
- 阶段文字答复后原 Task 继续：需要新的发布和后续输入规则；用户选择最终答复结束并收尾。
- 保留旧 reader/迁移器：增加历史状态验证矩阵；用户选择本包直接升级。

## 验证

本轮交付消费者盘点、接口/生命周期设计和用户决定；生产实现、ABI 0.50 / schema 6 保持。文档检查与交付证据在关联 PR 中记录；软件场景、公共接口/记录迁移及其执行证据随 AP-05 实现交付，不以本 ADR 宣称功能已通过。
