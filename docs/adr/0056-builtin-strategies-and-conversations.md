# ADR-0056：规则策略、ToolLoop 与有界对话

- **状态**：已接受
- **日期**：2026-10-26
- **关联**：MA-009，P1 PR 3；计划 §2.7、§3.3、§9.1；ADR-0024、0026、0042 决定 16、0054；C-POLICY-005～012

## 背景

Core 已有单调用决定、稳定步骤、持久 typed 结果和模型次数限制，但没有可装配的规则策略或 ToolLoop。现有检查点只接受同一写入策略的精确版本，不能显式声明兼容实现；也没有把已完成 Task 的对话结果交给外层存储的复制入口。

## 决策

1. **组件边界。** `strategies/builtin/` 只依赖公开 API，在配置期提供有限规则表或模型 Binding，使用 `ayni_register_strategy`。Core 不出现规则、提示词或 ToolLoop 分支。策略不分配、不阻塞、不做 I/O，只用当前快照；配置和对象由装配方保持到 Kernel 销毁，回调在同一拥有者线程顺序使用固定 scratch。（自 ADR-0073 起，ToolLoop 可选的非阻塞时钟端口是唯一例外，只改变主模型请求的正文；自 ADR-0074 起，模型请求正文把指令与对话数据分开。）
2. **规则。** 最多 8 条规则，每条以 GoalType ID/version 精确选择，含至多 16 个固定调用。步骤身份为 `name.vN`，语义/参数变化须使用新步骤版本。每次决定只请求首个未完成步骤；已完成结果由共同调用记录读取，不另存游标。已知失败结束本次任务；未知结果保持暂停，不发后续调用或补救。
3. **ToolLoop。** 模型步骤为 `round.N.model.v1`，工具为 `round.N.tool.I.v1`，不依赖策略实现版本、boot 或随机数。模型列表最多 8 项，先读完整列表并检查剩余步骤容量，再顺序请求一个工具；每个调用仍经 Kernel 的 Binding、授权、资源和派发屏障。全部成功才请求下一轮；未知或失败不自动重试。Task 模型上限及提高上限继续由 Core 管理，不另设可绕过的轮数计数。
4. **兼容声明，ABI 0.38。** `ayni_strategy_v1` 追加至多 4 个旧 writer ID 与闭区间版本声明。默认仍只接受精确的当前 ID/version；显式兼容不改变原步骤、调用身份或结果。注册复制声明；恢复只接受声明且容量足够的检查点，其余仍以 `STRATEGY_CHANGED` / `POLICY_OUTPUT_LIMIT` 保留并暂停。组件自己的便携编码也带版本，无法解码时停止。结构消费者统一重编译；schema 2 和既有持久记录布局不变。旧库不理解新增声明，回退时会按旧精确匹配规则暂停，不重置。
5. **对话范围（产品语义，用户 2026-10-26 选定推荐项）。** P1 交付 Core 外的有界对话值组件；P2 CLI 接文件持久化。`begin` 把明确的对话快照和当前用户输入编码为 Goal 参数，策略只读该参数/私有检查点。结果进入完成 Task 的检查点；新增 `ayni_copy_task_checkpoint` 只导出已 COMPLETED 且整个完成 transition 已持久的内容。可信装配方用 `finish` 取得候选，先保存成功，再替换旧对话。P1 的集成夹具显式模拟这次外层提交，不把它称为文件持久化。
6. **容量与摘要。** 每条用户输入和最终回答最多 384 UTF-8 字节，保留最近 3 轮，摘要最多 512 字节；完整编码上界实测小于既有 4096 字节 Goal 参数/检查点上限。满 3 轮时，当前 Task 先用文本模型 Binding 摘要旧摘要与最旧 2 轮，再继续本轮；摘要计入同一 Task 模型次数。摘要成功后先进入本次检查点候选，最终候选保存成功后外层才丢弃原轮次。摘要携带连续来源轮次范围，明确标为本对话内的未确认模型推断，不进入记忆或事实。提示词/工具轨迹缓冲 8192 字节，超限拒绝，不截断。
7. **删除与并发。** 对话由 `(id, owner_instance_id, generation, revision)` 标识；候选替换须与当前 generation/revision 匹配，同一基线只接受一个结果。整段删除产生无正文、无摘要/来源的新代际候选，保存后拒绝旧代际在途结果。调用方负责取消在途 Task；已外发请求不能撤回。这里清除的是外层对话值，Kernel 的 Goal 参数、调用行、检查点和历史日志不是该组件的所有物；它们的物理擦除与单轮删除仍随 P3 tombstone/lineage，不声称本 PR 已全盘擦除。
8. **更换实现。** 换模型只改 Provider/Binding 配置；换规则或 ToolLoop 实现只改注册、明确的兼容声明及对应私有格式 reader。业务步骤含义变化必须新版本，不把兼容声明当作重新执行许可。Native CLI、长期存储、真实硬件与新的故障/恢复专项不在本 PR。

## 后果

- 通用 ABI 仅增加检查点兼容声明与已完成检查点导出；Kernel arena 增量来自策略目录，不新增 Kernel 字段或业务状态机。
- 对话容量有意较小，超长输入/回答或工具轨迹明确拒绝。更大正文需要显式调整既有配置与组件版本，不静默截断。
- 外层存储若失败，旧对话完整保留；已完成 Task 的保留窗口仍受 Kernel 容量限制，P2 必须在回收前保存结果。
- 本次验证只覆盖正常顺序、公开边界和正常关闭后的兼容替换，不取代 E3 的故障验收。

## 备选方案

- 把对话作为新的 Core 持久实体：会扩展 P1 的业务持久化和删除范围；用户选定外层组件，文件接入留 P2。
- 只比较策略版本或忽略旧检查点：不能表达不同 ID 的显式兼容，或会静默重做，未采用。
- 把模型 JSON 留给策略：违背 ADR-0054，未采用。

## 验证

正常功能与边界测试覆盖双策略、摘要候选、完整删除、模型上限、检查点兼容与持久导出；执行结果和审查证据集中在 [#76](https://github.com/RobotSe7en/ayni/pull/76)。文件存储、新故障/恢复专项、ESP32 和完整 E1–E4 仍未验证。
