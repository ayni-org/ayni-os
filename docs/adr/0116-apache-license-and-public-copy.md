# ADR-0116：Apache-2.0 许可证与保留历史的公开副本

- **状态**：已接受（产品语义，用户选定）；用于首次公开复制。
- **日期**：2026-11-26
- **关联**：[主计划 §14](../ayni_v1.0.md#14-默认值与仍需用户决策的问题)、[LICENSE](../../LICENSE)、[第三方声明](../../THIRD_PARTY_NOTICES.md)。

## 背景

项目此前在私有仓库开发，主计划将 Apache-2.0 列为候选，许可证留待首次公开前决定。用户已将 `RobotSe7en` 添加为目标仓库协作者，并明确授权复制代码、保留提交历史，选择 Apache-2.0。

## 决策

1. 原创代码和文档采用 Apache License 2.0；根目录保留官方完整许可证、项目 NOTICE 与第三方许可入口。第三方作品的既有版权和许可证保持，不统一改标 Apache-2.0。
2. 将原 `main` 及其完整祖先提交复制到 `ayni-org/ayni-os`，以 `RobotSe7en` 推送，在原历史后追加许可证与公开入口文档提交；不改写既有提交 SHA、作者或合并关系。
3. 原 `RobotSe7en/ayni` 仓库保持独立且私有，不进行仓库转移；原开发分支不作为本次公开分支发布。PR、Issue、评论和 CI 运行记录不随 Git 推送迁移。历史引用继续指向其真实来源，并在中英文 README 标明访问原私有证据需要权限。
4. 复制使用独立工作副本；不纳入工作区未跟踪输出、构建产物、运行配置或设备数据。不改变 Core、ABI、存储格式、硬件和验收状态。

## 后果

公开仓库可按 Apache-2.0 复用原创部分，当前源码显式依赖与字体仍按各自许可分发。两个仓库后续独立演进，不自动同步；对新二进制或固件发布仍需按实际链接组件整理许可和验证证据。

## 备选方案

- 转移整个 GitHub 仓库：可保留 PR 等平台数据，但原账号不再保留独立旧仓库，用户未选择。
- 从当前快照重新初始化历史：公开记录较短，但无法在新仓库追查原提交，用户未选择。
- MIT 或继续不确定许可证：用户已明确选择 Apache-2.0。

## 验证

本次只改变许可证与公开入口文档。许可证原文、文档一致性、契约检查和历史包含关系的核对结果随[公开复制提交](https://github.com/ayni-org/ayni-os/commits/main/)保留；不新增编译、软件套件或硬件验收结论。历史 PR/CI 证据保存在原私有仓库，不作为新仓库已执行的 CI 记录。
