# ADR-0101：独立触屏应用入口、自动语音回复与电机启用

- 日期：2026-11-13。
- 状态：已接受（用户明确选择）；实施与正常验证见独立实验记录。
- 范围：`experiments/esp32_wifi_chat`；不改变 Core、C ABI0.54 或 schema9。
- 关联：ADR-0096、0097、0100；C-MEM-005、C-POLICY-004、C-STOP-006。

## 背景

用户要求触屏操作改成类似应用图标，进入各自配置；语音回复由按钮开启或关闭，开启后自动朗读最终模型答复，同时保留模型显式语音能力。用户明确选择保存开关状态；即使模型本轮已调用扬声器，最终文字仍自动朗读。此前不自动TTS的决定仅对此可选模式被取代。用户随后要求电机资源自动初始化，最终明确默认启用，覆盖讨论中先前的默认停用选择。（产品语义，用户选定）

## 决策

1. 主页为九个图标：聊天、语音回复、网络、模型、遥控器、电机、屏幕、状态、清理。按用户后续要求，子页采用统一深色卡片、圆角按钮及明确的字段分组，减少说明文字；开关与停止按钮独立呈现，错误详情仍可查看。图标与触区共用布局；子页提供返回。网络和模型配置继续使用原快照及正常重启流程，配置凭据不进入预览或日志。
2. 自动语音为独立UI偏好；旧设备缺少记录时关闭，用户开启后跨重启保留。偏好存入独立`ayni_ui/voice_reply`版本化NVS记录，原网络/模型settings v1/v2不重写。保存成功后发送带请求编号的模式设置；匹配的owner回执确认生效，旧回执不能覆盖新开关，新输入等待同步结束。
3. 最终答复先按原Session落盘并显示，再由独立`wifi.reply.voice` Goal朗读。复用内置Rules、`speaker.speak_text` v2、Grant、Core调用账本与原流式PCM/I2S，不额外请求模型，不修改通用提示。显式语音能力始终可用，自动开关仅控制应用的后续朗读。
4. 长答复按完整UTF-8字符分段，每段不超过原speaker的1024字节限额。Goal参数只存现有正文引用；本组合保留scope 0给这些暂存语音正文，其余会话/诊断/模型正文使用非零scope，避免去重后误删共享正文。分段Goal终止且其Task终态持久后才释放正文；准备中的异步写也先排空再清理。
5. 整条答复固定原Context id、owner、revision和generation。每段使用Agent Context，下一段还须核对原始基线及可用性；删除/撤权或版本变化时停止剩余段，不能把旧答复绑定到新清理的Context。关闭开关取消本次自动朗读；Goal取消受理不代表播放结束，须等待Provider/Task终态持久。失败保留已保存文字并明确说明，不自动重播、重交旧动作或伪造已听到声音。
6. 电机资源在组合时自动初始化，软件会话就绪后默认启用。普通停用可再次启用，独立停止或异常仍锁定至重启；状态消息由控制worker单写并保留待发送状态。普通停用推进本地nonce拒绝水位，重新启用不能复活停用前已发challenge的旧permit。限幅、Grant、Scene、PermitGate、心跳及停止事实保持，电机2沿用已选的反向映射。
7. 自动初始化和启用不等于实际转动或电源测量。已有复位失能/独立硬件超时未验证的边界保持；刷固件、重启或重连串口仍采用驱动断电条件。此次不增加运动、掉电、耐久、存储破坏或新的恢复专项。

## 兼容与替代方案

UI偏好独立于凭据快照，旧应用可忽略；Core日志和正文编码不变。新增语音GoalType/策略及部署容量仅属于此实验，旧应用缺失相应目录或容量时不能推定可继续该工作；新启动先取消保留的实验工作再开放策略，旧语音和物理调用不自动重放。回退还需识别相应电机极性版本，不把同ABI/schema等同于完整回退验收。

直接调用TTS/硬件会绕过现有授权、资源及取消账本；把自动语音塞进模型提示会增加请求并失去开关的确定性，因此均不采用。自动资源初始化替代手动“准备”，但独立停止不转换为可随意清除的普通停用。

## 验证

正常软件检查覆盖完整长答复、正文隔离、会话删除、缺授权、准备中/播放中/分段间关闭、异步停止终态、开关持久化、图标触区以及电机停用水位。独立只读审查及修复复查、ESP-IDF构建和实际部署边界见[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-13-应用图标自动语音与电机默认启用)。静态界面预览由同一绘图代码生成，不冒充设备截图；软件和正常启动不替代实际听感、轮轴方向、硬件停止链或恢复验收。
