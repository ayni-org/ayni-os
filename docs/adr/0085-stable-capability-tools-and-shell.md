# ADR-0085：固定能力工具、按需说明、连续上下文与显式 Shell

- **状态**：已接受范围（用户 2026-10-29）；AP-02 实现与 Shell Provider 见 [#112](https://github.com/RobotSe7en/ayni/pull/112)；AP-03 目录/按需绑定见 [#113](https://github.com/RobotSe7en/ayni/pull/113)；固定模型工具/连续上下文/部署见 [#114](https://github.com/RobotSe7en/ayni/pull/114)，验证见下文。
- **日期**：2026-10-29。
- **关联**：ADR-0073、0074、0083、0084；AP-02/AP-03；[基础计划](../architecture/foundation-and-experiment-plan.md)、[AP-02 设计](../architecture/ap02-typed-capability-design.md)。

## 背景

用户要求实施 AP-02、AP-03，并在出现产品问题时主动询问。逐项讨论确认目录披露、元数据外发与直接升级；随后明确 system prompt 提供能力摘要，模型按具体需求查看详细说明，模型侧继续采用普通 agent harness 的 OpenAI 兼容工具调用协议。每轮替换少数业务工具会改变请求前缀，不符合用户对多轮上下文缓存复用的要求。

当前模型 codec 只发送 system/user 文本、丢弃协议 tool-call ID，应用只保存用户输入和最终回答，并按固定三轮触发摘要。因此完整消息历史、协议身份和外层对话存储也属于本轮必要迁移。

## 决策

1. **目录披露（产品语义，用户选定推荐项）。** Agent/模型只可见 Task 策略允许且当前授权通过的能力；不提供未授权能力的公开摘要或申请目录。列举、查看、调用分别复核，不因已查看而授予权限。
2. **元数据外发（产品语义，用户选择）。** 当前获准目录的名称、摘要、说明与机器 Schema 可以随该模型目的地的调用授权外发，不新增独立元数据外发 Grant；这不改变私有记忆、媒体和业务正文的原有外发要求。
3. **固定工具（产品语义，用户明确修订并确认）。** system 前部提供稳定的工具说明与目录入口，获准能力摘要分页读取，完整定义按需查看。工具名统一保留 `ayni_` 前缀：`ayni_list_capabilities`、`ayni_inspect_capability`、`ayni_call_capability`、`ayni_shell`。Shell 直接暴露；其他扩展能力经固定调用入口进入同一 Core 调用链。取消“每轮最多八个业务工具窗口”的产品方案，目录、消息、正文和单响应提议分别受显式资源预算约束。
4. **标准消息与缓存（产品语义，用户确认）。** 使用 OpenAI 兼容 Chat Completions 的 function tools、assistant tool_calls 和带 tool_call_id 的 tool 消息。协议 ID 与 Ayni Call/operation/attempt 身份分开。工具定义和顺序稳定，详情与结果追加到历史；动态时间不改写最前部固定指令。删除、撤权、目录变更及压缩建立新的上下文版本，权限有效性优先于缓存复用。
5. **上下文压缩（产品语义，用户 2026-10-30 修订）。** 按 token 预算压缩，输入预算为部署明确配置的模型窗口减去输出预留；75% 触发，50% 为目标。此前沿用 8192 B 输入缓冲作为上下文预算的表述混淆了两类资源，按本决策纠正。固定工具和消息开销计入模型统计；字节容量只约束单次工作缓冲、队列和记录，不限制长期历史总量。优先保存最新完整工具往返，压缩更早的完整历史；保护内容使 50% 不可达时不强制拆组。摘要失败保留原文，不静默截断。
6. **显式完整 Shell（产品语义，用户选定推荐项）。** Native 软件 Provider 支持完整 shell 脚本与管道，部署明确授予该能力；固定启动目录、有限超时、输出和并发预算。启动目录不是文件系统沙箱；能力继承宿主用户的 OS 权限，不把普通进程组取消描述成任意原生代码隔离。任意脚本可能外发、计费和产生副作用，契约须如实声明；不分析脚本文本后假装证明副作用为零。不开启 Shell 的部署不要求该后端。
7. **所有权与执行。** backend/Provider 拥有枚举、进程、管道、线程和具体 I/O；catalog/authority/work 保持目录、权限、规范值和 Call 事实。固定调用入口不能注册一个回调 Core 的普通 Provider 作为旁路，不能通过 worker 查询 Core，不能把 JSON 数字先转成 double 后声称十进制精确。
8. **兼容（产品语义，用户选定推荐项）。** AP-02 和 AP-03 分别直接升级所有受影响消费者，ABI、存储与外层对话格式分别演进。新二进制在写入前拒绝旧格式，保留旧目录；无旧 reader/迁移器。回退使用原二进制与原目录，不清空数据。
9. **按需绑定（产品语义，用户 2026-10-30 选定推荐项）。** 未授权的可选工具不阻塞 Task 对话；目录随当前授权变化。实际调用时选一条完整 Grant 覆盖整次规范请求，与 Call 接受同批持久绑定。已使用授权撤销/到期仍暂停 Task，不因另一条当前可用 Grant 自动替换。原必需 Goal requirement 保持原语义；已绑定工具的重新授权须保留原上限及精确 Binding 选择。
10. **按需绑定实现边界（实施细则，2026-10-30）。** Goal 冻结最多 256 项 Binding ID/version/role，Call 留首次 Grant 与精确实现，Task 留 source Call/当前 Grant；原 Grant 的整份 Scope 为显式重新授权上界，Task 可安全退役前原/现引用均不可回收。沿用 GOAL_REAUTHORIZE 的完整 direct-live cohort 原子事务，CAS 保护原 Goal 创建/授权代际，作用于应用时当前 cohort，不是工具集合快照 CAS；管理接口可查已用来源。原父 requirement Scope 限制保持，可选列表额外向下收窄。说明由可信配置明确采纳至 catalog，不通过普通 Provider 回调 Core。目录和说明有界并可超过八项；分页对工作/持久前缀、Gate 或到期变化明确失效。第一部分沿用旧模型传输；第二部分再接固定四工具、标准消息和预算压缩，不以目录 API 代替模型闭环。
11. **system 预算（产品语义，用户 2026-10-30 选定推荐项）。** system 保留稳定的四个工具说明和目录入口，获准能力摘要经按需分页读取；目录增长不要求把全部摘要放入 system，模型上下文预算遵循决策 5 的 token 规则，不再使用 8192 B 作为模型窗口。此补充细化决策 3 的 system 内容；列举/检查/调用仍各自复核当前权限。
12. **实施及交付（用户授权）。** 本轮完成 AP-02/AP-03 与必要的 Shell、消息/上下文迁移，按完整功能提交 draft PR；独立审查、修复后复审，通过且最终适用 CI 全绿后由实施代理 merge commit。平台、硬件、付费服务及新故障/恢复和变异专项不由本次实现自动启动；现有相关回归保持。

13. **Native 历史存储（产品语义，用户 2026-10-30）。** 采用 SQLite 按消息追加、事务提交和分页读取；完整长期历史由 Runtime/Host 管理，Core 继续使用原日志与快照机制。工作状态引用上下文数据，不把整个会话历史反复写入 Goal 参数和 Task checkpoint。SQLite 版本与 Core 存储版本分开；仍遵循决策 8 的直接升级和旧目录保留边界。
14. **超限业务结果（产品语义，用户 2026-10-30）。** 完整原始结果留在 SQLite；超过可用上下文时按块摘要，tool 消息保持真实 outcome/effect 和结果引用，明确标注正文为未确认摘要。摘要失败保留原文并暂停，不把已知完成的执行改成失败或 UNKNOWN。完整能力 Schema 超限明确容量拒绝，不摘要替代；目录以完整条目缩小页长。
15. **token 统计范围（用户 2026-10-30 收窄并补充）。** 首版使用 Chat Completions；优先采用返回的 `usage`。预检或缺少有效统计时，对待发消息、固定工具及其 JSON 结构按 Unicode 字符数 × 0.75 向上取整估算，明确与服务统计分开。历史前缀未改写时，使用最近一次服务端 input_tokens 加新增字符的估值；压缩、删除及重建清除该锚点。估算不保证匹配各模型 tokenizer，服务拒绝超窗时保留原文并暂停。不引入本地 tokenizer、多厂商适配或 Responses 计数端点；不把 UTF-8 字节数冒充 token。

## 后果

能力详情不占据每轮原生工具定义；模型侧使用标准 function calling，Core 仍拥有类型、授权和派发的决定权。代价是必须迁移模型提议、标准消息历史、外层对话存储和上下文预算，不能只更改工具展示名称。Shell 是明确授予广泛 OS 执行权的能力，不作为低权限沙箱宣传。

## 备选方案

- 每轮切换八项或十六项业务工具：用户要求稳定前缀和按需查看，不采用。
- 查看后动态加入原生工具定义：会改变工具前缀；用户选择固定受管调用入口。
- 披露未授权能力摘要、另外申请元数据外发权限：用户分别选择仅获准可见和随模型授权外发。
- Shell 只允许预注册命令或强制 OS 沙箱：用户本轮选择显式授权的完整 shell。
