# ADR-0103：运行期复用不可变准入并接收多工具批次

- **状态**：已接受（用户2026-11-14要求实现、提交推送）；正常OTA及合成实测完成，本地流程仍为秒级，见实验记录。
- **日期**：2026-11-14。
- **关联**：ADR-0084、0086、0090、0102；C-CALL-001、C-AUTH-017、C-PERMIT-002/005、C-STOP-006。

## 背景

上一轮消除正常日志查重及空闲空间遍历后，用户真实回合从接受到保存答案为52.299秒；扣除模型12.896秒及电机输出1.605秒，仍有37.798秒本地流程。单次step最长1.073秒，4毫秒协作预算不能中断内部长工作项。原始脱敏日志在忽略的本机build目录，属于仓库外证据。

运行期多处再次完整校验、规范重编码同一不可变机器契约；执行门轮询又重复解码输入和逐行Scene投影。Schema临时对象无论实际节点多少都初始化、复制最大容量。ESP请求还显式携带`parallel_tool_calls:false`，而共享解析器和ToolLoop本来已能接收并串行执行至多8个工具。

## 决策

1. **边界完整验证，内部读取已准入字节。** catalog关闭及外部/恢复入口继续完整验证原域、Schema、默认值、规范编码和投影。CallRuntime只对自身catalog/Call拥有、已完成上述验证且未变的proof使用内部快速读取；共享同一布局reader，不建立常驻缓存、第二份契约或新的Kernel状态。实际新输入及Provider结果仍按原Schema验证/规范化，授权、资源及派发持久屏障不省略。
2. **静态输入复用与动态执行门分开。** prepare仍逐项检查整个输入的Scene范围，保存本boot的Scene代际和观察依赖。输入在调用期间不可修改；清除输入有显式content_erased状态。后续门检查拒绝内容清除、已停止、旧boot或owner变化，并检查Scene启用、配置精确匹配、版本、持久边界、原代际及当前观察。disable/re-enable、重启、撤权和观察过期不能复活旧动作；停止不等待日志准入。
3. **Schema只处理活动前缀。** reader逐项初始化已发布节点及默认值表，复制仅覆盖有效节点、选项和默认值前缀，随后重定位内部指针。view不暴露未使用尾部；失败仍不发布候选，工作区释放仍清除完整临时对象。容量、内存需求及ABI布局不变。
4. **接收批次，沿用串行策略。** ESP移除单工具输出限制；服务是否返回多个工具由其协议/模型决定。收到完整批次后ToolLoop按原顺序处理，普通前台工具等当前结果后再开始下一项，整批完成才请求下一模型轮。未知结果阻断后续动作；每Task同时一个action、资源冲突和受管操作语义沿用ADR-0086，不新增并行执行。

## 取舍与兼容

快速读取的前提来自原所有者的完整准入，不是对任意外部proof的信任开关；没有public ABI入口可以选择跳过验证。若未来允许运行期修改Schema或调用输入，必须先重新定义失效和准入规则，不能沿用此路径。替换Provider或Host仍在原边界完整校验，便携Core不依赖ESP或模型供应商。

ABI0.54、schema9、已有记录布局及持久/未知结果规则不变。此修改降低重复工作，不把协作预算改称硬实时截止，也不以桌面测量推定板端或硬件停止时限。

## 验证

正常软件回归、固件编译、机制测量及独立审查的实际结果见[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-14-运行期准入复用与多工具批次)。用户随后明确同意正常OTA及现有无模型/无电机合成回合：d754ca4正常启动并自确认；同一12字符回合由5677 ms降至4732 ms，Core累计4437→3299 ms，最长step仍602944 us。秒级本地交接和毫秒级响应目标尚未解决；桌面48倍门检查收益不代表整回合提速。没有云端模型、真实电机/语音或新的故障、掉电、恢复、耐久专项；真实37.798秒动作回合到新版本的变化尚未验证。
