# ADR-0105：共享对话主路径与本地重复工作

- **状态**：已按用户要求实施共享修正；正常软件检查、ESP编译和91c0c65-localreuse正常OTA/启动自确认通过；两次当前历史本地诊断与收尾通过；秒级冷/暖单步及100 ms目标仍未解决，用户要求先提交推送、明天继续。
- **日期**：2026-11-15。
- **关联**：ADR-0100、0103、0104；C-POLICY-013、C-HVAL-005/007/009。

## 背景

真实回合答案保存前51.974秒，其中扣除模型API worker和电机PWM区间后的本地流程28.316秒；首个模型派发前17.022秒。既有共享正文/增量提交没有消除所有读取重复：ESP新输入前全量trim缓存；ToolLoop冷读途中NOT_READY导致再次投影前面结果；展示最新答案仍取全部轮次。用户要求直接简化共用路径并同步契约。

## 决策

1. 输入引用→模型→按序工具→结果引用→模型最终答案→Session保存/发布是同一主路径。沿用原ToolLoop和Core状态机，不加第二套流程管理或平台专用执行捷径。
2. 共享历史读者复用同一索引/依赖读取逻辑，依赖就绪后再投影原Schema。已有格式、摘要与所有权检查保留，NOT_READY不暴露半份输出；活动回合复用解码状态；同一个cached_turns总额度内每会话最多保留最近完成的一份图。下一Task以owner、代际/上下文版本和完整引用匹配，仍验证当前正文所有权/摘要后复用历史与round派生表示，避免再次机器Schema投影。取消/失败的工作副本退休，隐私进度清除全部私有缓存；cached_turns计数包括这份完成图，布局和存储格式不变。
3. Session一次请求候选图的所有confirm，NOT_READY只推迟完成，不推迟其他依赖的请求；FileBodies仍每次一个后台4 KiB借用，最终正文/manifest→外层文件→Core ACK持久屏障不变。
4. 共用latest_answer读取轮次索引及最新答案，Native/ESP展示改用它；完整rounds接口继续服务历史查询。轮次布局只有一个元数据reader，格式和ABI0.55/schema10不变。
5. ESP移除新回合的强制全缓存trim及对应准备状态，沿用共享FileBodies正数预算/自动清退和Session统一后台推进。配置预算不变，未保存正文仍不可清退。
6. ESP本地诊断可在隔离scope中只读当前历史并走原ToolLoop本地模板结果；不保存到真实会话、不请求云端、不运行工具。修正append_group漏计，数值计时不输出正文/密钥。

## 后果与备选方案

冷读多一次轻量依赖遍历，换取避免反复的机器契约解码、规范化与临时区清零；没有新增缓存管理器或扩大缓存槽数；最近完成图复用原工作集槽。缓存预算在共用存储属主中执行，消费者不为每个输入清空它。只移除校验会失去外部存储/原结果解释边界，另建简化运行器会重复生命周期和授权机制，均不采用。API worker时段包含本地编码，Core/存储累计墙钟存在重叠，不能相加为端到端时间。

## 验证

正常异步冷读回归验证历史完整、依赖等待时不提前投影、失败前输出不变；最新答案检查只读索引与选中答案。既有策略流程及ASan/UBSan、共享Session/真实FileBodies/LittleFS RAM NOR的连续正常回合与关闭用于验证；具体已执行结果与部署限制记入[实验记录](../../experiments/esp32_wifi_chat/WIFI.md)。不以桌面结果声明板端P95或长期稳定性，新格式异常恢复仍未验证。
