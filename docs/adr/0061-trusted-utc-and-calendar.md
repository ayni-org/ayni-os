# ADR-0061：可信 UTC、日历规则与稳定发生时刻

- **状态**：已接受
- **日期**：2026-10-27
- **关联**：P4 / MA-011B；ADR-0019、0026、0038、0059；C-TIME-001～008、C-PROD-018

## 背景

已有延时与周期触发只使用单调时钟，不能表达本地日历时间。新增 UTC 必须保持租期、超时和既有触发的单调语义；校时、夏令时和停止期间错过的提醒需要稳定身份与持久游标。

## 决策

1. **用户选择。** 采用 POSIX TZ 规则串，支持夏令时。周期错过多个时刻时合并为一个 Task，标最近一次计划时刻并记录合并次数；权限暂停后的显式重新授权跳过周期积压，单次仍保留。重新授权时 UTC 不可信的周期目标返回 NOT_READY/TIME_UNTRUSTED，取得可信时间后由管理者显式重试，不先恢复再扩大跳过窗口。（产品语义，用户选定推荐项，2026-10-27。）同轮已确认的 Task 所有订阅与 Mock 媒体由 MA-008B 交付。
2. **时钟端口。** Host 可选非阻塞 `utc_now` 返回时间及可信状态；未提供、不可信或越界时日历等待校时。Native Linux 读取系统墙钟与内核校时状态，不以日期看似合理推定可信；Sim UTC 与单调时间分开注入。Kernel 每个 step 使用固定 UTC/单调前沿；存在活日历 Goal 时至少每秒请求重新 step，校时不重写单调期限。
3. **规则边界。** 单次、每日、每周各为独立 trigger kind。规则保存显式首个本地 Gregorian 时刻、规则版本和至多 128 字节 POSIX TZ；支持 1970～9999 年范围。每周沿首个时刻的星期重复。TZ 支持标准/夏令时名称、时分秒偏移、显式 M/J/n 转换日和有界转换时刻；拒绝 IANA 路径、冒号形式及省略转换规则的 DST，避免宿主默认规则使 Core 行为不同。语法依据 [POSIX TZ](https://pubs.opengroup.org/onlinepubs/9799919799/basedefs/V1_chap08.html)，不调用 libc 全局 TZ/mktime。
4. **发生身份。** Goal 内的顺序计数继续作为兼容查询；稳定日历身份由 Goal ID、不可变规则版本和计划本地 civil 秒组成。Task 同时保存计划本地键和解析后的 UTC。重复小时选择第一次发生；缺失时刻移到缺口后的首个有效瞬间。已消费本地键单调递增，回拨不能重复，跨多日用有界算术合并。
5. **状态归属与持久化。** `work/goal/CalendarTable` 持有每个 Goal 的规则、最后消费的本地/UTC 时刻及计数；GoalTable 持有生命周期与单调调度投影。易失 pending 只记录本次待消费前沿首次可调度的单调时间，校时不重置容量等待上限，消费/退役清除。`calendar_store` 遵循 PersistentStore，记录、预算、快照和恢复共用一个值 codec；规则/游标、Goal 状态、Task 创建和初始授权位于同一 transition。
6. **兼容。** ABI 0.41 只接受当前布局；schema 仍为 2。Calendar Goal 用 REQUIRED type3/v9～v12，游标为 REQUIRED type27/v1；日历 Task 的 type5/v3/v4 保留计划本地/UTC。旧 reader 在使用新日历工作前明确拒绝并保留目录。无日历工作保持原有存储读取路径，不新增旧数据迁移工具。
7. **变化场景。** 新 Host 实现 UTC 采样与可信报告即可复用全部日历规则；替换 Provider 不改变日历表与 occurrence 身份。时区规则变更通过新 Goal 表达，已有 Goal 不随系统时区设置改变。

## 后果

每个 Goal 的有界日历槽与新命令上限增加 arena 和批次预算，交付前量测。秒级 UTC 端口与轮询不承诺实时提醒截止。Host 校时状态不满足时提醒明确等待，开发者不能以默认当前日期绕过。

## 备选方案

- 每 86,400 秒运行：不能保留本地日历时间与夏令时语义。
- Core 使用进程 TZ：会耦合多个 Kernel/线程及平台规则库。
- 仅持久序号：回拨及规则恢复后无法证明具体计划时刻。
- 未校时时先重新授权、后丢全部积压：可能丢弃重新授权后本应执行的提醒，用户未选。

## 验证

正常模块与公开 ABI 场景、现有完整 Native 单元套件和公共 C99/C++ 头/layout 编译通过，独立审查发现已处理并复查；arena 增量已量测。最终命令、结果、CI 与资源数字集中在对应 PR。未执行新增故障/恢复专项，不声明完整 E1–E4、通知实际呈现、ESP32 或 Core Alpha 已验收。
