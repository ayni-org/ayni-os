# ADR-0083：通用 AgentOS 基础先于平台实验

- **状态**：已接受（产品定位与实施顺序，用户 2026-10-29 明确指示）。
- **日期**：2026-10-29。
- **关联**：计划 §0、§1、§6、§9～§15；ADR-0005、0008、0010、0080～0082；AP-02～AP-11。

## 背景

原实施路线将 AgentOS 通用机制与 ESP32-S3 轮式助理的语音、视觉、运动、停止链及用户试用串在一条发布路径中，容易将实验设备能力当作宿主或 Ayni 本身的必需功能。

用户明确 Ayni 提供通用原生 AgentOS，不要求宿主具备特定设备或能力；ESP32-S3 和外设只是实验，用于验证 Ayni。用户要求先明确并完成基础通用能力实施计划，再开展 ESP32-S3、Linux 系统等实验，并同步相关文档。

## 决策

1. 以[基础通用能力实施与平台实验计划](../architecture/foundation-and-experiment-plan.md)统一当前范围、依赖和完成条件。保留 AP/MA 编号与 M0/M1 已交付记录，原 M2～M6 的设备产品顺序不再作为所有部署的必经路线。
2. 基础包括生命周期、工作调度、授权、资源、调用、持久恢复、记忆/上下文，以及 AP-02 typed 输入/结果、AP-03 注册发现、AP-04 多实例验证、AP-05 长操作/订阅、AP-06 SDK/扩展/应用复用。先验证现有机制，只在真实缺口需要时演进；助理保持应用样例定位。
3. 基础以 Native/Sim、纯软件能力和确定性夹具开发验证，不要求语音、视觉、运动或物理设备。现有 CI 与回归持续执行，不因实验后置而停止。
4. 基础门槛通过后，再独立开展 ESP32-S3、Linux 系统及其他平台实验。Linux 实际 OS 集成实验与当前 Linux Native 构建/单测证据分开，不依赖 ESP32、机器人或 ROS；平台实验也不互为前置。
5. 语音、视觉、运动、外部协议与 peer 按需选择。通用取消、超时、撤权、关闭和 UNKNOWN 保证保持；现有物理许可、联锁、停止及结果契约约束实际声明这类能力的部署，不要求无执行器宿主装配硬件停止链。
6. 不改写已接受 ADR 或历史实验结果，不删除实现、放宽启用能力的合同或宣称新平台已验证。具体设备、OTA、耐久和试用门槛继续约束对应支持/发布声明，不作为所有 Ayni 部署的门槛。
7. 本次授权为规划与文档修改。基础接口和兼容决定按包明确，后续代码、平台/硬件、付费服务及新故障/恢复或变异活动不由本 ADR 自动启动。

## 后果

基础能力有独立可判定的交付范围，平台与设备实验检验其可移植性和扩展性。缺少可选设备不会阻塞通用系统完成；声明支持某平台或物理执行时，仍必须提供对应证据。代价是分别维护通用基础与所选实验的配置、版本及未验证边界。

## 备选方案

- 延续 ESP32 轮式产品作为所有平台发布的前提：将设备实验与系统能力耦合，不符合用户定位。
- 只更名工作包而保留原阶段依赖：Linux 仍可能被 ESP32/ROS 验收阻塞，无法表达本次顺序。
- 因定位调整删除控制/停止机制：超出本次文档范围，并会破坏已声明执行能力的保证，不采纳。

## 验证

两位子智能体交叉核对主计划、能力架构与现行实施/实验计划，相关范围、依赖和完成条件已统一；契约、diff、相对路径及标题锚点检查通过，架构图通过 XML 解析、渲染与目视检查。交付与适用 CI 证据见 [#110](https://github.com/RobotSe7en/ayni/pull/110)。本次仅修改文档，不提供新代码实现、平台运行或实验通过的证据；历史 Native/Sim、硬件未验证及覆盖偏差保持原范围。
