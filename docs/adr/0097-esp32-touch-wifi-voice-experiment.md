# ADR-0097：独立 ESP32 触屏 Wi-Fi 语音实验

- **状态**：已接受实验范围；完整实机验收未完成。
- **日期**：2026-11-07。
- **关联**：ADR-0083、ADR-0092、ADR-0095、ADR-0096；[实验说明](../../experiments/esp32_wifi_chat/WIFI.md)。

## 背景

原独立 USB 实验由 Mac 窗口负责输入、模型转发、中文排版和系统朗读。用户要求改用已部署的 Qwen3 ASR/TTS API，并使用 RC003-MS 语音输入；随后明确选择日常在触屏操作、ESP32 经 Wi-Fi 调 API，同时增加便于粘贴长 Key 的 Web 配置。

## 决策

1. 在独立实验中增加 Wi-Fi 运行配置，复用 Core、会话、ToolLoop 和现有屏幕/扬声器 Provider；不修改通用 Core、公开 ABI 或 Core 存储格式。原 USB 配置最初保留回退，后被下述用户决定替代。
2. 触屏和局域网 Web 共用完整配置快照，模型配置在一个开机期间冻结；保存后正常关闭并重启。Web 不回显保存的凭据。用户选择语音 API 使用局域网 HTTP 无密钥，Web 设置也无需验证码（产品语义，用户明确选定，2026-11-07）。模型出站仍为 HTTPS。
3. 遥控器须显式选择候选并完成加密和语音格式协商。松键后自动 ASR，再通过既有 USER 入口提交（产品语义，用户选定，2026-11-07）；输入声音或设备名称不授予执行权限。
4. 原始录音只在有限 PSRAM 暂存，取消及连接撤销有独立代次；不积压旧输入、不自动重试副作用或模型请求。TTS 最初请求完整的 16 kHz PCM WAV；后被下述流式决定替代，成功仍须真实 I²S 排空。
5. 最初本轮不连接电机、Wi-Fi 不开放运动；后续迁移范围见下述决定。旧台架例外和通用停止契约不变；本包不启动新掉电、耐久、变异或故障/恢复专项。
6. 新配置分区只使用旧空隙，扩展应用不跨入 Ayni 卷；部署前保存现有应用/表并检查新增区域。旧 Core schema 不迁移或自动擦除。

2026-11-08 补充的实例数据决定：实机现有 Host 日志被拒绝后，用户明确授权“清空重建”且声明旧会话不需要，仅重建该设备的 Ayni 卷并保留独立配置；没有增加自动擦卷或旧格式迁移。

2026-11-08 后续产品决定：用户明确删除 USB 版本，继续复用内置 ToolLoop；普通直接回答只请求一次模型，最初采用应用显示并自动朗读，后被下述通用能力决定替代。窗口满时允许原有额外摘要，预算改为128K；大请求经BodyRef传递，原历史编码保留。上下文硬件峰值/耐久另行验证。当前工程为 experiments/esp32_wifi_chat，原第1项的USB回退已由本决定替代。

2026-11-08 电机范围澄清：用户要求电机移植到 Wi-Fi 实验，删除的是 USB 端。保留原 PHYSICAL/Scene/Grant/PermitGate/worker，将准备与停止移到触屏。用户随后明确取消逐动作人工确认、单次最大持续1分钟；又明确普通聊天和设备操作应是同一对话，由模型决定直接回答或调用工具，并接受按需发现。最终实现只有一个内置ToolLoop/GoalType/历史/USER入口，没有模式切换；直接文字一次请求结束，设备操作走原发现/检查/调用流程，最终文字由应用显示聊天记录，语音由模型按用户需求调用能力。停止不依赖队列空位，初始化失败和停止锁定后须重启；独立停止链未验收边界保持，新实验电机能力v2区别于原v1人工逐次批准；60秒累计PWM由有限RMT批次与PCNT溢出累加支持，许可上限65秒，旧电机卷完整兼容未验收，本轮电机未连接，不执行运动。

2026-11-08最终提示词决定：用户要求系统提示通用、屏幕与扬声器也由模型根据输入选择调用，移除硬件/媒介指令和最终回答自动TTS代码；默认文字仍显示聊天记录。保留一个真正的ToolLoop和公开能力目录，不修改Core。Wi-Fi亮度问题查回此前仓库外已验收的PS_NONE三点策略，完整移植的目测结果另记实验说明，不从配置读回推定物理亮度已修复。

2026-11-08 流式语音决定：用户要求 TTS 边生成、ESP32 边接收边播放，减少首声等待。在同一实验能力内增加 AYTS/1 原生24 kHz PCM 传输，复用既有 MLX 单 Broker 与同一个公开 speaker Provider；不改变 Core、业务输入或能力结果分类。完整 WAV API 保留给旧消费者。流式成功同时要求协议显式成功终帧、HTTP完整结束及I²S排空；中途生成、网络或播放失败可已产生部分声音，沿用 RESULT_UNKNOWN 且不自动重试。协议/资源/当前证据见[实验说明](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-08-流式-tts)，当前主观硬件验收仍待确认。

当前流式实现的音频上限为300秒，调用期限330秒，使用固定64 KiB环形缓冲和有界背压；`speaker.speech`及其Binding版本为2，避免用旧声明解释新调用，提示音和Core版本保持原值。ASR录音继续使用独立的30秒上限；本次提交不包含仓库外服务代码或新的实机验收。

2026-11-09 任务清理决定：用户在任务创建容量不足后要求清理入口，并明确允许重建任务和会话（产品语义，用户明确选定）。主页“清理”区分仅清对话和确认重建。后者先由 owner 停止输出，API 代次取消并等待在途正文借用结束，再调用公开 shutdown；确认 Core、设备 worker 及 Host 存储关闭后，后台只擦除既有 `ayni` 数据分区，成功后重启。标签、地址和大小必须同时匹配既有布局；Wi-Fi、模型 Key、遥控器配对、应用和资源分区保留。关闭或擦除失败明确报告，不自动重试或在启动时自动擦卷；未知动作不重放。此操作明确放弃该实验的全部任务/调用/会话记录，不改变 Core 的未知结果保护语义，也不作为通用恢复保证。

## 后果

日常无需运行 Mac 窗口或 USB 桥接，Mac 仍须运行模型 API。代价是增加板端触摸、字体、BLE、网络工作线程和配置生命周期；媒体压缩暂存、字体块压缩和按真实响应长度分配用于保持有界内存。

## 备选方案

继续 USB 桥接不能满足独立触屏操作。把语音模型搬到 ESP32 不符合当前硬件资源；更换 API 服务器由端点配置解决，不把模型推理放入 Core。HTTPS 语音和 Web 验证码未作为首版默认，遵循用户本次局域网选择。

## 验证

独立适配器正常检查、固件编译和写入校验、修复后的启动观察及仓库外语音服务往返已执行；实机触屏、配网、Web 保存重启、RC003-MS 收音/松键转写已验证，用户确认模型回复及 TTS 正常交互成功，见实验说明。最终通用提示/设备能力版经用户确认识别、模型扬声器调用、执行步骤正常；额外RF唤醒引用加入后空闲及处理/播放时亮度稳定。未取得电气/耐久测量，128K峰值、60秒带电电机及独立停止链未验收；尚无本包PR/CI或硬件完整验收结论。

2026-11-09触屏重建已实际完成：关闭后擦除成功、自动重启、任务容量释放、配置保留和遥控器重连由脱敏元数据确认，随后新会话请求与回答保存完成。正常检查及独立停止/隐私审查已通过，见[#130](https://github.com/RobotSe7en/ayni/pull/130)；不据此声明掉电恢复或长语音听感验收。

同日扬声器调用方式已澄清：模型此前用受管start调用UNARY而被拒；能力说明补充invoke约束后，新会话直接invoke，实机完整播放58.16秒音频且正常收尾，用户确认正常。Core/ToolLoop、通用提示及能力机器契约保持不变；完整300秒和耐久仍未验证，证据见同一[#130](https://github.com/RobotSe7en/ayni/pull/130)。
