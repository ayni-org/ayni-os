# ADR-0068：正常集成夹具、编译数据与脱敏轨迹

- **状态**：已接受；实现与验证进行中
- **日期**：2026-10-27
- **关联**：P6；MA-021、022、023、033；ADR-0012、0067；计划 §10.1～10.5

## 背景

P1～P5 的能力已有正常功能测试和公开示例，尚缺可以按独立编号重放的跨能力证据。M0 的完整夹具格式仍是未实现草案；其中的故障与恢复动作不因正常集成而自动恢复。领域事实仍由同一 Core 持有，夹具不能自行修补内部状态或用日志代替实际副作用计数。

## 决策

1. **独立正常 profile。** `fixture_schema=1` 与 `profile=m1-normal` 共同确定本轮格式，使用 E1-N1 等新编号；不复用原完整用例 ID。闭合的 typed 动作/断言由 JSON 在构建时生成只读 C++ 表，生成器复用契约与计划步骤解析，拒绝未知字段、重复键、错误引用、无界数值及未实现动作。原完整 schema 0 草案继续保留，故障/恢复矩阵仍未验证。
2. **职责。** `applications/normal_fixtures` 持有测试工作流、稳定步骤及检查点语义；`runtime/sim_node` 组装独立 SimNode、可复用 Mock A/B/订阅、计数器及模拟呈现器，推进假时钟并收集公开查询结果。CLI 和 GoogleTest 只调用同一执行函数。Core、C ABI 0.45 与 schema 2 不变；没有 Core 私有头、存储字节修补或测试框架进入运行时。
3. **有界与可复现。** 每个等待、step 数、输入及产物量都有上限；profile 内没有随机调度，seed 固定为 0。模型延迟由假时钟驱动，采样沿用 Mock 的正常节拍；不使用墙钟等待控制逻辑。每例重复运行两次，比较完整逻辑轨迹。原生工具链与固件编译仍按工作流验证，不从本轮推为 ESP32 运行或真实时限证据。
4. **本地响应性（产品语义，用户选定推荐项，2026-10-27）。** 计入正常持久提交推进后，本地事件实测为 30 次 step / 模拟 30 ms。用户选定本轮验证“模型等待不阻塞本地工作”并记录总步数；用例在本地任务完成时即时断言等待模型仍未完成。10 步保留为后续性能目标，不借本轮更改完整 E1 的验收范围。
5. **真实观察范围。** trace 记录每个 owner step 后实际观察到的公开状态变化、command/transition/commit 序号、调用与订阅身份、资源及运行限制；不是全部内部 journal transition 的镜像。模拟呈现/计数器在接受回调之外才执行，独立记录执行次数。`barrier_checks` 只表示模拟副作用推进前公共持久屏障检查的次数，不证明 submit 回调入口时刻或故障窗口。
6. **正常重开。** 仅在没有在途或未知效果调用的静止点排空/重开，明确保留原 Task、owner、已完成 Call/operation、步骤和模型次数。兼容策略通过公开 reader 声明读取旧检查点；新独立调用使用新的 Mock Binding。此动作不提供断电、丢回执或恢复竞态证据。
7. **产物与失败。** 新目录独占创建，写 `run.json` / `trace.jsonl`；元数据包含生成时代码修订/dirty 标志、编译配置、实际 Kernel 配置及假时钟参数。正文、凭据与媒体不写日志。主失败、关闭失败、产物失败分别分类；不能证明关闭成功时保留整个组合及借用上下文，异常转换也遵守此边界。

## 后果

可以通过公开 API 复核正常的权限隔离、资源竞争、限制、检查点接续及通知顺序。夹具策略是测试业务，不成为产品默认策略。Native runner 使用文件系统；未来 Unity 接入还需平台产物端口和实际验证，不能据“数据与断言不依赖 GoogleTest”宣布移植完成。

## 备选方案

- 直接把既有单元测试列成 E1–E4 全通过：缺少统一数据和组合证据，拒绝。
- 在 runtime 内编写业务策略：让组合根因工作流语义变化而修改，改为独立 applications 组件。
- 运行时解析任意 JSON 动作或恢复原故障 DSL：增加未授权范围与运行时依赖，本轮只接受编译后的正常闭集。
- 为每个框架复制断言：重复领域判断，选择共用执行器；硬件产物端口留待 M2。

## 验证

正常场景及工具、产物复验已在进行；最终执行命令、独立审查和适用 CI 集中记录在本功能 PR。没有新增故障/恢复、变异、真实模型或硬件专项。MA-038 与性能/覆盖率收尾分别交付。
