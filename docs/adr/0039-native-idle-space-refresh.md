# ADR-0039：Native 空闲空间刷新

- **状态**：实施中
- **日期**：2026-10-24
- **关联**：MA-010；C-HOST-013、C-HOST-018；计划 §9.1

## 背景

Native 的 free_bytes 只读缓存，而缓存仅在打开和完成 I/O 后刷新。低空间或空间查询失败导致 Core 停止新写入，队列排空后便没有新的刷新机会；外部释放空间也不能恢复准入。

## 决策

1. 复用已有存储线程，每次请求后以及空闲等待一秒后采样。间隔是内部实现常量，不是文件系统或调度延迟上界，不添加公开配置或线程。
2. 文件系统查询在队列锁外执行；在锁内发布观测，并仅释放当前完成请求的预留，保留采样期间新受理请求的预留。同步端口仍只读取缓存。
3. 空闲观测的有效性或有效字节数变化时，在锁外调用 Host wake；不占用完成槽。查询失败仍继续采样，不复制 Core 的存储阈值或维护策略。
4. 停止通知中断定时等待；完成已受理请求后退出并 join。私有测试 peer 可替换空间观测，借用上下文直到 close_storage；生产路径仍直接使用 FileLog。

## 后果

恢复不再依赖下一次存储请求；空闲时增加每秒一次文件系统查询。ABI、schema、Core 内存需求及持久字节不变。关闭仍可能等待正在执行的文件系统操作，与原存储线程一致。

## 备选方案

不在 Core 查询路径同步调用 fstatvfs，因为会阻塞 step；不增加独立刷新线程或新端口，因为已有工作线程和 wake 已满足需要。

## 验证

本地 GCC Debug/Release、ASan/UBSan、TSan、Clang Debug、模拟器及工具检查通过；作者设计自查无未关闭发现。Core 内存需求不变。新测试覆盖无请求空间恢复、查询失败恢复、状态变化通知及稳定观测无唤醒。命令与结果见 [#57](https://github.com/RobotSe7en/ayni/pull/57)。真实磁盘耗尽与硬件耐久未验证。
