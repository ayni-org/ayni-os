# ADR-0107：单遍提议、引用轮次及旧机制清理

- **状态**：已接受；实施及本地验证见实验记录，暂不OTA。
- **日期**：2026-11-16。
- **关联**：ADR-0090、0096、0104～0106；C-CALL-014、C-POLICY-013、C-VER-006。

## 背景

用户要求继续减少输入到结束流程的重复读取、复制、遍历及校验，并清理前几轮替换后的代码；明确Ayni尚未公开发布，无需兼容旧入口。上一版逐项工具读取每次重新解码完整列表，ToolLoop另有两块最大节点输出区；保留轮次同时持有正文副本，新增答案时重写旧正文；部分JSON仍先测长再输出。净增代码包含正常测试与记录，也包含此前增加的缓存/发布状态，不能以总行数判定流程已简化。

## 决策

1. ABI0.56直接替换 `ayni_tool_calls_read` 为同步顺序visitor，删除逐项reader、固定最大节点输出类型及仓库内旧消费者。形状、唯一ID和完整结尾由同一codec负责。回调仅收集候选，整组成功后才可消费；不把提议读取当授权或派发。ATC3及Core schema10不变；不引入迁移器、双入口或兼容层。
2. 共享策略把当前工具组的原编码正文和实际节点前缀作为一个不可变对象，放入已有有界Turn缓存。固定8槽，节点上限沿用每项256；对象/节点用可检查的nothrow分配，专用同步引用句柄避免控制块另一次分配。缓存按Call身份、事实序号及完整正文身份复用，不缓存权限；每次仍查询Core现状。组结束、来源失效、取消/失败退休及隐私清空时释放。保留Turn事务性工作副本，未接受决定不能污染原缓存。
3. Turn轮次只持序号及原user/answer引用。保存新答案时只新增其正文及索引；删除/保留输入只更新引用索引，不提交旧正文。完整历史查询才投影公共Round文本；上下文失效后只读取需要重建的历史用户正文。索引只有一个reader/writer，没有正文与引用双状态。原正文所有权、摘要验证、UTF-8消费检查及发布屏障保持。
4. 参数、操作事实、摘要与模型请求JSON只写一遍。ESP独占PSRAM缓冲按需有界增长，替换前擦除旧区，失败不发送部分请求；最终仍擦除。预算预检、摘要选段与公共参数树准入是独立决策，不因消除测长而删除。
5. ADR-0106操作内正文句柄改为借读区或独占当前大正文，删除同步读操作中的共享控制块；读区16 KiB/64条目及跨owner/隐私不复用的限制不变。Session发布候选、最终整图确认、文件保存、真实清理与精确ACK各有持久职责，继续使用原状态机，不另加兼容分支。

## 后果与备选方案

减少整列表重复解码、轮次正文副本、旧正文提交和JSON测长遍历，工作区按删除的最大输出类型缩小。代价是活工具组会暂存一份编码正文和实际节点，直到组结束；原正文读取字符串分配沿用既有策略边界，未建立全仓无堆保证。ESP增长时旧/新PSRAM区短暂并存，保留有界上限及明确容量失败；实际板端峰值与时延仍待测量。

逐项接口适配会保留两套路径，违背用户选择；直接删旧并升级全仓。把可变Turn原地更新会破坏DEFER/未接受决定的回滚语义，保留有界工作副本。跳过当前权限/来源或最终持久确认会改变安全与持久保证，不采用。

## 验证

相关正常软件回归核对visitor顺序/整组准入/容量拒绝、工具组一次解析且每次查当前事实、原轮次不重提正文、JSON字节与容量、普通取消/隐私/发布/关闭。C99/C++17接口检查及ESP本地编译分别记录，实际结果见[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-16-单遍提议与引用轮次清理)。独立只读审查及修复复查已通过，无未处理阻断项。本轮不进行OTA、云端模型、真实设备或新增故障/恢复/变异专项，不以桌面计数声明板端性能达标。
