# ADR-0066：统一助理应用与异步通知呈现

- **状态**：已接受；正常实现、验证与独立审查见 [#88](https://github.com/RobotSe7en/ayni/pull/88)；文本路由、建议合并与 format1 已由 [ADR-0072](0072-single-assistant-schedule-tool-and-stop.md) 取代
- **日期**：2026-10-27
- **关联**：P5 / MA-019；ADR-0007、0042、0057、0060～0065；C-PROD-010～023、042、050

## 背景

Core 已提供日历、权限、记忆来源、Task 所有订阅和通用暂停组。它们需要由可信应用组成四类目标，保持 Kernel 事实为权威。原 Native 运行时只有一次规则和对话，Mock action 的完成不能证明 CLI 实际呈现；单个规则目标及 `/wait` 对所有活动目标的假设也不适合长期自主工作。

## 决策

1. **用户选择（产品语义，用户选定推荐项，2026-10-27）。** `@a/@b` 优先，未点名的 `check/检查` 给 A，其余文本给 B；不调用模型做路由。四类目标使用明确 CLI 命令及公开应用 API，复杂自然语言目标解析后续接入。安静时段默认关闭；启用后使用明确 POSIX 时区，时间未可信时普通通知等待，停止和故障指示继续。已开始呈现的通知允许完成，尚未开始的继续延后。（自 ADR-0072 起取消点名与路由，全部文本交给单一 ToolLoop 助理，模型可经计划工具登记待批目标；安静时段选择不变。）
2. **模块归属。** `applications/assistant` 拥有 GoalType、策略、参数版本、文本路由、建议重复/冲突合并及只读状态投影。应用只依赖公开 ABI；`runtime` 选择具体 Host、模型、Mock 设备、订阅和呈现器。Core 不增加通知类型或业务分支。公共档案仍通过显式保存与逐条/用途 Grant 操作，不自动共享。
3. **四类目标。** 提醒采用日历和 REMINDER 无界等待，不加入自主组，只有 `notify.present` 成功才完成；正文标明原定本地时间。设备检查采用周期和无修复/运动效果的 `mock.health`。整理为 BACKGROUND 周期，明确选择最多四条记忆、每条最多 1024 B，使用 ORGANIZE；模型摘要与本地空白/ASCII 大小写查重仅形成未确认、有来源的候选，不自动合并或删除。场景观察为一次长期 Task，订阅当前可用 Mock 标量；变化触发分析，可信 UTC 每五分钟抽查，未读取/外发真实媒体。
4. **用户选择（产品语义，用户选定推荐项，2026-10-27）。** 整理使用模型摘要加规则查重；每次摘要沿用授权、来源外发检查及 Task 计数。场景观察持续运行，默认八次模型调用后显示需要处理，由所有者提高上限或取消。所有自主目标在创建时固定到组 1；组外提醒和显式对话继续。
5. **暂停期间的分析。** 已确认取消的观察 round 记录中止步骤，恢复后等待新代际、新样本并使用新 round/key，原调用和计数保留。周期整理/检查的已确认取消结束本 occurrence，未来周期是新工作；UNKNOWN/FAILED 保持待处理，不以恢复作为重发授权。
6. **呈现与并发。** `providers/presentation` 是有界八槽异步 Provider；submit/cancel 仅操作短临界区，一个 writer worker 执行渠道回调。worker 不持锁做 I/O 或 post；写成功并刷新才返回 COMPLETE，明确无渠道为 UNSUPPORTED/NONE，其他写失败为 UNKNOWN。BUSY 只重投回执，不重复输出。已进入写出的通知允许完成，写前取消可确认 NONE。普通 CLI 输出另走有界 Console 队列，满/失败显式返回；两秒排空失败直接退出码1并跳过退出刷新，不能声称正常关闭。STOPPED 后先 quiesce/join、再释放 Kernel/Host；未排空时保留完整组合上下文。
7. **安静机制。** 独立 `notification.window` 管准入，`notification.slot` 管渠道占用；不占用旧 Mock 工具的 presentation.slot。writer 在开始前再通过线程安全窄端口读取当前 UTC，避免 owner 上次投影过期。正常延期在资源队列中无界保留；已接纳但未开始的操作保留原身份及通知专属有限 48 小时 deadline，覆盖一个小于 24 小时的安静窗口。校时长期不可用超过该期限时保留待处理，不宣称成功或自动重发。
8. **完成顺序（产品语义，用户选定推荐项，2026-10-27）。** 复用已交付的“调用结果持久→策略按稳定步骤完成 Task”两个有序 transition，替代 C-PROD-011 尚未实现的同批措辞。结果与完成之间只会晚标完成，正常重开读取原成功调用、不重复呈现；不增加 Kernel 自动结束某类业务 Task 的机制。新增故障窗口未验证。
9. **只读投影与合并。** 用户状态同时呈现处理、观察、待授权、需要处理的计数及自主暂停，不用主标签遮盖并行工作；普通 /status 不显示内部 ID；显式管理/诊断命令保留操作所需 ID 与提交回执。通知状态只投影公开调用事实。建议 API 合并同键同值的来源掩码，冲突值保留待审；显式所有者命令即使参数相同也各自创建，不能用参数相等替代 command_id。（建议合并 API 已随 ADR-0072 删除；模型来源目标按 operation_id 去重。）
10. **公共时间与兼容。** ABI 0.45 增加纯 UTC→本地秒、民用字段拆分，复用 work/goal 的 POSIX/Gregorian 规则，不用全局 TZ 或第二份日期算法；Task 调用结果视图追加 effect，使策略可区分已知取消与影响未知；无 Kernel 字段、持久布局或 schema 变化。所有 0.x 消费者重编译。原 rule/chat 与 Mock present 的目录、类型及绑定保持；实际通知使用独立 notify 别名。应用参数 format1 是有界小端值，不含指针（ADR-0072 升为 format2 并拒绝 format1；Mock present 已从 Native Profile 移除）；观察 checkpoint 仅存版本、phase、来源身份/序号、Mock 标量、round 与 UTC，不存单调截止时间。

## 后果

完整功能需要协调应用、具体部署、线程化呈现、公开纯时间工具及 CLI，放在一个功能 PR 便于审查整条呈现/授权链。按应用、Provider、runtime、Core 纯工具及正常场景分层审查，生产行数较大不按文件机械拆分。Core 的固定步和提交屏障保持；应用/Provider 可以分配有界启动存储，实际堆、栈及停止时限没有从 Native arena 推定为已测。

## 备选方案

- Mock action 即“已呈现”：没有实际输出证据，拒绝。
- owner 线程直接 flush：stdout 可阻塞 Kernel 推进，采用独立 worker。
- 只依赖资源的旧安静投影：writer 调度跨边界会误呈现，增加实际写前检查。
- Core 自动结束提醒：引入应用分支，与 ADR-0007 的归属冲突，使用通用调用事实与下一策略决定。
- 自动合并/删除记忆或用模型路由：超出用户选定边界。

## 验证

正常场景覆盖暂停保留提醒、未校时及安静延期、writer 阻塞时管理可推进、写前当前时间复核、长正文与原定时间、正常关闭重开不重复呈现、组织候选来源和模型计数、观察上限及暂停取消后新代际继续、Native 多目标重开和审批。具体命令、数量、工具链、内存、独立审查和 CI 结果集中在 [#88](https://github.com/RobotSe7en/ayni/pull/88)。未开展新的故障/恢复或变异专项；完整 E1–E4、真实媒体、硬件停止时限及 Core Alpha 未验收。
