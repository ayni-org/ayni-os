# ADR-0046：可信资源拓扑与冲突域

- **状态**：已接受；产品语义由用户 2026-10-25 选定推荐项
- **日期**：2026-10-25
- **关联**：MA-018A；计划 §2.2、§9.1；ADR-0042、0045；C-RES-002、004、008、013；C-PRIM-008

## 背景

#64 已把资源准入接入公开调用链，但资源目录尚不能表达设备/组件归属，两个不同资源名称也无法声明物理冲突。例如录音与播放可以分别有共享容量，但同一硬件接口不能同时运行两种模式。运行时持锁不能由策略或 Provider 各自协调。

## 决策

1. `catalog/device` 的 DeviceCatalog 持有可信 Device 身份及 Component→Device 关系；`catalog/resource` 持有资源描述和关联，`resources/admission` 继续独占健康、占用、隔离与公平队列。Kernel 只装配和启动交叉引用检查，不复制这些事实。
2. 注册顺序无关：单条注册检查形状/重复/容量，`ayni_start` 检查全部父引用以及 Binding 的整组资源是否可同时使用。缺引用保持 CONFIGURING，允许补登记后再次 start。所有目录由受信任 Host 配置，不执行自动发现、联网或设备控制。
3. **冲突域（产品语义，用户选定推荐项）**：同一资源仍按共享容量准入；不同资源若声明相同非空域则互斥。空域不冲突。请求同时需要同域的不同资源时直接拒绝；不会占有一部分后等待另一部分。域 ID 在 Kernel 内命名，跨设备是否共享域由可信配置明确声明。
4. 未确认停止的执行器仍隔离其整个冲突域。离线/健康变化不证明停止，只有原 claim 的准确确认才能解除隔离。已有 Agent 轮转、同实例 FIFO 和无冲突请求继续推进规则保持。
5. **组件关联（产品语义，用户选定推荐项）**：一个资源可关联多个组件，组件可用于多个资源；描述关联不替代 Capability/Binding 或授权，不把左右轮各自的资源声明当作两个独立控制域。无组件关联表示虚拟/系统资源。首版有界集合，不引入任意拓扑图或运行时重配。
6. ABI 0.32 增加目录容量、可信注册和复制查询，描述/配置追加字段；0.x 调用方重新编译。草案中同名声明移除，只有正式接口。所有目录和运行时占用仍是启动配置/易失事实，不新增持久记录，不恢复旧物理句柄。

## 后果

切换 Native 模拟设备或增加硬件 Host 时，只需在 runtime 组合根提供相应可信目录和 Provider；Core 不引入具体驱动依赖。目录可零容量关闭，默认 Hello 不启用实体表；显式配置需要的 arena 增量另行量测。描述中的身份与关联不是固件测量、校准证据或远程配对证明。

## 备选方案

把冲突伪装成额外互斥锁会让每个 Capability 重复隐藏资源，容易漏写，并使查询无法说明真正的冲突来源。把 Device/Component 运行健康再存一份会产生与 Resource 健康不同步的事实；本轮只报告可信目录与资源自己的运行状态。

## 验证

可信目录、共享/互斥、隔离与容量边界的相关正常验证通过，独立完整审查及影响复查无剩余阻断项。证据与 CI 结果见 [#65](https://github.com/RobotSe7en/ayni/pull/65)；不据此宣布完整 MA-018 或 M1。产品优先级、提醒保留/后台跳过、可复用 Mock、许可/Scene 与真实硬件停止仍有各自交付边界；不新增故障或恢复专项。
