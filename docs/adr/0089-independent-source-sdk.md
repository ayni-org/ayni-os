# ADR-0089：独立源码 SDK 与跨平台消费边界

- **状态**：已接受（实现与验证逐包记录）。
- **日期**：2026-10-31。
- **关联**：ADR-0011、ADR-0014、ADR-0083；[实施计划](../architecture/independent-consumption-plan.md)。

## 背景

现有Core、Host、Provider及runtime已有目录分层，但根CMake是Native部署工程，会引入SQLite、CURL及内部装配。公开示例借助runtime fixture，不能独立证明另一工程可以原样使用通用库。

## 决策

用户要求保持同仓库独立目录，完整实现独立验收所需能力。通用SDK提供源码导入函数与按需目标，不选择Host、平台或设备。原有部署继续作为参考和回归，不做无关搬迁。独立工程只消费公开接口；平台运行与实际功能分别取得证据。

SDK默认选择Core和Strategies；其他已实现便携组件显式选择，传递必要静态链接依赖。同源重复选择幂等，不同源码来源及未知组件在配置期拒绝。基础组件不查找平台或JSON依赖；Mock选中后才引入锁版yyjson。原内部目标保留，新增命名空间别名作为消费入口。

## 后果

Native根构建和ESP参考装配共用目标定义，业务及平台实现不进入Core。SDK入口不提供动态模块加载、二进制分发或新的包管理。添加第三个平台时，平台适配及runtime改变；Core和ToolLoop的机制保持在其公开契约内。

## 备选方案

直接把根CMake当库使用会混入部署依赖；复制源码清单容易与现有构建分叉。将全部平台代码迁出仓库扩大迁移且不是独立使用的必要条件，均不采用。

## 验证

独立只读源码构建、Native公开调用、组件链接及ESP编译分别验证；当前实施中，尚不声称完整跨平台验收通过。实际结果由对应PR记录。
