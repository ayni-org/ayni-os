# ADR-0104：共享对话正文与连续派发前缀

- **状态**：已随[#137](https://github.com/RobotSe7en/ayni/pull/137)合并；独立审查修复、完整CI与ESP固件编译通过；ESP缺失删除误报修复后已正常OTA，启动自确认、三轮本地诊断及收尾观察通过；板端交接延迟验收仍待实测。
- **日期**：2026-11-15。
- **关联**：ADR-0096、0098、0100、0103；C-COMMIT-004/006/008、C-CALL-012、C-HVAL-001/005；本轮原分支 `fix/esp32-reply-speech-text`。

## 背景

前两轮优化保留全部对话保存等待与完整调用更新。板端同一无模型、无电机合成回合仍为4732 ms，最长step约603 ms；不同真实指令的交接观察不能充当同条件比较。本轮目标是减少共享流程中的串行保存、完整历史副本及重复解析，仍在真正派发前持久确认实际参数、身份、绑定和DISPATCHING事实。

用户已选择异步对话尾部、独立正文引用、直接升级且不迁移，以及两段交接各P95≤100 ms并报告最大值。随后明确**先只完成代码，板载先不验证**；因此不执行OTA、擦区、云端模型或自动短动作。原先20次、100 ms、20% PWM、单路轮流、至少500 ms间隔且确认停止的边界只保留给后续已安排的板端验证，不能据此自动启动。

## 决策

1. **正文内容与所有者分开。** ABI0.55的body store提供stage、share、confirm和可选临时模型输入释放。stage在正数容量预算内接受不可变正文，立即可读，不自行请求保存；confirm非阻塞请求后台保存，完整正文及所有权都持久后才返回OK。write复用暂存/确认实现，仍只在持久后成功。不同scope得到独立、幂等引用，最后一个所有者释放后才删除正文。FileBodies用持久manifest保存所有scope引用，4 KiB分块、每次至多一个文件借用；Memory/SQLite共享同一不可变载荷。payload和所有权元数据均有界，失败保留已接受内容并明确报告。
2. **历史只保存顺序、结构与正文引用。** ConversationRecord6、turn7拒绝旧格式，不保留旧reader。消息索引只增加新帧的结构及引用；round索引复用用户/回答正文，滚动窗口即使轮数未变也更新。工具结果采用Core已经规范化的正文，历史保存小投影视图及原Schema/domain引用，冷读通过同一JSON writer重建；不另存完整渲染结果作为执行账本。模型原始提议、Core实际规范参数保持不同事实。Core首次Call行仍拥有原身份、绑定、契约、授权与实际参数。
3. **保存策略由组合根选择。** 共用组件默认durable；ESP明确background并启用共享规范结果，通用portable profile也可显式选择以运行同一软件夹具。未保存聊天尾部可以丢失。普通模型请求正文只是临时输入，Core在该Call终态事实持久、Provider借用结束后释放未确认的请求所有者；不同步骤使用不同scope。模型原始答复/提议只后台保存一次。最终历史的正文、索引及外层文件全部成功后才ACK Core发布；隐私删除保留旧图并重试加载/删除，实际排空或明确失败前不ACK。普通关闭在Core停止后继续推进已请求的正文chunk/manifest，完整排空且无保存错误才报告组合关闭成功；失败后无借用可安全dispose并返回错误。未知执行结果不重试，重开不自动续跑旧物理命令。
4. **缓存的是不可变表示。** ToolLoop有界保存已解码回合和按已采纳契约生成的工具JSON；每次主请求刷新当前可见列表。权限、来源、Task/Scene及停止状态仍由Core实时检查。普通请求只拼装/计量一次出站上下文；索引引用枚举不读取整段正文；已确认历史版本不用每次poll重复确认。组合根在Core step后、历史/隐私ACK前调用ToolLoop维护入口，以公开Task状态清除取消/终结/held回合，以privacy request_seq和phase清除失效的WAITING私有副本；完成代际只消费一次，不清掉后续有效回合。缓存不成为权限依据。
5. **首次全量、后续可变状态。** Core schema10的type21/v2为首次完整Call行及完整快照；v3仅在journal中更新已有Call的可变状态、结果及执行/订阅事实。共享同一mutable codec，不能用delta创建或替换身份/契约。准备和DISPATCHING仍分别有序进入journal，取消PREPARED单独的持久等待；最终claim仍必须等待包含DISPATCHING的完整前缀持久，并重新检查当前权限和执行门。
6. **有界连续提交与存储优先级。** 可选storage_append_many把至多8个连续批次作为一次Host借用，保留每个原身份；整个组OK才推进durable_seq，重试冻结原组及字节。Native/ESP以完整帧顺序追加并在末尾同步。执行记录优先于普通外层值，后台正文再次让位；相同优先级仍保持FIFO，正在执行的文件操作不被中断。没有新执行单或平台私有Kernel。

## 兼容与数据处置

ABI0.55、Core schema10、ConversationRecord6、turn7、SQLite user_version4和文件正文manifest1分别升级。全部消费者重新编译；旧Core格式在新写入前拒绝并保留，格式不匹配**不触发清空**。原完整二进制和原目录只能作为匹配的回退组合。

用户已选择不迁移旧聊天/任务，软件交付时暂不操作板卡；随后另行要求拉取main并OTA，且引用原用户计划确认继续，按该选择完成本次指定分区清理。部署仍走既有指定`ayni`分区流程，先停止输出、排空并关闭Host，再清理0x800000/8 MiB；不清配置、密钥、配对或偏好，不加启动擦卷。Native默认durable/archive行为保留；新共享结果配置可在现有有界内联账本中保留无法暂存的已接受结果，后续正文容量/保存错误明确阻止会话推进，不能丢回执或伪造执行失败。

## 取舍与备选

只缓存Schema或只把write改成后台，仍会反复保存完整历史并堵住同一文件队列；取消最终持久屏障则破坏派发保证，均不采用。消息索引和原结果投影增加少量引用元数据及冷读成本，换取正文只保存一次；缓存受明确额度约束。批量提交减少同步次数，但不把Host工作改成跨批事务，不声称掉电时全部批次原子出现。

## 验证

Native相关回归、ASan/UBSan、正常关闭重开、独立源码SDK导入及ESP-IDF固件编译通过；独立只读审查无剩余阻断发现，实现、独立复核与适用CI集中见[#137](https://github.com/RobotSe7en/ayni/pull/137)，此前软件结果同步到[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-15-共享正文与连续提交软件实现)。本轮新增格式的异常恢复、掉电、耐久和完整板端交接性能均未验证；现有历史测试保留，不把正常关闭重开或既有旧格式证据解释为新格式恢复验收。短/固定长历史的两段板端P95与最大值，以及100 ms目标是否达到，留待后续部署实测。

用户随后单独授权的正常Wi-Fi部署已完成：临时schema9过渡镜像在原正常关闭屏障与完整候选校验之后，复用精确分区ResetWorker清理已授权的旧卷，再选择未修改的main `c6fc731`；新应用ABI0.55启动并自确认，配置标记保持。临时镜像不进入产品源码，不能作为以后默认擦卷授权。部署与现有本地合成诊断见[实验记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-15-main正常ota与指定旧卷清理)；这次OTA不恢复20次PWM或完整板端性能验收，新格式异常恢复仍未验证。

同日用户报告失败后的只读复核确认：OTA已自确认，但合成诊断结束后立即出现AYNI_STORAGE_FAILED（-14），应用不可用；首次诊断脚本漏检终态后的失败，不能把该回合标为整体通过。根因尚未证实，现有日志缺少底层文件原因；现场保留，详见上述实验记录的状态纠正。

后续正常路径已在生产ESP适配与RAM NOR上重现：缺失删除被错误标为整卷poisoned，导致目录确认EIO/-14。修复仅分类该正常缺失，既有RAM介质回归、ASan/UBSan及ESP编译通过；未更改ABI/schema或放宽其他元数据错误，详见[修复记录](../../experiments/esp32_wifi_chat/WIFI.md#2026-11-15-缺失正文删除导致的存储错误修复)。用户完成普通复位后，已保留当前卷正常OTA至c6fc731-storagefix，启动自确认和三轮本地诊断及终态后15秒观察通过，未再出现存储失败。
