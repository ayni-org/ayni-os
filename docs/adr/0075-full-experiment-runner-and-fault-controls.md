# ADR-0075：完整实验运行器与受控故障生命周期

- **状态**：已接受；实施与验证结果随本阶段 PR 记录
- **日期**：2026-10-28
- **关联**：计划 §10.1；MA-021/022/023/033；ADR-0012、0068；C-EXP-001～005

## 背景

用户已授权依次完成完整实验至 E4。Sim Host 已有故障和持久镜像，但 SimNode 只支持正常关闭，P6 正常 profile 明确不接受故障动作。直接复用其“正常重开”会在实际切断前排空，从而错过需要验证的窗口。

## 决策

1. **复用 SimNode/Host。** 增加仅用于模拟根的 owner-thread Host 控制与 abrupt power_cut。丢弃 arena 前须由组合根 quiesce 所有模拟 Provider，再由 Host 结束存储借用。新 Kernel 重建配置/目录，保留同一 Host 的镜像与时间。此方法不适用于真实异步生产者，未声明硬件断电证据。
2. **独立完整 profile。** `m1-experiment` / schema 1 在构建期将有界闭集 JSON 动作编译为顺序 C++ 调用，与 `m1-normal` 分开。只编译实际支持的动作；原 schema 0 保持草案。阶段 1 只登记 HARNESS 自验证，后续逐阶段增加原完整实验编号，不用自验证冒充 E1～E4。
3. **明确观察属主。** Core 事实经公开 API 读取；Host 负责实际匹配故障与存储；受控本地服务负责执行次数，计数和 operation 记录保留在 Kernel 外。执行与回执分开控制，服务不自动去重，暴露重复执行。所有控制均在 owner 线程，无真实 I/O 或生产者线程。
4. **失败和证据。** 等待、部署步数、轨迹和服务槽有上界。只保留第一个失败原因，清理/产物独立分类；未知用例、空 suite、已有输出目录均拒绝。CLI/GTest 共用执行器，原正常与新实验复用诊断 JSON 编码，ABI 和 schema 2 不变。

## 后果

可在不改变 Core 的情况下真实切断并重建模拟 Kernel，分别观察实际效果和持久结果。更换故障 Host 或补充具体故障点时只改 Host/实验装配，Core 仅在实验揭示机制缺陷时修改。模拟 Host 控制增加了 Native root 的测试能力，但不进入 C ABI 或生产 Host。

## 备选方案

- 在 P6 正常重开前排空全部工作：无法验证结果丢失和提交中断，拒绝。
- 为完整实验另造 Kernel 生命周期或存储 codec：重复机制并可能与真实路径分叉，拒绝。
- 直接复用旧 completion 指针投递迟到结果：arena 生命周期不成立，拒绝；后续只向有效 mailbox 投递带旧 attempt 身份的受控事件。

## 验证

六个设施场景、受限恢复/共享时钟回归及相关正常夹具本地验证通过；命令、独立审查、最终 CI 和修复结果集中在 [#97](https://github.com/RobotSe7en/ayni/pull/97)。完整 E2/E1/E3/E4 仍待各自阶段，不代表覆盖率、Core Alpha 或硬件验收完成。
