# ADR-0064：Agent、Goal 与 Task 的持久存储属主

- **状态**：已接受；实施与验证见关联 PR
- **日期**：2026-10-27
- **关联**：P5 / MA-019；F04；ADR-0051、0059、0061、0063

## 背景

Grant、Call 等表已经通过 `PersistentStore` 声明记录、预算和快照遍历，但 Agent、Goal、Task 的同类规则仍分散在通用日志、快照和版本分类器里。P5 的暂停组与应用目标需要沿用这些存储语义，先完成可独立交付的职责迁移，避免新增第二套记录规则。

## 决策

1. Agent、Goal、Task 各有编译期存储适配器，拥有版本识别、日志编码、最大记录及完整快照容量、快照记录选择、写入与恢复。通用协调器只保留所有者绑定、清理事实和跨存储顺序。
2. 快照游标包含行、部件和部件内位置。一次选择返回实际记录类型、版本和长度；只有完整记录写入后才能消费。Goal 的元数据紧接其状态；Task 按创建、步骤、可选检查点、状态、准入顺序输出，空部件由属主跳过。
3. 读取时只保留一个活动存储的配对游标。待配对事实不能跨对象或存储，必须等完整对象结束后才切换；完整性证明及日志跨记录关系仍由原有重放机制维护。
4. 多记录对象的完整 payload 上限由属主声明，不能用最大单条记录乘对象数代替。日志和快照预算沿同一存储清单汇总。
5. ABI 0.43、schema 2、现有记录布局及顺序保持。保留旧读取器对 optional envelope、上下文专属版本及 REQUIRED 的既有处理；本次不建立迁移工具。

## 后果

新增表不再要求通用快照协调器了解领域对象的部件。适配器增加显式游标职责；通用层仍检查顺序和边界，不能把跨记录配对证明当作重复解析删除。

## 备选方案

- 只移动函数到另一个文件：预算、版本和多记录遍历仍分散，未完成 F04。
- 每张表建立独立快照流：增加分页与恢复机制，无法复用已验证的有界协调器。

## 验证

沿用现有记录、分页快照、重放及相关公开 API 正常用例，并补充跨页与大页输出记录一致性的断言。实际命令、结果及独立审查集中于关联 PR。新增故障/恢复与变异专项仍暂停；此次整理不扩大历史验收结论。
