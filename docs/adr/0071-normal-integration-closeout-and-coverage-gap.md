# ADR-0071：正常集成收尾与覆盖率差距

> **现行目标补充（2026-10-30）**：安全关键分支目标已由 [ADR-0088](0088-safety-branch-coverage-target.md) 统一为 ≥80%，原90%目标弃用。以下保留本 ADR 当时的决定、测量及验证事实。

- **状态**：已接受；统一证据见 [#93](https://github.com/RobotSe7en/ayni/pull/93)
- **日期**：2026-10-27
- **关联**：P6；ADR-0038、0050、0068～0070；计划 §4.2、§9.1、§10；workflow §2

## 背景

正常组合、typed 多节点子集和 Native 开销已分别交付。当前测试政策暂停新增故障/恢复与变异专项；阶段仍须量覆盖率并如实保留差距。历史 F 阶段的用户指定门槛不能替代当前通用 90% 安全分支目标。

## 决策

1. **报告正常范围。** 统一交付 M1 正常集成报告，索引独立用例、Native 测量和配置验证，不把它命名为 Core Alpha 或完整 E1～E4/MA-038 通过。原任务归属、权限、持久屏障、未知结果及独立停止链契约不变；真实硬件和完整专项仍未验收。
2. **沿用统计口径。** 固定 GCC 13 Debug、无 sanitizer，计数更新用 atomic；构建/发现后清空本轮 gcda，运行既有完整套件和模拟器。收集所有当前 TU，包括头消费者，行取并集；仅过滤编译器 throw 弧，分支只在同函数/同有序布局内合并。保留 P4 的 Core/安全保守范围，不以新子集缩小分母。
3. **完整性与来源。** 收集器核对干净源码与编译后二进制身份；当前编译数据库限定有效 notes，冲突 profiling/sanitizer 参数明确拒绝。缺少安全范围实现源数据时失败；无数据的合法 notes 仍按零计数。无 gcov 头单列，独立审查区分声明/编译期体与运行时体，不凭缺条目声称已覆盖。
4. **实测差距。** Core 行覆盖达到 75% 目标，安全保守分支覆盖未达到 90%。未覆盖分支继续保留；当前测试全集尚不足，不宣称它们全是不可达/故障分支。按既定测试政策记录差距，后续补测与完整安全验收继续开放，不降低目标或自动恢复专项。具体比例、计数、冻结修订和原始证据限制见报告及 #93。
5. **后续修复与冻结。** 仅工具守卫修复后重聚合同一原始数据验证完整性，不冒充重新运行测试；报告保留实际测量冻结修订。阶段完整配置结果放在 PR，状态页只说明已交付内容、下一步与待用户的选择。ABI 0.45 / schema 2 不变。

## 后果

本轮正常交付有可复核证据，安全覆盖与原始专项的欠账不会被正常结果掩盖。覆盖率是已编译 Native 代码的指标，不能推出硬件安全时限或生产协议保证；ESP32 数据继续留到 M2。

## 备选方案

- 为达到比例临时删掉防御分支、缩范围或默认把未覆盖代码排除：拒绝。
- 自动重启新的故障/变异活动追数：违反本轮既定政策，留待用户安排。
- 用此前配置结果或当前 Native 指标直接宣布 Alpha：缺少完整实验与硬件证据，拒绝。

## 验证

正常夹具、Native 容量/开销、多节点子集和本轮冻结覆盖率已执行并复核；Core 行覆盖达到目标，安全分支目标仍未达到。统一命令、计数、独立审查和适用 CI 集中在 [#93](https://github.com/RobotSe7en/ayni/pull/93)。原始本地覆盖率未上传，完整专项与硬件保证不在该结论内。
