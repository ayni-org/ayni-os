# ADR-0088：安全关键分支覆盖目标统一为 80%

- **状态**：已接受（验收政策，用户 2026-10-30 明确指示）。
- **日期**：2026-10-30。
- **关联**：ADR-0012、0038、0080、0083、0087；AGENTS.md、工作流与基础验收。

## 背景

AP-04/AP-06 基础验收对当前干净生产修订完成完整回归及覆盖测量。Core 行覆盖满足既定目标，保守安全范围分支覆盖达到 80% 而低于当时的 90% 目标。向用户提出本轮接受范围问题后，用户明确要求“统一都改成80%，90%弃用”。这是通用目标调整，不是沿用 M1 的局部例外。

## 决策

1. 现行安全关键分支覆盖目标统一为 **≥80%**，弃用原 90% 目标；适用于当前及后续工作、基础验收和相应发布计划。Core 行覆盖目标仍为 **≥75%**。
2. 统计范围、分母、编译器与聚合方法保持既有工具规则：Core 行并集；安全保守范围包括 Core、permit gate、Mock/Mock execution 及对应运行头文件，仅去除 compiler throw 弧，不删除防御分支或按新阈值缩小范围。
3. 同步仓库规则、工作流、主计划、架构计划、README 和当前验收报告。历史测量、当时的门槛及偏差保持原事实，并追加本决定的替代说明；历史低于新门槛的结果也不重写为通过。
4. 覆盖达标不替代功能、权限、恢复、停止或硬件证据，也不自动恢复故障/恢复和变异专项。未取得的必要证据仍明确列出，用户另行选择范围。

## 后果

不再为弃用的 90% 目标安排补测或保留现行偏差。当前及后续结果按 80% 判定；软件覆盖数字不能作为平台、物理执行或耐久通过证据。现有覆盖收集器报告原始分子/分母，没有硬编码验收阈值，不新增另一套计算或 CI 执法声明。

## 备选方案

仅对本次基础验收接受 80%、仍保留通用 90%：用户明确要求统一调整，未采用。

## 验证

当前完整软件回归及覆盖已采集，达到 Core 行 75% 和保守安全分支 80% 的目标。政策同步检查、实际统计、独立审查和适用 CI 集中 [#117](https://github.com/RobotSe7en/ayni/pull/117)。本决定不声称尚未执行的新恢复专项或平台验证通过。
