# ADR-0044：Provider 有界结果交接与可靠消费确认

- **状态**：已接受
- **日期**：2026-10-25
- **关联**：ADR-0042；MA-008A；C-PROV-006、C-CALL-012、C-ID-006

## 背景

Host CompletionPool 只交接一次固定确认，回调返回就释放。Provider 另有可合并进度、不可丢取消控制和有界正文，业务结果还可能等待日志空间。若强行复用同一消费队列并阻塞头部，就可能挡住释放该空间所需的存储确认。

## 决策

1. `kernel/completion/ProviderMailbox` 独立拥有结果交接生命周期；复用 Host ingress lock/wake 和精确 attempt 比较，不复制领域状态、授权或记录编码。Host 确认继续独立推进。替换模型 Provider 只改变消息生产者；新增 Host 实现同一锁/唤醒端口。
2. submit 前从 caller arena 预留完整槽：独立 progress/terminal 字节区域和无正文 cancel 控制。进度序号递增，旧序号忽略；新进度只替换旧进度。第一个终态封闭生产者入口并取代可选进度，已接受的取消控制仍保留。终态之后的控制/结果是迟到消息，不再接受。
3. 单 owner reserve/read/ack/withdraw，多非 ISR 线程 post。post 在锁内复制、锁外 wake；owner 读取复制到独立缓冲，不持有内部指针。按 attempt 轮转，每个 attempt 内先取消控制、再终态、再进度。BUFFER_TOO_SMALL 保留消息并返回所需长度。控制确认后保留其身份以拒绝重复。
4. 读取不删除。owner 仅在相应业务 transition 能被提交后 ack；背压时消息保留。旧 progress receipt 不可删除新进度或终态。终态 ack 须在先前取消控制 ack 后，随后释放槽并清空两段缓冲；这不是持久安全擦除。withdraw 仅适用于 submit 明确 NOT_RETAINED 且未发布任何消息，不能丢弃矛盾证据。
5. reservation 绑定 mailbox 生命周期、槽和完整 attempt，不是安全能力。caller 提供非零 boot 和严格递增 request ID（跨同一实例的 boot 切换也不重置）；本模块不另建分配器。Kernel 集成时须与 Host 共用唯一 request ID 来源，耗尽拒绝而不回绕。销毁前 caller 必须保证生产者退出，空槽不证明不存在迟到线程。
6. 本次独立交付边界是内部并发结果交接，不发布 ABI、不扩充 Kernel arena、不装配实际 Provider。参数上限为 256 槽、每段 65536 字节，调用装配随后按部署容量选择；不能据此声称 ESP32 可承受最大配置。状态码、正文 Schema、取消语义、Task/ActionRecord 和 B4 原子结果应用由领域消费者校验，不在 transport 中假造完成。

## 后果

可靠结果不会因事件队列满或业务存储背压被覆盖；有界拷贝的锁占用随配置正文上限增长，硬件时长仍需量测。两个独立字节区域比单缓冲多占用内存，但避免已复制进度和可靠终态互相覆盖。统一调用接入必须明确销毁、排空、ID 分配与提交确认次序。

## 备选方案

扩充 Host 单次确认会混合借用归还与业务持久两种生命周期；通用无界消息队列不能保证终态入列；读取即删除会在日志背压时丢失唯一结果。均不采用。取消控制不含正文，保留独立元数据即可，无需第三段字节区域。

## 验证

内部正常行为测试覆盖预留、复制、背压保留、进度合并、取消/终态顺序、槽复用与并发生产；现有 Host CompletionPool 相关回归通过。独立审查未发现功能阻断，重复身份比较与持锁说明已整理。验证证据随本功能 PR 记录；没有新增故障/恢复专项或运行 TSan，不代表生产调用、B4 持久性或硬件已验证。
