# ADR-0091：共用Host文件存储与平台文件端口

- **状态**：已接受；实现、审查及验证见 [#120](https://github.com/RobotSe7en/ayni/pull/120)。
- **日期**：2026-10-31。
- **关联**：ADR-0026、ADR-0027、ADR-0039、ADR-0040、ADR-0089；[独立接入计划](../architecture/independent-consumption-plan.md)。

## 背景

Native文件日志把帧检查、快照、轮转及系统调用放在同一实现。新ESP Host需要相同的提交身份、物理顺序与未知写入规则，重复实现会使平台语义分叉。Core已经提供公开存储格式探针，不需要Host读取Core私有结构。

## 决策

将文件机制移动到`hosts/storage/`，通过有界、同步的`Files`接口借用平台文件命名空间。机制只处理AYNL v1帧、完整性、物理游标、快照及轮转；Core继续拥有记录、提交与恢复决定，异步Host继续拥有队列、完成投递及容量缓存。SDK可按需选择`Ayni::HostStorage`或Linux的`Ayni::NativeHost`；共用机制链接Core公开格式读取实现，没有反向依赖。

`Files`在配置线程取得独占命名空间后，仅由单一I/O worker调用，所有操作返回明确结果。文件令牌只在Host内部使用，不能进入C ABI。文件同步须确认数据与长度；命名空间同步可由适配器已完成的同步持久操作满足，但必须另有平台证据，不能用无条件成功伪装保证。当前Linux端口仍使用flock、pread/pwrite、fdatasync及目录fsync；ESP LittleFS端口在后续包实现并验证。

共用日志只在成功取得命名空间后承担关闭责任；第二个被拒绝的实例不会结束第一个实例的租约。关闭状态拒绝写入、栅栏与容量确认，非法非平面文件名在取得命名空间前拒绝。正常短读取由机制累计至EOF或完整边界。追加预留字节计算由帧格式属主统一提供。

保留Native内部的组合对象以同时拥有文件适配器与借用它的日志，保证销毁顺序，并保持现有故障接缝及消费者。它不保存第二份存储状态。Native完整Host依赖Linux时钟接口，SDK明确只在Linux选择该组件，不宣称macOS完整支持。

## 后果

新Host替换文件端口和异步执行环境即可使用同一存储机制，不修改Core或复制恢复策略。原文件头、帧格式、快照布局、Core schema8及ABI0.53保持不变，无迁移器。新C++源码组件不是稳定二进制插件ABI，消费者按固定源码版本构建。

同步文件接口只能在配置或后台I/O中使用，不能由`ayni_step`调用。原Native故障回归保留；本包新增正常重开、拒绝后的资源归属和独立导入验证，不开展新断电或记录变异专项。文件系统耐久保证与实际Flash写入代价仍须由ESP适配及实机证据分别支持。

## 备选方案

不为LittleFS复制Native日志，不在Core引入POSIX或ESP类型。没有把不同平台的线程、时钟和锁强行抽成通用OS框架；本次仅分离实际需要共享的文件机制。

## 验证

共用引擎、Linux适配及相关正常/既有存储回归的实际命令与结果集中在 [#120](https://github.com/RobotSe7en/ayni/pull/120)。默认无Host、共用存储及Linux Host的隔离源码消费者分别验证构建边界。ESP编译、实际介质、掉电及耐久尚不属于本包已验证结果。
