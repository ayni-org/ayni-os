## 6. E：需求、待批与原子批准

按依赖拆为 E1 内部事实/codec；E2a arena、日志/快照/恢复及 Grant 引用回收保护；E2b 需求导出、创建/查询与最低消费门控；E3a Goal 专属绑定、内部批量容量/ID 预检与全部既有消费限制；E3b 公开原子批准、原始创建内容查询、完整命令身份与持久配对。回收保护不能推迟到 F；公开入口与其安全前置一同交付。原 ABI 0.20 是顺序预留，实际按每次公开变更递增。

### 6.1 需求与授权上限

GoalType 从已验证参数导出有界需求。契约明确所有者线程、缓冲所有权/生命周期、容量、失败和禁止重入；catalog 保存声明，authority 提供范围机制，work 保存 Goal 的规范需求与引用。每 Goal 需求默认 4、范围 1～16，继续使用已定 Scope 字节限额。

持久事实区分明确零需求和缺少元数据；保存 exact Capability 版本及足够原始域证据，恢复时不能按漂移目录重新解释。无需求、多个需求、非法字段、未知能力、容量不足、回调失败与重入均需测试。

### 6.2 创建、查询与待批

合法但缺授权的 Goal 保存为 PROPOSED，占用有界 Goal 容量；不生成 Task、不积累 occurrence、不能有子目标，允许取消和按原期限失效。全部需求被有效持久 Grant 覆盖时进入激活路径；未知能力、非法需求和不支持功能明确拒绝。

查询复制完整需求、缺项和已有 Grant 依赖到调用方缓冲，错误不发布半份输出。一项需求由一条完整 Grant 覆盖；Goal 专属优先、实例通用其次，同级按 ID。不拼接多 Grant 扩大单项权限。

### 6.3 审批身份与原子应用

批准要求绑定管理端、非零命令 ID 和 expected revision；绑定 Goal ID、owner、GoalType 版本、完整参数、触发源、重复规则及期限。语音不能批准，拒绝提案复用 GOAL_CANCEL。请求回显不可变的完整创建内容，并携带原缺项 mask 和明确期限；复制查询提供原始参数及相对失效期限，不能用当前截止时间倒算。命令查找先于当前 Goal 查找，终态或回收后仍可精确重试。

按用户选择复用原 Grant，只为明确缺项创建默认长期有效、不可委派的 Goal 专属 Grant；不能覆盖别的 Goal 或子 Goal。审批前原有依赖失效而使缺项增加时拒绝本次批准，返回新的缺项情况，不能自动扩大批准内容。

先预检全部 Grant 槽位及替代候选、ID、命令窗口、日志和快照容量，再将专属 Grant、授权引用、激活和完整命令映射同批提交。命令按完整规范请求去重；重试返回原结果，不再次发权限或重启计时。

### 6.4 计时、持久与最低门控

延迟/周期从批准激活开始；待批不积累 occurrence，既有失效期限沿用原规则，限时 Grant 不因等待落盘延长。新权限持久前不能执行。批准入口开放时同步具备派生前、策略执行前的最低授权复核：撤销、过期或父链失效立即阻止推进；完整 Task/子 Goal 传播与恢复由 F 完成。

新记录同时进入 journal、重放配对、启动发现、双槽快照和最大容量公式。旧 reader 遇未知 REQUIRED 记录安全受限。审批断电只能恢复整批事实，不存在部分可用权限。

### 6.5 E 验收

管理端完成创建待批、查询、批准、等待持久和执行；补齐多个需求原子性、陈旧审批依据、命令重试、表满、期限边界、批准后撤销、快照冻结、FAILED/UNKNOWN 和恢复配对错误。公开写入口不得先于最低消费检查交付。

### 7.2 模块与授权事实

catalog 保存可信声明；authority 拥有 Grant/父链/范围/期限/Gate；work 拥有不可变上限、选定引用、独立暂停、触发与工作清理进度；kernel 编排原有事务、命令及重放证明；durability 不解释授权。禁止 authority 反向读取 work，不增加 Kernel 散字段。

Task 按稳定 slot 和 exact task_id 保存 Goal 绑定及按需求顺序的准入引用，不复制 Scope 或 Grant 当前状态。子 Goal 保存父绑定代次；父重新授权不能自动放行未清理的子 Goal。派生、策略前及结果接受前复用同一检查，回调后重新采样时钟。独立授权暂停不覆盖用户暂停、策略失败或兼容性原因。

### 7.3 原子重新授权与有界清理

MANAGEMENT 以 command、Goal revision、授权事实提交序号和完整原创建回显重新授权指定 Goal 及全部直属活 Task。在有效持久 Grant 中专属优先、通用其次、同级按 ID 选择；缺覆盖先单独创建 Grant，不隐式发权限。完整预检后同批更新引用、绑定、授权暂停解除、触发/输入边界和命令结果，持久后执行；子 Goal 单独恢复。

批准及重新授权保存当时引用证据，精确重试不再次应用；快照不能以当前引用反推旧批准。新记录同时纳入发现、配对、分页快照及最大预算。恢复失败丢弃部分事实，继续沿用 writer 隔离。

工作扫描按固定 through/单调 after 的稳定 ID 有界推进，扫描中新请求保留下一轮边界；每批最多一 Goal 的授权事实与直属 Task，游标同批。活 Task 保护 Grant，引用释放等实际持久确认；Goal 结束后专属 Grant 立即不可消费，终态清理后按原规则回收。

### 7.4 触发选择与开发期格式边界

一次性/延迟目标未失效时显式恢复后执行一次，同 boot 不重新延时。周期全部未派生积压（含暂停前）记跳过，之后接回原节拍；已有 Task、步骤/检查点保留。输入水位之前未消费输入对该 Goal 全部跳过，不影响其他 Goal；水位由 ingress 锁内入队序号采样，实例身份隔离比较。普通断电提醒及跨 boot 计时契约保持。

F2 批次/快照切至 schema=2，仅支持新格式。旧存储明确拒绝并保留，开发使用新状态目录；不迁移、不自动补授权、不做旧数据确认，不自动清空或回退。新格式完整证据有效时 F5 正常继续；授权暂停、旧 boot 限时 Grant 和不兼容继续禁行。F 完成才可标记 MA-006 机制/模拟消费者闭环，真实许可/Provider/完整故障矩阵仍随 MA-018/008/022。

### 7.5 提速与验收

每 PR 本地完整 Debug、ASan/UBSan、模拟器和工具检查；最终提交的 ready PR CI 跑全部适用矩阵。验证与只读审查重叠，独立审查者兼变异出题（15～25 项）；变异在隔离固定目录增量构建，全部首轮完成后补测试。等待 CI 时可准备下一份本地分支，仍逐份按依赖合并。

覆盖率在 F1～F5 全部合并后统一量测，本地完整五配置再复核；Core 行≥75%、安全分支≥90%，范围为 E 原范围加 F 新增授权/清理/重放模块。补齐可触达的相关 E 缺口，不缩范围，不以旧偏差豁免。本轮收尾时用户另行指定安全分支超过 88%，依 ADR-0038 决策 21 量测验收；通用 90% 目标及实际差距仍保留。每 PR 独立报告四项可读性证据，实际命令、变异表及 CI 写 PR，状态页保持简短。

## 8. 每份 PR 的交付门槛

1. 保持 catalog、authority、work 的不变量所有权，kernel 只编排；不增加平行事务/日志或 Kernel 零散授权字段。
2. ABI、记录版本、storage schema 分开管理；更新契约、traceability、布局测试、容量公式和实施文档。E/F 实施时分别新建 ADR，按实际交付顺序编号。
3. 按 workflow 运行 GCC Debug/Release/ASan+UBSan/TSan、Clang Debug、模拟器、依赖、契约、格式、可读性及 diff 检查；每个 PR 最终提交完成所需 CI；F 按第 7.5 节与 workflow 的分层本地验证执行，适用 CI 仍须全绿。
4. Core 逻辑由另一代理/会话按 diff 和契约出 15～25 项缺陷，默认由做独立审查的同一会话出题；首次结果与补测后结果分开，编译失败不算检出；独立审查逐项报告四项可读性结论。
5. 开始构建/测试/变异前检查宿主内存、swap、CPU 与其他任务，明确并行度及容器限制并监测；植入缺陷的原文备份放仓库外持久目录，用于中断后恢复。资源监测结果不写进 ADR 或 PR。
6. 代码整理及涉及 ABI/容量的 PR 实测默认/最小配置内存，没变时写一句未变；E/F 补需求数、Grant 数、树深及清理规模边界。覆盖率在每个部分（R2b、R3、E、F）全部合并后量一次，不足按证据记录，不用历史数字代替本次结果。纯文档/工具变更不量测 Core 内存或覆盖率。
7. PR 正文逐个对应复查编号，列出位置、验证及限制；状态文件保持简短，只在取得相应证据后更新完成状态。
