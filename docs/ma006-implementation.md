## 6. E：需求、待批与原子批准

按依赖拆为 E1 内部事实/codec；E2a arena、日志/快照/恢复及 Grant 引用回收保护；E2b 需求导出、创建/查询与最低消费门控；E3 Goal 专属 Grant 与原子批准。E3 若超规模限制，先交专属绑定/内部预检，再交公开批准，已有消费者同步限制专属 Grant。回收保护不能推迟到 F；公开入口与其安全前置一同交付。原 ABI 0.20 是顺序预留，实际按每次公开变更递增。

### 6.1 需求与授权上限

GoalType 从已验证参数导出有界需求。契约明确所有者线程、缓冲所有权/生命周期、容量、失败和禁止重入；catalog 保存声明，authority 提供范围机制，work 保存 Goal 的规范需求与引用。每 Goal 需求默认 4、范围 1～16，继续使用已定 Scope 字节限额。

持久事实区分明确零需求和缺少元数据；保存 exact Capability 版本及足够原始域证据，恢复时不能按漂移目录重新解释。无需求、多个需求、非法字段、未知能力、容量不足、回调失败与重入均需测试。

### 6.2 创建、查询与待批

合法但缺授权的 Goal 保存为 PROPOSED，占用有界 Goal 容量；不生成 Task、不积累 occurrence、不能有子目标，允许取消和按原期限失效。全部需求被有效持久 Grant 覆盖时进入激活路径；未知能力、非法需求和不支持功能明确拒绝。

查询复制完整需求、缺项和已有 Grant 依赖到调用方缓冲，错误不发布半份输出。一项需求由一条完整 Grant 覆盖；Goal 专属优先、实例通用其次，同级按 ID。不拼接多 Grant 扩大单项权限。

### 6.3 审批身份与原子应用

批准要求绑定管理端、非零命令 ID 和 expected revision；绑定 Goal ID、owner、GoalType 版本、完整参数、触发源、重复规则及期限。语音不能批准，拒绝提案复用 GOAL_CANCEL。

按用户选择复用原 Grant，只为明确缺项创建默认不可委派的 Goal 专属 Grant；不能覆盖别的 Goal 或子 Goal。审批前原有依赖失效而使缺项增加时拒绝本次批准，返回新的缺项情况，不能自动扩大批准内容。

先预检全部 Grant 槽位及替代候选、ID、命令窗口、日志和快照容量，再将专属 Grant、授权引用、激活和完整命令映射同批提交。命令按完整规范请求去重；重试返回原结果，不再次发权限或重启计时。

### 6.4 计时、持久与最低门控

延迟/周期从批准激活开始；待批不积累 occurrence，既有失效期限沿用原规则，限时 Grant 不因等待落盘延长。新权限持久前不能执行。批准入口开放时同步具备派生前、策略执行前的最低授权复核：撤销、过期或父链失效立即阻止推进；完整 Task/子 Goal 传播与恢复由 F 完成。

新记录同时进入 journal、重放配对、启动发现、双槽快照和最大容量公式。旧 reader 遇未知 REQUIRED 记录安全受限。审批断电只能恢复整批事实，不存在部分可用权限。

### 6.5 E 验收

管理端完成创建待批、查询、批准、等待持久和执行；补齐多个需求原子性、陈旧审批依据、命令重试、表满、期限边界、批准后撤销、快照冻结、FAILED/UNKNOWN 和恢复配对错误。公开写入口不得先于最低消费检查交付。

## 7. F：工作模型、撤销与兼容闭环

按运行时传播与清理、显式恢复、旧数据确认与兼容验收拆分；各合并点保持完整拒绝路径。原 ABI 0.21 为顺序预留，多次公开变更继续递增，不复用版本。

### 7.1 Task 与子 Goal

Task 继承 Goal 的权限上限及可核查引用；换 Grant 不扩大原范围。派生、继续策略决定、接受策略结果分别复核，期限判断使用相应检查时刻。子 Goal 必须落在父上限内，并独立取得自身授权；父专属 Grant 不直接授予子 Goal，零需求父也不能成为扩权入口。

测试主体、父链、范围、未持久 Grant、撤销、期限，以及策略回调期间跨过期限时不提交未获准步骤/检查点。

### 7.2 独立暂停与显式恢复

用户暂停、授权暂停、类型不兼容和策略失败分别保留；查询说明有效生命周期与阻塞原因。撤销/过期即时阻止派生和策略执行，持久清理可分步，进度与检查点保留。新 Grant 不自动替换引用或恢复工作。

管理端的明确重新授权并恢复操作验证命令/revision、完整需求、父上限和当前有效持久 Grant；将指定 Goal 及直属 Task 的引用、授权暂停解除及命令结果同批提交。保留其他暂停/失败原因，子 Goal 单独恢复；普通 GOAL_RESUME 继续遵守普通暂停规则。

测试授权不足、恢复前再次失效、重复命令、写失败重载、其他 hold 并存、父恢复不越过子 Goal 授权暂停。

### 7.3 授权暂停期间的触发

按用户选择跳过期间的新周期触发与本地输入，记录周期跳过的数量/原因，恢复后接回原节拍；既有 Task、步骤和检查点保留。一次性与延迟工作单独验证，避免被周期规则误伤。

本地输入先排队：显式恢复时为该 Goal 建立输入接收边界，边界之前未消费的输入全部跳过（含暂停前已入队的旧输入；按推荐项实现，改选再改）。必须能够判断输入与授权恢复边界的顺序，不能让暂停期间入队、恢复后才出队的输入补执行，也不能全局清队列影响其他 Goal。覆盖入队、撤销、背压、快照、恢复及出队的交错情况。跨 boot 沿用既有恢复计时契约，不比较不同 boot 的单调时间，不改变普通断电提醒补发。

### 7.4 有界清理与回收

将 D 的撤销依赖扩展到 Goal/Task；有界扫描的进度与本步工作状态同批，断电不跳过未处理依赖，快照冻结期间仍即时拒绝。活工作引用阻止 Grant 回收；引用替换/解除须满足持久条件。Goal 结束后专属 Grant 不再可消费，按既有历史保留与安全回收规则处理。

work 提供活引用事实，authority 保持回收规则，不引入 authority 对 work 的反向依赖。测试小容量/满表、多 Goal 共用 Grant、祖先撤销、清理断电、未持久引用解除及清理完成前回收。

### 7.5 正常恢复与旧数据确认

| 恢复对象 | 预期结果 |
|---|---|
| 元数据完整、永久 Grant 与目录有效、原来可运行 | 正常继续并保留进度 |
| 原来已因撤销或授权失效暂停 | 保持暂停，等显式恢复 |
| 依赖旧 boot 限时 Grant | 旧授权失效，等新授权与显式恢复 |
| 缺授权元数据的旧 Goal/Task | LEGACY_UNCONFIRMED，等管理端确认 |
| 原类型、Capability 域或检查点不兼容 | 保留，报告具体原因 |
| owner binding 失配 | 只读受限 |

旧数据确认须用原 GoalType 版本与保存参数重建完整需求；缺原语义则继续暂停，不能把缺元数据当零需求，不能以新类型重释旧工作。确认、绑定及获准恢复事实原子持久。

F 完成才可标记 MA-006 机制及模拟消费者闭环完成。真实执行许可/续租、Provider 在途取消/外发、完整故障矩阵分别随 MA-018、MA-008、MA-022；物理停止仍需硬件证据。

## 8. 每份 PR 的交付门槛

1. 保持 catalog、authority、work 的不变量所有权，kernel 只编排；不增加平行事务/日志或 Kernel 零散授权字段。
2. ABI、记录版本、storage schema 分开管理；更新契约、traceability、布局测试、容量公式和实施文档。E/F 实施时分别新建 ADR，按实际交付顺序编号。
3. 按 workflow 运行 GCC Debug/Release/ASan+UBSan/TSan、Clang Debug、模拟器、依赖、契约、格式、可读性及 diff 检查；每个 PR 最终提交完成所需 CI；本轮 GitHub 额度耗尽期间按 workflow 第 2 节的本地验证例外执行。
4. Core 逻辑由另一代理/会话按 diff 和契约出 15～25 项缺陷，默认由做独立审查的同一会话出题；首次结果与补测后结果分开，编译失败不算检出；独立审查逐项报告四项可读性结论。
5. 开始构建/测试/变异前检查宿主内存、swap、CPU 与其他任务，明确并行度及容器限制并监测；植入缺陷的原文备份放仓库外持久目录，用于中断后恢复。资源监测结果不写进 ADR 或 PR。
6. 代码整理及涉及 ABI/容量的 PR 实测默认/最小配置内存，没变时写一句未变；E/F 补需求数、Grant 数、树深及清理规模边界。覆盖率在每个部分（R2b、R3、E、F）全部合并后量一次，不足按证据记录，不用历史数字代替本次结果。纯文档/工具变更不量测 Core 内存或覆盖率。
7. PR 正文逐个对应复查编号，列出位置、验证及限制；状态文件保持简短，只在取得相应证据后更新完成状态。
