`memory.access` v1 有四个必需参数：field 1/2 为 Kernel ID 的 epoch/sequence（I64，单位 `id`），field 3 为用途（1 CONTEXT、2 ORGANIZE），field 4 为操作（1 read、2 write，单位 `code`）。`memory.egress` v1 前三项相同，field 4 是实际目的地 IDENTIFIER，usage=EGRESS_DESTINATION。公共 scope 构造函数负责拆分 ID；CLI 默认共享 CONTEXT/read，不生成后台整理许可。跨 Agent 派生内容的闭包仍保留原 actor；外发要求每项 actor 等于当前调用者，否则保守拒绝。

策略 `read/search/propose` 只在当前 decide 回调借用，不能保留指针；至多一个 MODEL/DERIVED 提议，须配一个 WRITE_MEMORY step。MODEL 来源须为本 Task 已完成且 durable 的模型 Call。显式模型工具适配未实现；CLI `/memory use` 选择一条上下文记忆，复用同一受限读取。
