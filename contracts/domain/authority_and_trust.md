# 授权与信任

- **关联**：计划 §2.2、§2.5、§3.4、§3.5、§5.4；ADR-0003、ADR-0004、ADR-0017、ADR-0028～0031；`MA-004`、`MA-006`、`MA-016`；E1 步骤 1、6、7，E2 F1、F10
- **属主**：`authority/principal`、`authority/scope`、`authority/grant`、`authority/scene`

## 信任的两条轴

| 轴 | 不可信 | 可信 |
|---|---|---|
| 输出可信度 | 模型与 VLA 输出、外部消息、发现到的设备描述、MHS 参考文件、语音识别文本 | 经可信注册的目录、本机授权库、已认证管理端的确认 |
| 代码可信度 | 第三方原生代码、MHS 代码文件（均不进入固件） | v0.x 固件与 Kernel 进程内的策略、GoalType、Provider、Driver、控制器（可信内置 C/C++） |

纯函数策略接口用于确定性与可替换，不是安全边界：它不能阻止进程内原生代码越权访存、直接 I/O 或无限循环。ESP32 首版不提供强进程隔离，权限保证只覆盖受管理入口。

## 有限字段与规范范围（ADR-0029）

本节为 B 的设计契约，实施及验证状态以条款验证列为准。公开类型与注册入口位于 `include/ayni/authority.h`。Capability 身份是 CatalogId 加非零版本；字段 ID 非零且在该版本内唯一。参数、执行目标、外发目的地共占最多 8 个字段；目标和目的地必须是 IDENTIFIER，且各至多一个。整数单位为非空 CatalogId，符号集合单位为空，不做隐式单位转换。所有声明的授权字段在实际请求中必填，业务中的其他可选参数不属于本 schema。

ENUM 与 IDENTIFIER 都是有界 CatalogId 文本集合，但类型不互换。集合原始输入 1–8 项，排序去重；空集合、非法文本、重复字段、未知字段、倒置整数区间、错误 kind/unit 均拒绝。I64 等值用相等端点、符号等值用单成员集合表示；覆盖检查为区间包含或逐成员包含，各字段取合取。实际请求只能是单点区间或一个规范 token，不能提供范围代替一次调用的具体值。

规范正文格式版本为 1：4 B 头部为 `u16 format`、`u8 field_count`、`u8 reserved=0`；每字段先写 `u32 field_id`、四个 u8 的 `kind/usage/unit_length/member_count`、unit 正文，随后为两个小端 i64 端点，或逐项 `u8 length + token bytes`。字段按 ID、token 按字节序严格递增；I64 的 member_count 为 0，符号集合为 1–8。省略字段补完整注册域；拒绝非规范、缺失或多余尾字节，不依赖 C++ 布局。该正文不是公开 wire 协议或独立日志记录；后续 Grant 持久化须带 Capability 身份/版本并引用此格式。

完整注册域与任一规范 Scope 都受 `authority_scope_max_bytes` 约束。默认 256 B，范围 64–4096 B，字段数/成员数/字符长度/字节数上限同时有效；超限明确拒绝，不能先接受无法表示的省略全域。Scene、次数/费用额度不属于本字段表达，不因字段缺省而成为无限权限；依赖 Scene 的授权不支持，额度随 `MA-018`。

## Grant 管理与恢复（MA-006 C，已实现并完成 Native 验证）

`GRANT_CREATE` 沿统一意图入口创建根 Grant 或携带 parent 的受限委派；C 的管理端为唯一owner，不把subject_instance_id视作调用者认证。known Scene/Quota flags返回 `UNSUPPORTED/GRANT_UNSUPPORTED`，unknown flags为形状错误。查询使用固定typed `ayni_get_grant` 与按index复制字段的 `ayni_get_grant_field`，所有输出由caller拥有，不返回内部指针。lifecycle表示持久领域模型的状态，可能尚待落盘，不能当作持久确认；用对象commit_seq与Kernel durable_seq核对，effective_reason给出即时有效性。

每Grant拥有metadata与source_domain/scope两个配置字节stride；恢复先独立读取合法事实，再按当前exact目录完整bytes证明语义一致。未持久、过期、subject缺失、catalog变更等有效性原因不能被单纯scope包含替代；完整父链继承拒绝。到期即时拒绝与终态持久回收分开，易失deadline/hold不导出快照。撤销、Goal专属Grant/批准与完整work检查分别由D/E/F交付，这是C的历史边界。其中D的Gate/祖先拒绝、阶段回执与Grant持久清理已实现并通过Native验证（ADR-0031）；Goal专属Grant/批准与完整work消费者仍未实现，本次不启动E/F。

## 即时撤销与阶段回执（MA-006 D，已实现并完成 Native 场景验证）

`GRANT_REVOKE=10` 仍经统一意图入口；新请求要求绑定所有者的 MANAGEMENT Session、非零 command/target/expected revision。首次形状、身份和目标/CAS均合法后，GrantTable 安装易失 Gate，CommandTable 复制专用 pending；接受不分配 transition，不等存储。所有 kind 先查 pending 再查窗口与 floor；低于后来 floor 的已接受撤销仍能发布，同 target 另一命令 BUSY。窗口只逐出未 pin 最小 ID，全 pin 拒绝普通新工作；专用控制容量不足原子拒绝。

GrantTable 的独立 Gate 与 CommandTable 的 pending/易失 pin 归各自 owner，以 grant_capacity 有界分配，无 Kernel 数组或第二套普通窗口。自动重载只清可恢复领域事实及 queued stamp，保留已接受控制；完整恢复后仅凭原 mapping 的完整 canonical 确认。真实 Grant 检查遍历完整祖先 Gate/REVOKED；Goal/Task 接入随 E/F，本部分不把模拟检查称为真实派发或物理停止。限时授权仍沿 C 的 duration-only 持久规则。

Host 通过已认证 principal 与 command 查询统一回执，不依赖旧 Session；PENDING 控制在部分恢复和只读受限期间可查，普通窗口须完整恢复。snapshot/journal 不保存 Gate/pending/pin，跨进程只承诺已 DURABLE 的领域结果。DRAINING只在有效writer仍可append时排空已接受控制；从RESTRICTED或失败reload关闭不应用新事实，收回借用后安全STOPPED，不主动清Gate/pending。详细字段、持久布局及未执行验证见 ADR-0031。
