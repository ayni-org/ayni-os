# Native 助理应用运行时

- **关联**：ADR-0057、ADR-0060、ADR-0066、ADR-0072；MA-019、MA-020 前半；计划 §9.1。

条款描述本机可信演示装配，不构成远程管理认证或硬件支持。

| 编号 | 规范 | 反例 | 验证 |
|---|---|---|---|
| C-NATIVE-001 | 唯一的助理实例以 ToolLoop 通过公开意图运行，全部普通文本（含 `check/检查`）都是它的对话回合；缺授权保存待批；正常重开继续原待批 Goal，不重复创建；双 Agent 版本的数据目录在任何启动写入前拒绝且不修改。CLI首次/重开入口等待本地会话读取、保存及ACK的完整过程，包含请求之间的状态；原待批/暂停Goal不阻塞入口，不重试已接受工作 | CLI 按关键词把文本交给另一实例，或从配置直接给策略绕过 Grant；重开另建同一工作；改写或迁移旧目录 | M1 已实现：`NativeAssistant.check_text_is_an_ordinary_turn_of_the_single_assistant`、`NativeAssistant.proposed_turn_can_be_approved_after_normal_reopen`、`NativeAssistant.dual_agent_conversation_file_is_refused_before_any_boot_write`；CLI 脚本 tests/integration/native_cli_test.py；`NativeStartup.loading_stays_visible_until_the_original_turn_or_record_is_available` |
| C-NATIVE-002 | 对话只由完成且 durable 的 Task 检查点产生候选，异步文件必须匹配 Context ID/revision/generation/轮次，精确 ACK 持久后才展示；等待完成包含文件提交与 ACK，正常关闭重开保留正文与摘要 | Task 刚内存完成即宣布已保存，下一轮回收其检查点 | M1 已实现：`NativeAssistant.short_history_and_conversation_survive_clean_close_and_reopen`、`NativeAssistant.continuing_past_retained_capacity_keeps_latest_context_and_queryable_calls`；异常退出窗口及文件故障未验证 |

## P5 统一助理

| 编号 | 规范 | 反例 | 验证 |
|---|---|---|---|
| C-NATIVE-007 | 普通文本不做路由，全部交给单一助理；四类目标通过明确 API/CLI 创建，提醒/检查/观察也可由模型计划工具登记（C-NATIVE-011）；显式创建不按参数相等合并；自主组不包含提醒/显式对话；并行状态与提醒继续可见 | 暂停助理使提醒消失；多个自主目标导致启动失败 | `AssistantPolicy.encoding_grammar_stop_phrases_and_quiet_time_are_explicit`、`NativeAssistant.autonomous_goals_reopen_and_approve_through_the_public_application`、`AssistantApplication.pausing_autonomy_preserves_reminders_and_new_goal_membership` |
| C-NATIVE-008 | notify 声明 NOTIFICATION，实际写出并刷新成功才是完成证据；owner 不等待输出 I/O；有界普通 Console 队列与通知回执分别处理，满/失败显式返回；失败排空不释放生产者借用 | 仅提交输出队列就完成提醒；stdout 堵塞使 Kernel owner 卡住 | `QuietAssistantApplication.blocked_writer_keeps_owner_responsive_and_queued_output_rechecks_time`；CLI脚本 stdout backpressure 正常场景；通知 I/O/真实线程停止上限未实测 |
| C-NATIVE-009 | 安静时段默认关闭；启用时明确 POSIX TZ，未校时等待。owner 管准入，writer 写前复核当前时间；开始写后的结果可收敛。已接纳通知采用独立48h有限deadline | owner 旧时间投影使尚未开始的通知跨安静边界写出 | `QuietAssistantApplication.due_notification_waits_for_trusted_time_then_presents_once`、`QuietAssistantApplication.blocked_writer_keeps_owner_responsive_and_queued_output_rechecks_time` |
| C-NATIVE-010 | 整理仅对明确最多四条来源做模型摘要/规则查重，ORGANIZE授权和外发沿用 Core；不确认、合并或删除原值。观察使用当前 Task-owned Mock标量，变化/五分钟抽查，默认八次模型调用后等待处理；确认取消round保留计数，新代际新key继续 | 整理自动删除相同记忆；暂停恢复重试未知模型调用 | `AssistantApplication.explicit_memory_sources_produce_unconfirmed_summary_and_duplicate_candidates`、`AssistantApplication.continuous_observer_waits_for_current_samples_and_stops_at_model_limit`、`AssistantApplication.paused_analysis_round_is_retained_and_new_generation_continues` |
| C-NATIVE-011 | 模型计划工具与所有者命令共用一套文法，整理仅所有者发起；一次工具操作至多登记一个调用实例名下的顶层 Goal，同一操作被再次决定时按 operation_id 返回原 Goal；模型来源且待批的 Goal 有固定上限；模型来源 Goal 另需 CLI 不提供授权别名的确认能力，所有者批准前停在待批；发起调用的 Task 已停止或结束时不登记，以 CANCELLED/effect NONE 作答；文法、容量或上限拒绝以 COMPLETED 文本回给模型并写明未登记；Goal 持久后才向所有者公告一次，重新打开时对仍待批者再公告 | 同一操作再次决定时登记出两个提醒；一次模型回复登记的待批目标占满 Goal 表；“停”之后工具仍登记目标；模型登记的观察未经批准就运行；把未持久的 Goal 公告为已登记 | M1 已实现：`NativeAssistant.model_schedule_tool_registers_a_goal_that_waits_for_owner_approval`、`NativeAssistant.model_goals_waiting_for_approval_are_bounded`、`NativeAssistant.stop_before_the_schedule_tool_decides_registers_nothing`、`AssistantApplication.model_origin_goal_waits_for_consent_and_is_found_by_its_operation`、`AssistantPolicy.encoding_grammar_stop_phrases_and_quiet_time_are_explicit`、`NativeAssistant.local_http_tool_loop_and_text_only_summary_use_real_provider_wiring`（文法拒绝回给模型）；仅本地 HTTP 夹具，真实模型多轮与崩溃时在途调用（UNKNOWN）未验证；GoalPort BUSY、无端口与准入关闭路径未构造 |
| C-NATIVE-012 | 整句停止短语（停、停下、停止、stop，可带首尾空白含全角空格与句末标点）与 `/stop` 不经模型，也不等待授权或进行中的对话保存：取消当前回合并暂停自主组，已接受提醒继续；更长句子仍是普通对话。它不是 C-STOP 的独立紧急停止 | “停”作为对话交给模型，或因上一轮保存未完成返回 BUSY；停止撤销提醒 | M1 已实现：`NativeAssistant.stop_phrase_cancels_the_turn_pauses_autonomy_and_keeps_reminders`、`NativeAssistant.stop_cancels_the_active_shared_session_before_answer_publication`、`AssistantPolicy.encoding_grammar_stop_phrases_and_quiet_time_are_explicit`；CLI 脚本 tests/integration/native_cli_test.py |
| C-NATIVE-013 | 每次主模型请求的 system 指令末尾写明发请求时的本地日期、时刻、星期，另起一行写 POSIX 时区（ADR-0074），由模型换算相对日期，代码不解释自然语言日期；时钟未同步时照写并标注，没有可用 UTC 样本或时区时写未知，配置了时区就写出时区；CLI `timezone` 只接受 POSIX 规则，未配置时依次取：`TZ` 本身是完整规则；`TZ`（去掉开头的 `:`）指向的时区文件，绝对路径或相对 `/usr/share/zoneinfo`；`TZ` 未设或为空时 `/etc/localtime`；取不到为未知。与 glibc 的主要差异：规则优先于同名文件，空 `TZ` 或 `:` 不视为 UTC，`:<规则>` 不按规则解析，不读 `TZDIR` | 模型不知道当天日期却把“明天”换算成具体日期；按关键词在代码里换算相对日期；把 `Asia/Shanghai` 这类区域名当作规则 | M1 已实现：`BuiltinLoop.model_request_instructions_state_the_local_time`、`NativeAssistant.model_schedule_tool_registers_a_goal_that_waits_for_owner_approval`；CLI 脚本 tests/integration/native_cli_test.py（只看退出码）；读取 `TZ` 与时区文件的默认路径、`--mock` 保留时区未自动测试，真实模型换算效果待本机试用 |
