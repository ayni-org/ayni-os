# Host 端口

- **关联**：计划 §2.1、§3.2「所有权/异步/线程」、§4.1、§4.2、§4.3；ADR-0002、ADR-0006、ADR-0014、ADR-0015、ADR-0016、ADR-0019、ADR-0020、ADR-0021、ADR-0026、ADR-0027；`MA-003`、`MA-005`、`MA-007`、`MA-010`；E1 步骤 10，E2 F2、F7、F12
- **属主**：`kernel`（端口的调用方、事件入口与完成槽）；各 Host 实现（`hosts/native`、`hosts/esp_idf`、`hosts/sim`）
- **头文件**：已实现部分 `include/ayni/ayni.h`（`ayni_host_v1`：时钟、唤醒、入口临界区与八个存储端口；`ayni_completion_post`；`ayni_post_event`）；计划部分 `include/ayni/draft/host_v1.h`

Host 为 Kernel 维护自身不变量提供平台服务（ADR-0006）：时钟、持久存储、唤醒与日志出口。网络、模型、媒体与设备 I/O 不是 Host 端口，而是经 Binding 调用的 Provider（`provider.md`）。

## 端口一览

| 端口 | 方向 | 调用线程 | 是否阻塞 | 完成方式 | 状态 |
|---|---|---|---|---|---|
| `monotonic_now_us` | Kernel → Host | Kernel 所有者线程 | 否 | 同步返回 | M0 已实现 |
| `wake` | Kernel 或 Host 线程 → Kernel 所有者线程 | 任意非 ISR 线程（ISR 经桥接） | 否 | 多次唤醒合并为所有者线程的一次调度 | M1 已实现 |
| `ingress_lock`、`ingress_unlock` | Kernel → Host | 任意非 ISR 线程 | 只等待持锁者的一步有界操作（C-HOST-020） | 同步返回 | M1 已实现 |
| `storage_append` | Kernel → Host | Kernel 所有者线程 | 否 | `OK` / `FAILED` / `UNKNOWN`；同身份同字节追加幂等 | M1 已实现（模拟与 Native） |
| `storage_read_prefix` | Kernel → Host | Kernel 所有者线程 | 否 | 按起始 commit_seq 返回完整批次；缓冲不足报告所需大小 | M1 已实现（保留旧调用方式；Kernel 恢复使用 read_log） |
| `storage_read_log` | Kernel → Host | Kernel 所有者线程（恢复） | 否 | 物理游标读完整批次，`value` 为字节数、`next_cursor` 为后继位置；0 字节为 EOF | M1 已实现（模拟与 Native） |
| `storage_fence_writers` | Kernel → Host | Kernel 所有者线程（恢复或 FENCED） | 否 | `DRAINED` / `EPOCH_INSTALLED` / `UNAVAILABLE`；成功 value 返回实际新 epoch | M1 已实现（Native 排空；模拟安装 epoch） |
| `storage_write_snapshot`、`storage_read_snapshot` | Kernel → Host | Kernel 所有者线程 | 否 | 按 slot、offset 分块；写 `OK/FAILED/UNKNOWN`，读另报字节数 | M1 已实现（模拟与 Native，两个独立槽） |
| `storage_trim_prefix` | Kernel → Host | Kernel 所有者线程 | 否 | 保留指定 activation 身份及其后全部物理批次；幂等 | M1 已实现（模拟与 Native） |
| `storage_free_bytes` | Kernel → Host | Kernel 所有者线程 | 否 | 同步读取已扣除 Host 配额、在途预留的可用字节缓存；无法建立空间时 STORAGE_FAILED | M1 已实现（模拟与 Native） |
| `log` | Kernel → Host | Kernel 所有者线程 | 否（可丢弃并计数） | 无 | 草案 |
| `ayni_post_event` | Host → Kernel | 任意非 ISR 线程 | 只等待入口锁 | 返回 `OK`（已入队，解锁后 `wake`）/ `BUSY`（队列满）/ `CAPACITY_EXCEEDED`（ABI 0.25 起，同一 ingress 实例累计接受的输入序号达到 UINT64_MAX）/ `INVALID_STATE`（`CONFIGURING`、`STOPPED`） | M1 已实现（本地输入，ADR-0021；其他事件种类为草案） |
| `ayni_completion_post` | Host → Kernel | 任意非 ISR 线程 | 只等待入口锁 | 写入预留的完成槽，然后 `wake` | M1 已实现 |

端口名与 `ayni_host_v1`（已实现部分）和 `include/ayni/draft/host_v1.h`（计划部分）的成员名一致。

八个存储函数为 append、read_prefix、read_log、fence_writers、write_snapshot、read_snapshot、trim_prefix、free_bytes。`ayni_create` 仍允许没有存储或只有旧 append/read_prefix pair 的合法短表；pair 缺一或新扩展只提供一部分时拒绝。`ayni_start` 要求八个函数齐备，否则返回 `UNSUPPORTED` 并保持 `CONFIGURING`；不以成功桩补齐缺失能力。

`storage_read_log` 的游标只在当前日志实例内有效，0 从首帧开始。同一实例内非空返回必须严格增加 `next_cursor`；空返回为 EOF，轮转成功后从 0 重读。它按物理顺序交回所有完整批次，包括旧 epoch；Core 才决定 fence 后哪些批次失效，不能让 commit_seq 过滤吞掉后面的有效批次。首个完整批次超过缓冲时，以 `AYNI_READ_BUFFER_TOO_SMALL` 完成，`value` 为所需字节数，不写出半个批次；Kernel 将其分类为 `STATE_EXCEEDS_CAPACITY`。普通 I/O 失败仍为 `STORAGE_READ_FAILED`。

快照 offset 0 开始覆盖 inactive 槽，后续块顺序写入；同一 offset、相同字节重试幂等。读端可读取尚未提交的候选以校验内容；Core 校验后才写 marker，再以日志 activation 切换。`trim_prefix` 以 writer epoch、transition_id、commit_seq 定位 activation，保留该帧及其后所有物理帧，不按序号另筛一次。

## 完成槽

控制类完成（存储确认、调用终态、取消结果、停止确认）在 `submit`/`append` **受理时**预留一个完成槽：

1. Kernel 先从预留池取一个槽，为这次尝试分配 `(boot_epoch, request_id)`，再连同二者调用 Host；没有空槽时 Kernel 不调用 Host，调用方得到 `AYNI_BUSY`。Host 同步返回 `REJECTED_NOT_RETAINED` 时槽立即释放（C-HOST-004）。
2. Host 完成时以同一 `(boot_epoch, request_id)` 把结果写入该槽并 `wake`；写槽不会因普通事件队列满而失败。
3. Kernel 在所有者线程上应用结果并释放槽，之后该槽可以分给新的尝试。结果所带的尝试身份与槽当前的尝试不一致（迟到或重复的完成）时忽略并计数，所以槽被重用后旧结果也不会被当作新尝试的结果。
4. Host 对每个已受理的请求恰好完成一次，结果未知时也要以 `UNKNOWN` 完成；完成之前 Host 可以持有槽指针与请求引用的 Kernel 缓冲，完成之后两者都不再访问。全部预留槽都已完成，Kernel 才能进入 `STOPPED`。

隔离成功只证明旧写入方不能再改变介质，不等于归还旧请求借用；旧请求仍各自完成一次。Host 在 `UNKNOWN` 后继续排队的底层写入只能引用 Host 自有副本。M1 不设置会回收槽或复用缓冲的合成 I/O 超时：永久不完成的请求保持槽与缓冲，不能安全重载或进入 `STOPPED`；组合根须停止相关线程后才能销毁 Kernel。退避与限频期限由 `next_deadline_us` 调度，不阻塞 owner。

在途请求数有上限，所以预留池有界；可靠性逻辑留在可移植 Core，不在各 Host 重复实现确认与重投协议。槽的状态变更都在入口临界区内进行（ADR-0015）。
