# 人工架空电机验线

此入口用于人工在场的短脉冲硬件诊断，不运行 Ayni Core，不开放模型运动能力，也不替代 `PHYSICAL` action、许可、联锁和独立停止链的正式接入/验证。该验线入口与新加入的 Ayni 人工逐次审批运动配置分别构建；后者见上级 README。

已知配置：用户确认 TA6586、D0/1/2/3→GPIO38/39/40/41（用户2026-11-01改线并确认）；3V3 辅助输出留空，只共地及四根控制线；驱动独立 10 V、电机额定 12 V、车轮架空、有独立断电开关。电机电流和驱动板停止时限未测量。烧录/重启期间保持驱动电源关闭；握手通过后由在场用户开电并备好断电开关，再执行已授权的单个短脉冲。

诊断应用完成初始化后四脚低，不主动提交启动波形；ROM/复位期间的引脚电平未保证，打开/关闭USB串口及烧录必须保持驱动断电。新 ARM 的 nonce 必须严格增大、两秒内使用、硬件调用前消费；一次 ARM 只允许一个 PULSE。频率为 1 kHz，占空比 1..20%，持续 50..5000 ms（5 ms步进），均为人工诊断软件界限，不是电机实测额定值。ESP32-S3 RMT 发送5个1 ms PWM symbol组成的块并进行有限次数硬件循环，结束电平为低；固定 SDK 已确认 S3 支持硬件自动停止循环。没有无限 PWM，也不依赖主循环准时发 STOP 来结束正常波形。异常尝试停止输出并锁定故障，不自动再次转动。

当前验线协议 v7：除仅可停止的 plain STOP 外，CHECK、ARM、PULSE 都须带完整 CRC32，格式为 `body *8hexcrc`。握手为 `AYNI MOTOR PROBE/7`（D0..D3=38,39,40,41），版本不匹配不降级。仅显式 `--check-routes-unpowered` 才发送 CHECK_UNPOWERED：在用户声明驱动断电时逐脚绑定/读回/释放，并检查准备与释放阶段硬件计数为0；不能与转动命令混用。正常脉冲只准备目标脚，不先配置其他三脚。每次 PULSE 前又检查只有目标脚路由到 RMT，其余三脚均为普通 GPIO 低电平。释放通道时必须显式切回 `SIG_GPIO_OUT_IDX`；固定 SDK 的 `gpio_reset_pin` 和 RMT 删除本身不会解除旧 matrix 路由，直接重新使能旧脚会在通道复用时串脚。本轮初版实际发现该问题后停止后续脉冲、用户断电、修正并完成无波形逐脚隔离检查；不能把修正前“同一个电机转动”的结果记为电机 2 通过。

历史v3另在脉冲期间观察四个MCU GPIO的上升沿（v6已替换该软件IRQ机制）。GPIO ISR 和计数在内部 IRAM/DRAM、32 位原子操作内联，ISR 与 main 固定同核；开始前禁用并清 pending，结束观察后保留计数。只有目标脚约为请求周期数（识别容差±1）、其余脚为0才返回正常 DONE；未选脚发生边沿时先停止/隔离输出，再打印诊断并锁定故障。计数用于引脚辨认，不是精密时序、驱动板线末端波形或电机转动测量。主机 `--channel/--direction` 当前只是选择四个输入槽位，不能当作已经辨认通过的电机编号或转向。

这里没有外部超时看门狗或完整启动失能电路，复位/掉电/异常停止上限未经验证；独立电源开关是人工台架的物理切断方式。不能将此测试记为 C-STOP/C-PERMIT 全通过，不能据此开放无人值守或模型控制。

构建：`bash motor_probe/build.sh`，产物在 `build/motor-probe/`。使用已验证的 IDF Python 执行 `device.py deploy --variant probe` 仅写原应用/分区表；不写 bootloader、NVS、audio 或 Ayni 日志。通用 `idf.py flash` 仍禁止。

`motor_probe.py` 不主动烧录或发送复位指令，但本机USB适配器实测每次重开串口会复位ESP32；预设DTR/RTS=false不能保证不复位。带电人工测试必须先在驱动断电时启动 `--interactive-bench --driver-power-off --arm-isolated-bench`，收到SESSION_OPEN后由在场用户开电、发送READY，再逐条发送 `PULSE 2 positive 20 5000` 等单次命令。程序持续持有同一串口；每轮匹配nonce、所有参数、四脚硬件计数及STOPPED，不自动重试。每轮用带nonce的只读PING/PONG获取实时uptime检查连续性，不使用可能积压的周期HELLO。故障、输入丢失或Ctrl-C进入停止及持有状态；仅用户确认驱动断电后的 `POWER_OFF_QUIT` 允许关闭。进程强杀、USB断开、宿主失败等不能由此保证，独立电源开关仍是人工台架切断方式。

单次 `--channel` 仅允许同时声明 `--driver-power-off` 做无动力波形；默认10%/5000 ms。无channel时只有握手和补充STOP，全脚检查另需 `--check-routes-unpowered`。负方向为 `--direction negative`，实际反向转动尚未验证。DONE只说明应用有限波形及输出低读回通过，不证明车轮/机械停止或独立停止链性能。

诊断后先由用户关闭驱动电源，再 `device.py deploy --variant motor` 回到含软件电机查询/计划的 Ayni 候选；`--variant stable` 回到已验证的屏幕/朗读构建。旧星图固件恢复资料和 `device.py restore` 保持原样。

## 当前辨认结果（2026-11-01）

GPIO42 的初次 10%/200 ms 脉冲，用户确认原车轮转动并自行停下。GPIO40 在修复 RMT matrix 残留后再次进行同条件单次测试：CHECK 及脉冲前后读回均通过，用户仍报告是原车轮转动。

加入 v3 后，用户关驱动电源，四脚各做一次10%/200 ms数字波形检查：GPIO42/41/40/39分别恰为200次上升沿，其余三脚均0。重新开电后分别测试GPIO41、GPIO39，两次均实测只有目标脚200次、其余0；用户均确认仍是原车轮转动并停下。用户随后已关电，确认四控制线与给定映射一致、两电机分别接两输出组，机械上互不联动。

因此电机2仍未辨认通过，当前不能确定具体接线、板上分路或电机连接原因，不能把MCU引脚检查当作驱动板端子的波形测量。已暂停继续脉冲，保持原GPIO映射，下一步需要核对实物接线。现场波形/用户辨认记录为本机被忽略的 `artifacts/motor-pin-identification.json`，不作为停止链全验收或公开CI证据。

用户随后要求改用 D0→38、D1→39、D2→40、D3→41，并确认在驱动断电时已改线。v4 与软件规划共用此新映射；改变握手版本以拒绝沿用旧映射的诊断固件。默认单次脉冲从200 ms延长到300 ms，占空比仍10%，固件允许范围不变；上述v3实测均属于旧映射，不能作为新接线已通过的证据。

v4新映射已完成诊断与Ayni电机查询/规划候选编译；诊断应用200,512字节已烧录并校验，四脚无PWM路由检查通过。用户开电并确认架空/独立开关就手后，GPIO38与GPIO40各做一次10%/300 ms脉冲，回执分别为38=300/其余0、40=300/其余0。用户先报告GPIO38带动“另一只车轮”并停下，随后报告GPIO40仍带动刚才GPIO38的同一只车轮。因此换脚未解决分路辨认；GPIO39/41在新接线下尚未做带电转动测试。已暂停脉冲，用户确认驱动电源关闭。

用户进一步明确要求观察5秒。v5维持1 kHz和10%默认占空比，每硬件循环包含5个PWM周期，5秒为1000次硬件循环，静态约束不超过S3单批1023次；不依赖ISR续装循环或主循环补发STOP结束正常波形。电脑端开始核对ACCEPTED的nonce/通道/方向/占空比/时长与完整EDGES，未匹配即仅停止，不重试。

### 针脚与控制方式复核

用户补充成功直连条件为：D0、D2接ESP32的3.3V，D1、D3接GND。该恒定HIGH与当前10% PWM不是等效启动试验。其提供的[同板教程](https://tutorials.aposteriori.com.sg/100-Arduino-in-Cpp/40-Components/12-hbridgeControl.html)使用一脚HIGH、另一脚反相PWM；当前是一脚LOW、另一脚正PWM。[制造商TA6586数据表](https://d148k72crfmm2d.cloudfront.net/wp-content/uploads/2021/12/1809091025_RZ-Wuxi-Smart-Microelectronics-TA6586_C128851.pdf)的真值表支持两者，分别交替驱动/制动及驱动/滑行，不能仅凭这种差异认定当前选错电机。

[Espressif GPIO资料](https://docs.espressif.com/projects/esp-idf/en/latest/esp32s3/api-reference/peripherals/gpio.html)列出S3 GPIO38..42可输入输出；[标准DevKitC-1 v1.1针脚表](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html#header-block)同时说明GPIO38接板载RGB灯。实际底板仅获知N16R8标记，所收实物照片为驱动板；尚未确认ESP底板型号及板级占用，不能冒认为标准板或将RGB占用判为同轮根因。

v5诊断应用200,640字节已编译、烧录并校验；6个电脑端协议检查及定向独立复查通过。驱动断电时，GPIO38/40分别做一次10%/5秒波形，均为目标5000个上升沿、其余三脚0，完整nonce/参数/边沿检查和DONE通过。主机ACCEPTED到EDGES回执间隔均5.001秒（含串口报告，不是示波器精密测时）。电机带电表现仍待用户开电后观察。

v5带电观察逐步澄清：GPIO38 10%/5秒时用户确认轮A只动一下、对应电机尾轴/码盘持续约5秒；GPIO40 10%/5秒两次观察为有声音但无持续转动。用户明确同意GPIO40 20%/5秒后，确认轮A先动一下，另一台电机尾轴持续约5秒并停下。这支持两次正式波形驱动不同电机，仍未确认车轮持续输出；轮A额外动作来源尚未定位。

v6以四个PCNT硬件计数器替代仅覆盖正式PWM的GPIO IRQ计数；计数器持续运行，每轮在目标脚配置前清零，覆盖准备、正式PWM及释放，结束后精确要求目标为duration_ms、其他三脚为0。任一准备边沿、额外目标/非目标边沿或读回错误先coast，再报告并锁定故障。无输入glitch filter；计数带宽受硬件约束，不能替代驱动端电压测量、机械观察或独立停止链验收。单位/通道仅在启动时创建，全部及部分启动持有的资源保留至复位，失败后不再分配或武装。取消每次带电全脚CHECK是减少不必要引脚操作；尚不能把CHECK假设写成已证实的额外车轮动作根因。用户已关驱动电源，先做无动力检查。

PCNT当前不累加或锁存溢出，32767计数上限之后可归零；所选1 kHz、最多5000周期的正常波形在范围内，不能把零读回扩展成任意频率异常毛刺均不存在的证明。

v6断电下全脚setup/release硬件计数均0，GPIO40 20%/5秒完整PCNT计数5000、其他0、STOPPED通过。连续两次重开串口、仅被动读三个HELLO，uptime均从1000/2000/3000重新开始，证实每次重开会复位。随后改用持续连接；首次尝试在ARM前被周期HELLO的uptime校验拦下，没有发送脉冲，尚不能仅据该次校验认定再次复位。v7改用nonce相关实时PING/PONG，保留持续连接、故障持有和关闭许可；16项主机检查与只读定向复查通过，应用204,704字节已构建、烧录并校验。

持续串口 v7 实际结果：D2/GPIO40 20%/5秒，PCNT40=5000、其他脚0，用户确认轮A没动、另一台电机尾轴持续约5秒并停；D0/GPIO38 10%/5秒只有声音/抖动；D0 20%/5秒PCNT38=5000、其他0，用户确认轮A尾轴持续约5秒、另一台没动，随后停止。原轮A额外抖动在持有同一串口后消失，支持每次开串口复位是重要干扰来源；10%不能可靠起转。不能据此声明轮胎持续输出或实测RPM。

v8把人工诊断上限扩为50%，保持1kHz、最多5秒、持续连接及单次ARM。已构建但未作为设备50%实测证据；用户随后转为要求真实模型能力、最大90%，采用上级工程的逐次Mac确认配置。
